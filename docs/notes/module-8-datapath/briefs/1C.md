# Brief 1C: lesson `instructions` (Module 8, lesson 1), the end

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**instruction** and **datapath** in its earlier sections, so here they are used plainly, not in
bold.

Keys to write: `writeJobsLead`, `c2Task`, `c2Hints.1` to `c2Hints.5`, `reflection`,
`modelVsReality`.

## writeJobsLead (one sentence)

Write the register jobs' datapath as text, from the course's own register file and ALU.

## c2Task (the task; about 200 words, lists allowed)

1. The course supplies two modules that your text may use:
   - `registers`: inputs RA, RB and WA (4 bits each), D (64 bits), WE and CLK; outputs QA and QB
     (64 bits each). It is the register file of the drawing.
   - `alu`: inputs A and B (64 bits each), OP2, OP1 and OP0; outputs Y, ZERO, MINUS, COUT and
     OVER. It is Module 7's ALU at 64 bits.
2. This challenge brings one new construct: one module used inside another. You write the
   module's name, a name for this use of it, and its ports connected by name, as in
   `registers regs (.RA(IR[23:20]), .WE(WRITEY), ...);`. Each `.PORT(signal)` joins the module's
   port to one of your signals. An output you do not need can be left out.
3. Your module, `jobs`, has inputs CLK, IR (32 bits) and WRITEY, and one output, RESULT (64
   bits): the ALU's Y.
4. The starting text gives the module's first lines, declares QA and QB, uses the register file
   once (the use is called `regs`), and ends with `assign RESULT = QA;`.
5. Replace that assignment: use the ALU, with its A and B from QA and QB, its code from IR's bits
   26, 25 and 24, and its Y on RESULT.
6. You may use what the digits challenge used, plus one module used inside another.
7. The tests are 10 steps. R1 starts at -184, R2 at -250, and every other register at X. The steps
   set IR, WRITEY and CLK and check RESULT. One step changes IR while the clock is high, and the
   next checks that no register was written then. One step makes an edge with WRITEY at 0.

## c2Hints (five rungs)

1. RESULT is the ALU's Y. Use the ALU once and connect each of its inputs.
2. A common mistake: giving the ALU's code J's top three bits, `IR[27:25]`. The code is J's bits
   2 to 0: `IR[26]`, `IR[25]` and `IR[24]`.
3. `alu alu1 (.A(QA), ...);` uses the ALU and names this use alu1.
4. Connect `.A(QA)`, `.B(QB)` and `.Y(RESULT)`, then the three code bits.
5. The whole answer: replace `assign RESULT = QA;` with

```
alu alu1 (.A(QA), .B(QB), .OP2(IR[26]), .OP1(IR[25]), .OP0(IR[24]), .Y(RESULT));
```

## reflection (about 100 words)

1. The register file and the ALU, joined, make a datapath. An instruction's digits are wires to
   its parts. One edge does one instruction, and writes its result when WRITEY is 1.
2. Every instruction so far works on registers alone, and R1 and R2 started with words the lesson
   gave them.
3. The shop needs numbers that no register holds yet: the limits it checks the rooms against, the
   number of seconds in a minute.
4. End on the question: how can an instruction carry a number of its own to the ALU?

## modelVsReality (about 110 words)

1. The simulator shows a register no edge has written as X. The lesson set R1 and R2 for you. A
   real register file at power-on holds 0s and 1s nobody chose.
2. In this model the register file and the ALU settle in steps, and an edge takes no time. In a
   real datapath, the next edge must wait for the slowest path: the register file's read, the
   ALU's carry through 64 bits, and back to D, with the setup time (Module 4) before the edge.
3. You set WRITEY by hand here. In the course's machine, a block works it out from K and J; a later
   module builds that block's insides.
