# Brief 5C: lesson `branches` (Module 8, lesson 5), the end

Read `00-module.md` (the shared fact sheet) first; it applies here, with two changes: PC,
"program counter", "fetch" and "branch" are allowed, plainly (earlier sections introduced them).
The datapath is whole: PC, the ROM, the closed decoder, the stop logic, loads and stores, and now
the condition block (MET) and the block "next PC" (NEXT: PC + 4, the target PC + 4c, or RESULT).

Keys to write: `generalisation`, `callLead`, `callAfter`, `writeNextLead`, `c2Task`, `c2Hints.1`
to `c2Hints.5`, `reflection`, `modelVsReality`.

## generalisation (about 100 words)

1. Two more kinds use the next-PC block.
2. A call (kind 6) keeps the address of the next instruction in the register Y names, RY ← PC + 4,
   and goes to PC + 4c.
3. A jump (kind 7) goes to RA + c, the ALU's RESULT. `goto R15` returns from a call whose Y was
   R15.
4. A block "word for Y" (named yWord) gives the register file's D: RESULT, MQ for a load, or
   PC + 4 for a call.
5. A jump can reach any address. A target outside the ROM, or not a multiple of 4, stops the
   machine at its fetch, with cause 11 or 12.

## c2Task (about 170 words, a list allowed)

1. The text is the course's whole datapath, the module `datapath`: every part of this module's
   lessons, written with the course's modules.
2. The starting text has `assign NEXT = PC4;`, so every instruction goes on to the next. Replace
   it so that:
   - NEXT is TARGET when BRANCH and MET are both 1, or when CALL is 1;
   - NEXT is RESULT when JUMP is 1;
   - NEXT is PC4 otherwise.
3. TARGET is already worked out: `assign TARGET = PC + {WIDE[61:0], 2'b00};`, the constant times 4
   added to PC.
4. The ROM holds the call program above. The tests reset the machine and check PC after each of
   its 15 edges before the stop, then HALT and the display, 6, at the stop: 17 tests.
5. You may use every construct the earlier challenges used.

## c2Hints (five rungs)

1. Start NEXT at PC4, and let the other cases replace it in an `always_comb` block.
2. A common mistake: taking the target for every branch. A branch goes to the target only when MET
   is 1.
3. `if (JUMP) NEXT = RESULT;` is the jump's case.
4. The branch and the call share the target: `if ((BRANCH & MET) | CALL) NEXT = TARGET;`
5. The whole answer, in place of the assignment:

```
always_comb begin
  NEXT = PC4;
  if ((BRANCH & MET) | CALL) NEXT = TARGET;
  if (JUMP) NEXT = RESULT;
end
```

## reflection (about 110 words)

1. The datapath is whole. It runs every instruction of kinds 1 to 7 and `stop`, one per edge: PC
   names it, the ROM gives it, the register file and the ALU work on it, the memory reads or
   writes, and the next-PC block chooses where to go next.
2. You wrote most of it as text: the digits, the widening, the selectors, PC, the checks, the
   condition and the next PC.
3. One block stayed closed in every lesson: the decoder.
4. End on the question: how does the decoder work out every control signal from K and J alone?

## modelVsReality (about 120 words)

1. Here every instruction takes one edge, so the clock must wait for the slowest one. A load's path
   is the longest: PC, the ROM, the decoder, the register file, the ALU's add, the memory's read,
   and back to the register file. Module 9 splits instructions over several edges.
2. In the settle model every gate takes one step. Real gates and wires take different times, so a
   real circuit's passing values differ from the model's. They exist in real circuits too.
3. Registers take their words only at an edge. A passing value that settles before the next edge,
   with the setup time to spare (Module 4), does no harm.
