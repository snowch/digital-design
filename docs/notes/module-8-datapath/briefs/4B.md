# Brief 4B: lesson `memory-access` (Module 8, lesson 4), the middle

Read `00-module.md` (the shared fact sheet) first; it applies here, with one change: PC,
"program counter" and "fetch" are allowed now. Use them, **instruction** and **datapath**
plainly. This lesson introduces no term. The "stop logic" stops the machine when any cause is not
00 (lesson 3: 11 and 12 from a fetch, 21 for an instruction the decoder does not know).

Keys to write: `construction`, `writeMemcheckLead`, `c1Task`, `c1Hints.1` to `c1Hints.5`,
`memoryFaultsLead`, `memoryFaultsAfter`, `explanation`, `generalisation`.

## construction (about 120 words, a list allowed)

1. The memory refuses some loads and stores. It says why on its output CAUSEM, and the stop logic
   stops the machine, as for a fetch:
   - 31: no memory at the address: `7F8` or above.
   - 33: a word not at a multiple of 8, or a byte at a device (`7C0` or above).
   - 34: a store to the ROM (below `400`), or to a device that is read only: the signals word at
     `7D0` and the sensors at `7D8` and `7E0`.
2. When two apply, 31 wins over 33, and 33 over 34.
3. A load or store the memory accepts gives 00. So does an instruction that neither loads nor
   stores.
4. The challenge below writes these checks.

## writeMemcheckLead (one sentence)

Write the checks the memory makes on every load and store.

## c1Task (about 160 words, a list allowed)

1. Write a module called `memcheck`. Inputs: ADDR (64 bits), LOAD, STORE and BYTE. Output: CAUSEM
   (8 bits). BYTE is 1 for a byte, 0 for a word.
2. The starting text sets CAUSEM to `00`, then to `31` when ADDR is outside the memory (any of
   bits 63 to 11 is 1, or bits 10 to 3 are all 1: `7F8` to `7FF`), then back to `00` when neither
   LOAD nor STORE is 1. Add the checks for 33 and 34, using the rules above.
3. The addresses in bits: a device is at `7C0` or above, so bits 10 to 6 are all 1. The ROM is
   below `400`, so bit 10 is 0. The read-only devices `7D0`, `7D8` and `7E0` have bits 10 to 3
   equal to `FA`, `FB` and `FC`.
4. In an `always_comb` block a later assignment replaces an earlier one, so put the checks in
   order: 34 first, then 33, then 31.
5. You may use `module`, ports, `logic`, multi-bit signals, `assign`, selects, the bitwise
   operators, `always_comb`, `if`, `==` and `!=`.
6. There are 14 tests, each named by the access and the address, such as "store byte at 3F9".

## c1Hints (five rungs)

1. Each rule is one `if`, and the order of the `if`s decides which cause wins.
2. A common mistake: forgetting that only a store can give 34. A load from the ROM or a sensor is
   allowed.
3. The store to the ROM: `if (STORE & (ADDR[10] == 1'b0)) CAUSEM = 8'h34;`
4. The 33 checks: `if (BYTE & (ADDR[10:6] == 5'b11111)) CAUSEM = 8'h33;` and
   `if (~BYTE & (ADDR[2:0] != 3'b000)) CAUSEM = 8'h33;`
5. The whole answer:

```
always_comb begin
  CAUSEM = 8'h00;
  if (STORE & (ADDR[10] == 1'b0)) CAUSEM = 8'h34;
  if (STORE & ((ADDR[10:3] == 8'hFA) | (ADDR[10:3] == 8'hFB) | (ADDR[10:3] == 8'hFC)))
    CAUSEM = 8'h34;
  if (BYTE & (ADDR[10:6] == 5'b11111)) CAUSEM = 8'h33;
  if (~BYTE & (ADDR[2:0] != 3'b000)) CAUSEM = 8'h33;
  if ((ADDR[63:11] != 53'h0) | (ADDR[10:3] == 8'hFF)) CAUSEM = 8'h31;
  if (~(LOAD | STORE)) CAUSEM = 8'h00;
end
```

## memoryFaultsLead (above the figure; about 90 words)

1. The same program, with two faults to choose.
2. "LOAD held at 0": the decoder's output LOAD is 0, so pickLoad always gives RESULT.
3. "STORE held at 1": the decoder's output STORE is 1 for every instruction.
4. Choose a fault and press "Run until it stops". Say first what the display will show.

## memoryFaultsAfter (below the figure; about 110 words, a list allowed)

1. "LOAD held at 0": the loads write their addresses instead of the words there. R2 holds 2008,
   which is `7D8`, and R3 holds 2016, which is `7E0`. R4 is 2008 - 2016 = -8, and the display
   shows -8. Nothing stops the machine: every address is one it accepts.
2. "STORE held at 1": the machine stops at the first edge, at `000`, with cause 34. The load from
   room A's sensor has become a store to it as well, and the sensor is read only. No register is
   written.
3. A check can catch a fault: the second stopped at once, while the first ran to the end with a
   wrong answer.

## explanation (about 130 words)

1. A load or a store uses the ALU's add for its address: A + c, or 0 + c for an absolute address.
   The decoder sets the ALU's code to add for every load and store.
2. A load's word arrives on MQ before the edge, and the edge writes it into the register Y names.
   A store's word, QB, is written at the edge into the memory.
3. The memory reads twice at once: the instruction at PC, and the word at ADDR. They are two
   reads of one memory, as the register file has two reads.
4. The decoder's new outputs, AZERO, LOAD, STORE and BYTE, are control signals like WRITEY and
   BCONST.
5. The memory checks every load and store before the edge. A store it refuses writes nothing:
   the memory's writes, like PC and the register file, wait for GO.

## generalisation (about 100 words)

1. A byte load fills the register's low 8 bits with the byte and the rest with 0s. A byte store
   writes the register's low 8 bits.
2. Words are 8 bytes, low byte first, at multiples of 8 (Module 6).
3. The RAM holds 960 bytes, from `400` to `7BF`. The devices are 7 words, from `7C0` to `7F7`.
4. Every device is reached with the same load and store as the RAM. The machine needs no
   instruction of its own for the display or the sensors.
