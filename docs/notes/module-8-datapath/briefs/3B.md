# Brief 3B: lesson `fetch` (Module 8, lesson 3), the middle

Read `00-module.md` (the shared fact sheet) first; it applies here, with one change: PC,
"program counter" and "fetch" are allowed (this lesson introduces them, and brief 3A and the
explanation below set them in bold where they are introduced). Use **instruction** and
**datapath** plainly.

Keys to write: `construction`, `writePcLead`, `c1Task`, `c1Hints.1` to `c1Hints.5`,
`fetchFaultsLead`, `fetchFaultsAfter`, `explanation`, `generalisation`.

## construction (about 60 words)

1. PC is a register with a reset and an enable, as in Module 5. Its enable is GO, from the stop
   logic: GO is 1 unless the machine is stopping.
2. As text, it is an `always_ff` block: `if (RST)` gives PC 0; `else if (GO)` gives PC `PC + 4`.
3. The challenge below writes it, with the + 4 inside.

## writePcLead (one sentence)

Write the program counter: reset to 0, then 4 more at every edge while GO is 1.

## c1Task (about 120 words, a list allowed)

1. Write a module called `counter`. Inputs: CLK, RST and GO. Output: PC, 64 bits.
2. At a rising edge of CLK: if RST is 1, PC takes 0; otherwise, if GO is 1, PC takes PC + 4;
   otherwise PC keeps its value.
3. The starting text adds 4 at every edge, with no reset and no GO. Change it.
4. You may use `module`, ports, `logic`, multi-bit signals, `always_ff`, `if` and `+`.
5. The tests are 11 steps, and 10 of them check PC. One step changes GO while the clock is high.
   One makes an edge with RST at 1 and GO at 0.

## c1Hints (five rungs)

1. PC is a register: write it in `always_ff @(posedge CLK)`, with RST first.
2. A common mistake: testing GO before RST. A reset must give 0 even while GO is 0.
3. Module 5's counter with a reset: `if (RST) Q <= 4'b0000; else if (EN) Q <= Q + 4'b0001;`
4. `if (RST) PC <= 64'h0;` then `else if (GO) ...`.
5. The whole answer:

```
always_ff @(posedge CLK)
  if (RST) PC <= 64'h0;
  else if (GO) PC <= PC + 64'h4;
```

## fetchFaultsLead (above the figure; about 100 words)

1. The margin program again, with two faults to choose.
2. "PC4 held at 0": the "+ 4" block's output, the bus PC4, is 0.
3. "STOP held at 0": the decoder's output STOP is 0, whatever the instruction.
4. Choose a fault, then press "Clock edge" a few times, or "Run until it stops". Say first what PC
   will do.

## fetchFaultsAfter (below the figure; about 110 words, a list allowed)

1. "PC4 held at 0": every edge gives PC 0. The machine runs the instruction at `000`, R1 ← -250,
   at every edge and never reaches `stop`. "Run until it stops" gives up after 500 edges. R2 stays
   X.
2. "STOP held at 0": `stop` at `010` does not stop the machine. PC goes on to `014`, where the ROM
   holds `00000000`. The decoder gives cause 21 there, and the machine stops after 6 edges, with
   PC at `014`.
3. The check for an instruction the decoder does not know stopped a program whose own `stop` was
   broken.

## explanation (about 140 words)

1. Reading the instruction at the address PC holds is called **fetch**. Introduce the term here,
   plain meaning first.
2. In this machine, every edge fetches and does one instruction. Between two edges, PC settles to
   its new value, the ROM gives the instruction at it on IR, and the datapath works out the
   result. The next edge writes the result and gives PC its next value.
3. IR is a bus: the ROM's output at PC. It is not a register, and it changes as soon as PC does.
4. The decoder works out the control signals from K and J alone: for a register job, BCONST 0; for
   a constant job, BCONST 1; WRITEY 1 for both. For `stop`, WRITEY is 0 and STOP is 1.
5. The stop logic gives GO, which is 1 unless HALT is 1. GO is PC's enable. The register file's
   write enable is now WREG: WRITEY AND GO. So an edge that stops the machine changes nothing.

## generalisation (about 110 words)

1. The ROM holds 256 instructions, at `000` to `3FC`.
2. The ROM itself checks each fetch, and gives its cause on the bus CAUSEF:
   - 11 when PC is outside the ROM, at `400` or above;
   - 12 when PC is not a multiple of 4;
   - 00 otherwise. When both are true, 11 wins.
3. With the decoder's 21 for an instruction it does not know, the stop logic stops the machine on
   any of them, and CAUSE says which.
4. In this lesson PC only counts up by 4, so neither check can fire yet. A later lesson gives PC
   other values.
