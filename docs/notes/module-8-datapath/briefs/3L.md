# Brief 3L: lesson `fetch` (Module 8, lesson 3), the labels

Read `00-module.md` (the shared fact sheet) first; it applies here, except that a label is short
and need not be a sentence. PC, "program counter" and "fetch" are allowed.

Keys to write, each one line:

- `title`: a question a learner would ask, ending in "?", at most 9 words: how the machine knows
  which instruction comes next.
- `objectives.1` to `objectives.4`, each starting with a verb, at most 12 words: follow PC, the
  ROM and IR through a program's edges; predict when and why the machine stops; write the
  program counter with reset and GO; write the ROM's fetch checks as a module.
- Ten section headings, `titles.question`, `titles.motivation`, `titles.prediction`,
  `titles.investigation`, `titles.construction`, `titles.failureExperiment`,
  `titles.explanation`, `titles.generalisation`, `titles.challenge`, `titles.reflection`: each
  2 to 6 words, starting with a capital letter, like "When 16 bits run out" or "The carry, step by
  step". They hold: the machine on its own; the program counter; a program with no stop; a
  program run edge by edge; the program counter written as text; a broken PC4 and a broken STOP;
  fetch and the control signals; the checks on every fetch; the checks written as text; what the
  machine can do now and the next question.
- `challengeTitles.c1`: "Program counter, written" style. `challengeTitles.c2`: the fetch
  checks, same style.
- `captions.predictEnd`: predict what the next edge does, then check.
  `captions.margin`: run the program edge by edge.
  `captions.writePc`: write the program counter and run the tests.
  `captions.fetchFaults`: choose a fault and run the program.
  `captions.writeChecks`: write the checks and run the tests.
- `options.p1On`: the machine goes on to `00C`. `options.p1Stops`: the machine stops, cause 21.
  `options.p1Stop`: the machine stops, as at `stop`, cause 00. Each at most 8 words.
- `faults.pc4Low`: "PC4 held at 0". `faults.stopLow`: "STOP held at 0".
