## explanation
The compiler follows 5 rules. Four follow advice the assembler gave in lesson 11.1 when it refused a line.

1. A device's name the line reads. 11.1 has no refusal for this one. The rule writes the device's word into the next register: `R1 <= word[sensorA]`.
2. A number. 11.1 said: "Put the number in a register first." The rule does that: `R4 <= 100`.
3. Two registers joined by a job. 11.1 said: "One line does one job." The rule writes the result into the next register: `R3 <= R1 - R2`.
4. `if`, once both sides are registers. 11.1 said: "After < or >=, write signed or unsigned." The rule writes a branch past the rest of the line, on the comparison turned over, which is its opposite. For `<`, that is `if R3 >= R4 signed goto after1`.
5. A device's name the line writes. 11.1 said: "A store writes a register's word." The rule writes the store: `word[lamps] <= R5`.

Each line starts again at R1, so nothing stays in a register from one line to the next. The program ends with `stop`. Where the comparison turned over is `>` or `<=`, the machine has no branch for it, so the compiler swaps the two registers, as lesson 10.3 did.

The figure shows where each instruction came from: the gap line's are Module 0's lines 1 to 4, and the CLASH line's are Module 0's lines 1 to 3 and 5 to 9. Your first program in the course was these two outputs, with the gap worked out once instead of twice.

## generalisation
The figure below puts the compiler's program for both lines beside Module 0's. Compare three things: how many instructions each program has, how many of them run with the shop's readings, and what each leaves on the display.

Module 0's program keeps the gap in R3 for its second rule. The compiler works the gap out again, because each line starts afresh.

A better compiler does more, and this page does not teach it. It keeps a value in a register for a later line. It leaves a number in an instruction's constant where it fits, as 10.3's immediate does. It keeps a comparison as a word, using set if (10.5). Real languages add loops, functions and names the program makes up for its own values. A function call follows the calling convention of 11.3.

## modelVsReality
This compiler reads one kind of line. It keeps nothing between lines, and it writes the same instructions every time it reads the same line. A real compiler reads a whole language, with loops, functions and names of its own. It chooses among many ways to write the same work. It keeps values in registers across lines. It checks the whole program before it writes anything. It still ends where this one does: in instructions an assembler turns into machine code.
