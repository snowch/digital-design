## question
The generalisation of lesson 11.1 says: "The assembler translates line for word. It adds no instruction of its own: every word in the listing comes from one line you wrote." The generalisation of lesson 13.2 says: "Every program reaches a machine as machine code. Whatever language it was written in, the machine runs words like `A7345000`."

Module 0's shop wanted the display to show how much warmer room A is than room B. Its program took four lines for that, lines 1 to 4. The shop would say it in one line: `display <= sensorA - sensorB`. Each of the four lines does one job, as the assembler requires.

Can a program take a line that says what to work out, and write the instructions that work it out?

## askedLead
The debugger below holds two lines: `display <= sensorA - sensorB` and `stop`. You can edit them. The assembler refuses line 1 and gives its reason: "Each line is one instruction. Write it as a transfer, such as R3 <= R1 + R2." Read the refusal, then try writing line 1 the way the assembler asks.

## motivation
Such a program is a **compiler**. A compiler is a program that reads lines that say what to work out, and writes the instructions that work it out.

Set against the assembler, the compiler does four things the assembler does not:

- it writes several instructions for one line, where the assembler writes one word;
- it chooses the registers;
- it makes up a name for a line;
- it turns a comparison over.

The compiler's lines are the course's own text with the assembler's refusals lifted. There are two forms. In the first, `D <= E`, D is `display` or `lamps`. In the second, `if E C E then D <= E`, C is one of `<`, `<=`, `>`, `>=`, `==` or `!=`.

An E is a device's name, a number, two Es joined by `+`, `-`, `&`, `|` or `^`, or an E in brackets. Jobs are done left to right, brackets first.

One trap sits in these lines. In the compiler's lines, a device's name stands for its word, the reading. In assembly, the name alone is its address: `R1 <= sensorA` assembles, and puts `7D8` in R1, the address of room A's sensor.

The compiler is a program in the page, as the assembler is. It refuses a name that is no device the line may read, a number that does not fit from -2048 to 2047, `*` and `/`, since the machine has no multiplication or division, and a line in neither form.

Which branch does the compiler write next?

## p1Explain
The compiler writes `if R3 < R4 signed goto after1`. The branch jumps past `lamps <= 4` when the comparison fails, so it tests the comparison turned over: `>=` turned over is `<`. The readings can be of either sign, so the comparison is read signed. `after1` is a name the compiler makes up for the line after the rest.

Each wrong option fails in one clause. `>=` is the comparison not turned over, so it would skip the lamps when the gap is 100 or more. `R4 < R3` swaps the registers, which is `>`, wrong here. `unsigned` reads a negative gap as a huge number.
