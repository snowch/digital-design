## explanation (section prose, 160 to 210 words)

Facts, in this order:
1. The compiler's five rules, as a numbered list, each beside the refusal from 11.1 whose advice it
   follows (rule 1, a device's name read, has no refusal of its own: say what it writes). Give each
   rule's example instruction.
2. Each line starts again at R1. The program ends with `stop`. Where the comparison turned over is
   `>` or `<=`, the compiler swaps the two registers, as lesson 10.3 did.
3. What the figure showed: the gap line's instructions are Module 0's lines 1 to 4, and the CLASH
   line's are Module 0's lines 1 to 3 and 5 to 9. Your first program in the course was this
   compiler's two outputs, with the gap worked out once instead of twice.

## generalisation (section prose, 90 to 130 words)

Facts:
1. The figure below puts the compiler's program for both lines beside Module 0's. The compiler's
   has 12 instructions and runs 10 with the shop's readings; Module 0's has 9 and runs 7. Both show
   66 and leave CLASH dark. Do not state these numbers in this prose: the figure shows them after
   its run. Say instead what to compare.
2. Module 0's program keeps the gap in R3 for the second rule; the compiler works it out again,
   because each line starts afresh.
3. Named, not taught: a better compiler keeps a value in a register for a later line, leaves a
   number in an instruction's constant where it fits (10.3's immediate), and keeps a comparison as
   a word with set if (10.5). Real languages have loops, functions (a compiler writes a call by the
   calling convention of 11.3) and names a program makes up for its own values.

## modelVsReality (the note on how the page differs from real compilers, 60 to 90 words)

Facts: this compiler reads one kind of line, keeps nothing between lines and writes the same
instructions every time. A real compiler reads a whole language with loops, functions and names
of its own, chooses among many ways to write the same work, keeps values in registers across
lines, and checks the program as a whole before it writes anything. It still ends where this one
does: in instructions an assembler turns into machine code.
