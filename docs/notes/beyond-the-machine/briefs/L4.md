## 1. The challenge, "Two programs, set up"

**c2Task** (Markdown, 150 to 200 words). Facts:
- The box holds the kernel, given whole, and a start that sets up the first program the tests add,
  named `program`: its C2 word (its first line), its C1 word (2, user mode with interrupts on) and
  its R14 word (`7C0`, the top of its stack), with `500` at `480`, 0 at `488`, and the timer set.
- Set up the second program, named `second`, in the save area at `5A0`, so that the kernel runs
  both. Change only the start.
- The second program expects, when it starts, the address of its readings in R1 and how many there
  are in R2, as a function receives its arguments (11.3). The tests add the readings, named
  `secondLog`, and a word holding how many, named `secondCount`.
- The tests' programs call a function that pushes on the stack, so each program needs a stack of
  its own. The RAM is free from `640` to `7BF`.
- The save area's layout: R0 to R15 at `5A0` to `618`, one word each (R14 at `610`), C1 at `620`,
  C2 at `628`, the record at `630`.
- Three runs test your text. Each adds two programs after it, and checks the words shown, in order,
  both records (`590` and `630`), C1 at the end, and that the run ends at the kernel's `stop`.

**challengeLead** (one sentence above the challenge).

**c2Hints**: five, in order, each 1 to 3 sentences:
1. The concept: a program waiting to start is its save area; `load` reads it into every register,
   C1 and C2.
2. A common mistake: setting R1 and R2 in the start before `goto load`; `load` then writes over
   them from the save area.
3. A smaller example, no part of the answer: a word stored at `518`, 24 bytes into the first save
   area, is the first program's R3 when it starts.
4. Part of the answer, as a code block:
   ```
           R1 <= second
           word[0x628] <= R1       // the second program's return point
           R1 <= 2
           word[0x620] <= R1       // its status
           R1 <= 0x700
           word[0x610] <= R1       // its R14
   ```
5. The whole answer: those lines, then
   ```
           R1 <= secondLog
           word[0x5A8] <= R1       // its R1: the address of its readings
           R1 <= word[secondCount]
           word[0x5B0] <= R1       // its R2: how many readings
   ```
   and `R1 <= 0x5A0` in place of `R1 <= 0` before `word[0x488] <= R1`.

**details**: kernelSetUp, one sentence shown under a failed run's values: what the start must
write for the second program (its C2, C1 and R14 words, and its R1 and R2 words), and that `488`
must name its save area. Never give an address of the answer other than those in the task.

**ends**: kernelSetUp, one sentence: a run must end at the kernel's `stop`, after both programs
have ended, with a record for each.

**runs**: three short labels: run 1, the gap program for three rounds, then the report on its own
readings; run 2, two programs that call one function; run 3, as run 1, with the second program
storing to the display itself.

## 2. The lesson's labels

- **objectives**: three or four, each starting with a verb (say what a program is to the machine
  between two instructions; follow a system call and a timer's interrupt through the kernel; work
  out what a switch saves and where; set up a program for the kernel).
- **titles**: a heading for each of the ten sections (question, motivation, prediction,
  investigation, construction, failureExperiment, explanation, generalisation, challenge,
  reflection), each a few words naming what it contains. The question's must not use "kernel".
  The challenge's is "Two programs, set up".
- **challengeTitles**: c1 "The save areas, worked out"; c2 "Two programs, set up".
- **captions**: one sentence each: runner (12.8's runner with the gap program and the report;
  no "kernel"); predict (the kernel with both programs, asking about R5); switch (the kernel's
  switch, with the save areas drawn); save (the construction's challenge); short (the kernel with a
  count of 40); lanes (the kernel's run as lanes, over its first switches); challenge.
- **lanes**: start ("The start"), handler ("The handler", for 12.8's runner), kernel ("The kernel's
  handler"), gap ("The gap program"), report ("The report").
- **memory**: titles over memory regions: records ("The records"); areas ("Running, waiting");
  gap ("The gap program's save area"); report ("The report's save area"); first ("The first
  program's save area"); second ("The second program's save area").
- **options**: roomA ("-184, room A's reading"); reportZero ("0, as the report left it"); roomB
  ("-250, room B's reading"); unknown ("X: not known"); both ("66: both programs get on");
  never ("0: the gap is never shown").
- **fields**: the construction's three answers: c2 ("The report's C2 word"), r13 ("The address of
  the report's R13 word"), c1 ("The report's C1 word, as two bits").
