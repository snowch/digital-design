## motivation

The current text:

> Such a program is a **compiler**. A compiler is a program that reads lines that say what to work out, and writes the instructions that work it out.
>
> Set against the assembler, the compiler does four things the assembler does not:
>
> - it writes several instructions for one line, where the assembler writes one word;
> - it chooses the registers;
> - it makes up a name for a line;
> - it turns a comparison over.
>
> The compiler's lines are the course's own text with the assembler's refusals lifted. There are two forms. In the first, `D <= E`, D is `display` or `lamps`. In the second, `if E C E then D <= E`, C is one of `<`, `<=`, `>`, `>=`, `==` or `!=`.
>
> An E is a device's name, a number, two Es joined by `+`, `-`, `&`, `|` or `^`, or an E in brackets. Jobs are done left to right, brackets first.
>
> One trap sits in these lines. In the compiler's lines, a device's name stands for its word, the reading. In assembly, the name alone is its address: `R1 <= sensorA` assembles, and puts `7D8` in R1, the address of room A's sensor.
>
> The compiler is a program in the page, as the assembler is. It refuses a name that is no device the line may read, a number that does not fit from -2048 to 2047, `*` and `/`, since the machine has no multiplication or division, and a line in neither form.

## explanation

The current text:

> The compiler follows 5 rules. Four follow advice the assembler gave in lesson 11.1 when it refused a line.
>
> 1. A device's name the line reads. 11.1 has no refusal for this one. The rule writes the device's word into the next register: `R1 <= word[sensorA]`.
> 2. A number. 11.1 said: "Put the number in a register first." The rule does that: `R4 <= 100`.
> 3. Two registers joined by a job. 11.1 said: "One line does one job." The rule writes the result into the next register: `R3 <= R1 - R2`.
> 4. `if`, once both sides are registers. 11.1 said: "After < or >=, write signed or unsigned." The rule writes a branch past the rest of the line, on the comparison turned over, which is its opposite. For `<`, that is `if R3 >= R4 signed goto after1`.
> 5. A device's name the line writes. 11.1 said: "A store writes a register's word." The rule writes the store: `word[lamps] <= R5`.
>
> Each line starts again at R1, so nothing stays in a register from one line to the next. The program ends with `stop`. Where the comparison turned over is `>` or `<=`, the machine has no branch for it, so the compiler swaps the two registers, as lesson 10.3 did.
>
> The gap line's instructions are Module 0's lines 1 to 4, and the CLASH line's are Module 0's lines 1 to 3 and 5 to 9. Your first program in the course was these two outputs, with the gap worked out once instead of twice.

## rules

Five sentences for the figure, one per rule, each at most 25 words, plain text (no Markdown), each
using the slot `{piece}` (the marked piece, as written in the line) and the slot
`{instruction}` (the instruction the compiler writes for it), each slot once:
- read: `{piece}` is a device's name the line reads, so the next register takes its word.
- number: `{piece}` is a number, so the next register takes it.
- job: `{piece}` is two registers joined by a job, so the next register takes the result.
- branch: `{piece}` has both sides in registers, so the compiler writes a branch past the rest of
  the line, on the comparison turned over, read signed, the registers swapped for `>` and `<=`.
- store: `{piece}` writes a device from a register, so the compiler writes a store.

## deviceName

One sentence, in the form of the assembler's refusals ("Each line is one instruction. Write it as
a transfer, such as R3 <= R1 + R2."), for a line such as `R3 <= sensorA - sensorB`: `{name}` is
a device's name, and in assembly a device's name alone stands for its address, not its reading;
to read the device, load its word on a line of its own, as `R1 <= word[{name}]` does. Plain
text, the slot `{name}` as written, at most 35 words.
