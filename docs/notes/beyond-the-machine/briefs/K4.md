# Brief K4: the compiler chapter, the challenge, the labels and the figure's words

Read `docs/style.md`, then `docs/notes/beyond-the-machine/briefs/compiler-facts.md` (the fact
sheet: the voice, the banned words, the working words and every fact). Use only those facts. Do
not write or change any file. Return each item under its key, with no commentary. Markdown only
where an item says so.

## 1. The challenge, "Being the compiler"

**c1Task** (Markdown, 110 to 150 words). Facts:
- Write the instructions the compiler's five rules give for one line no figure compiles:
  `if sensorB - sensorA > 100 then lamps <= 4`.
- The shop wants CLASH when room B is more than 10.0 degrees warmer than room A. This mends what
  Module 0's failure experiment showed: room B's failing freezer left CLASH dark, because the
  program checked one way only.
- The box starts with the line as a comment and `stop`.
- Six runs test your program, each with room A and room B: -184 and -50; -250 and -150; -250 and
  -149; -184 and -250; -30 and 80; 20 and 25. Each checks the lamps (CLASH lit in the first, third
  and fifth), that the display is still 0, and that the run ends at your `stop`.
- The runs judge what the line means, so any instructions that do what it says pass. Write the
  rules' instructions anyway: a run that fails names the rule it points to.

**challengeLead** (one sentence above the challenge): what you write here.

**c1Hints**: five hints, in this order, each 1 to 3 sentences:
1. The concept: the branch jumps past the rest of the line when the comparison fails.
2. A common mistake: copying the figure's `<` lights CLASH when room B is exactly 10.0 degrees
   warmer, a gap of exactly 100.
3. A smaller example, no part of the answer: `if R6 == R9` turned over is `R6 != R9`, so the
   compiler would write `if R6 != R9 goto after1`.
4. Part of the answer, the first four instructions: `R1 <= word[sensorB]`, `R2 <= word[sensorA]`,
   `R3 <= R1 - R2`, `R4 <= 100`.
5. The whole answer, as a code block:
   ```
   R1 <= word[sensorB]
   R2 <= word[sensorA]
   R3 <= R1 - R2
   R4 <= 100
   if R4 >= R3 signed goto after1
   R5 <= 4
   word[lamps] <= R5
   after1: stop
   ```
   and one sentence: `R3 > R4` turned over is `R3 <= R4`, which the machine writes as `R4 >= R3`.

**details**: one sentence for each run, shown when that run fails. Each names the rule the run
points to and never gives an instruction of the answer. Plain text, no Markdown.
- compilerWarmer (room B at -50, room A at -184, a gap of 134, CLASH must light): the gap is room B
  minus room A, in that order, and each room's reading comes from `word[...]`, not the name alone.
- compilerExactly (gap exactly 100, CLASH must stay dark): the line says more than 100, so its
  comparison turned over must let a gap of exactly 100 through to the branch.
- compilerJustOver (gap 101, CLASH must light): the branch must go past the lamps only when the
  comparison fails.
- compilerSigned (room A warmer, a gap of -66, CLASH must stay dark): readings and gaps can be
  negative, so the comparison is read signed.
- compilerBothSigns (room A at -30, room B at 80, gap 110, CLASH must light): the gap is room B
  minus room A, read signed.
- compilerClose (rooms 0.5 degrees apart, CLASH must stay dark): the branch must skip the lamps
  when the comparison fails.

**ends**: none needed.

**runs**: six short labels for the runs, each naming the two readings, for example
"Room A -184, room B -50".

## 2. The lesson's labels

- **objectives**: three or four, each starting with a verb: what the reader can do after the
  lesson (apply the compiler's rules to a line by hand; say why a comparison is turned over and read
  signed; follow a compiled line down to the condition block; say what a better compiler would
  keep).
- **titles**: a heading for each of the ten sections (question, motivation, prediction,
  investigation, construction, failureExperiment, explanation, generalisation, challenge,
  reflection), each a few words naming what it contains. The challenge's is "Being the compiler".
  The question's must not use "compiler".
- **captions**: one sentence each for the figures: asked (the debugger holding the shop's line,
  refused); predict (the compiler stopped before it writes the CLASH line's branch); steps (the
  compiler at work on a choice of two lines); branch (the compiled CLASH line on the whole machine,
  paused before the branch's FETCH edge); fault (the compiler with every piece in R1); compare (the
  compiler's program for both rules beside Module 0's); challenge (the challenge). The asked caption
  must not use "compiler".
- **lines**: two choice labels, gap ("The gap rule") and clash ("The CLASH rule"), with the line
  after each in code.
- **readings**: three choice labels: shop (room A -184, room B -250); warmA (room A -100, room B
  -250); bothSigns (room A -30, room B 80).
- **programs**: two column titles: compiled (the compiler's program for both rules); module0
  (Module 0's program).

## 3. The figure's words (the compiler at work)

Plain text, no Markdown. Slots in braces stay as written.
- linesLegend: the radio group of lines to compile.
- readingsLegend: the radio group of readings for the run.
- written: over the line as first written ("The line as you wrote it").
- lineNow: over the line as it stands, with its number: `{line}`.
- nothingLeft: in place of the line once nothing of it is left.
- ruleHeading: before the rule's sentence, 1 or 2 words and a colon.
- rules: one sentence for each of the five rules (read, number, job, branch, store), as the fact
  sheet states them, each at most 25 words.
- ruleHidden: in place of the rule while the figure waits for the reader's prediction: the rule
  shows once you have checked your prediction.
- next: "Next instruction". back: "Back". again: "Start again".
- progress: `{n}` instructions written of `{total}`.
- listingCaption: the table of instructions written.
- address, word, instruction: the table's three column headings.
- linkHint: press an instruction to mark the piece of the line it came from.
- rowLabel: what a screen reader says for an instruction's button: `{instruction}`, and that
  pressing it marks its piece.
- ended: after the last piece: nothing of the line is left, and the program ends with `stop`.
- run: the run's result: room A at `{a}` and room B at `{b}`; the display shows `{display}`; the
  lamps: `{lamps}`.
- lampsDark: the lamps' slot when none is lit. lampsLit: the slot when CLASH is lit.
- displayNothing: the display's slot when nothing was written to it.
- answer: the verdict after a prediction: the compiler writes `{answer}`.
- pieceLabel: what a screen reader says for the marked piece: `{piece}`.

## 4. The compiler's refusals

One sentence each, in the form of 11.1's refusals quoted in the fact sheet: what is wrong and what
to write instead. Slots stay as written.
- name: `{name}` is no device a line may read; the names are sensorA, sensorB, signals and lamps.
- range: `{number}` does not fit in an instruction's constant, -2048 to 2047.
- multiply: the machine has no multiplication or division.
- form: the line is in neither of the two forms.
- registers: the line has more pieces than the registers R1 to R13 can hold.
