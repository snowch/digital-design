Sceptic's verdicts on the 9.3 several-edges review. I checked each claim against the 9.3 text, lessons 8.1 to 9.2, `packages/dd-model/src/control.ts`, `multicycle.ts`, `content/lessons/module9.ts`, `several-edges.prose.ts`, `docs/isa.md` and `docs/style.md`. I wrote and changed no files.

**1. A table the learner has not seen. Stands, but the first suggested fix is not available.**
- The fault comes before the explanation, where the controller figure is. Rows in `controllerMachine()` count from FETCH→READ, so row 4 is ALU→MEMORY (MEM 1). With `decode: "full"`, no matching row gives code 000, which is FETCH.
- The `edge-faults` settings have no `states` and no `timing`, and the buses are only IR and ADDR. So the skipped MEMORY state cannot be seen.
- Moving the fault after the controller figure is not possible: the schema fixes the section order (failureExperiment comes before explanation).
- Fix: describe row 4 in words in the lead, and say in the outcome that no row driving a 1 leaves the code `000`. Add `"states":true` (and possibly timing) to this figure, as `colder-edges` already does.

**2. IR becomes a register unannounced. Partly.**
- Real: 8.3 says "IR is a bus … It is not a register". 9.3 introduces "the instruction register" and never says it is the IR the learner knows, now made a register.
- Falls: the "buses IR and HR" point. Module 8's "Buses" table already showed PC, a register's output ("The table 'Buses' shows PC, PC4, IR and RESULT", 8.3).
- Fix: one contrast sentence in the motivation, under rule 10. Leave the wording of the bus table alone.

**3. A branch's cause. Stands.**
- 8.5 says the condition block reads the flags and gives MET, and "NEXT is the target when the instruction is a branch and MET is 1."
- "The ALU's result decides the next PC for a branch" is wrong.
- Fix: name the flags (or MET) for the branch.

**4. PCEN once per instruction. Stands.**
- `module9.ts`: `assign PCEN = (next == FETCH) & GO;`. The stop halts in READ, where the next state is not FETCH and GO is 0. So the stop gets no pulse: 5 pulses for 6 instructions.
- Fix: except the stop, which the same paragraph already says halts in READ.

**5. "and no more". Stands.**
- The load's READ edge uses neither HA nor HB. The prediction text is right: `isa.md` says an absolute load gives the ALU's A input 0, not register A.
- A call reads no register either. The reason every kind passes through READ (the decoder's checks run only once IR holds the instruction) is given only in the explanation.
- Fix: either soften the claim, or give that reason in one clause in the generalisation.

**6. The same reason for 3 and 4 edges. Stands.**
- The quoted sentences are as the reviewer says. The real cause is where each kind ends: the branch ends at ALU, the store at MEMORY (`stateSequence`).
- Fix: give the ending state as the reason, or drop the reasons here and leave them to the kind-edges table (see 10).

**7. Incomplete list of what an edge does. Partly.**
- Real: the list leaves out the WRITE edge's register write.
- "Two registers, not one" is weaker: READ is one read step that fills HA and HB together. Still, rule 12 favours "two registers' words".
- Fix: make the list match the five states.

**8. Loose cross-reference. Stands.**
- 8.3's margin is R1 ← -184, R2 ← -250, R3 ← R1 - R2, R4 ← R3 + R3, stop. It has no store.

- The numbers hold: 4+4+4+4+2 = 18 edges, display 66.
- Fix: call it 8.3's margin program with that one change, or list its instructions.

**9. "next-PC adder". Stands (small).**
- 8.5 names the block "next PC" and calls it the "next-PC block". It is a chooser, not an adder.
- Fix: use 8.5's name.

**10. Repeats. Partly.**

**11. Overloaded sentence. Stands.** The "Beside the drawing: …" sentence holds three lists, against rules 1 and 8. Fix: use bullets.

**12. Prediction answerable from the motivation. Falls.**

- The motivation also does not say whether a load needs READ: its address is the constant alone, which the outcome points out. So the count is not simply read off the list.

**13. Minor points.**

The hint also states the consequence (IR tracks FETCHED and loses the instruction when the address switches), which is what rule 9 asks for.
- (b) "The control unit now has four parts". **Stands.** 9.1 says "the control unit is the decoder alone" and 9.2 says "The control unit is the decoder of Module 8's machine". Nothing says when the digits block and the stop logic joined it. Fix: say so in one clause, or drop the count.
- (c) "transitions to". **Stands under rule 5** (trivial). Use "goes to", as the controller "After" does.
