motivation: This instruction does two things at its last edge:
- RY ← PC + 4, like a call: register Y keeps the address of the next instruction;
- PC ← RA + c, like a jump: the PC takes the address from a register.

A call goes to PC + 4c, a place fixed when the program is written. This instruction goes to the address in RA, so the program can choose the place while it runs.

It takes kind 9, job 0. Kind 9 is the first kind the machine does not use.

For `R15 ← PC + 4, PC ← R4 + 0`, the word is `9040F000`: kind 9, job 0, A is R4, B is R0, Y is R15, constant 0.

p1Question: The PC is `004`, the call through R4. How many edges does it take, from its fetch to the edge where the PC moves on?

p1Explain: It takes 3 edges, as a call does:
- FETCH: IR ← memory[PC];
- READ: HA ← R4, HB ← R0;
- WRITE: R15 ← PC + 4 (which is `008`), and PC ← HA + c (which is `00C`).

The decoder sets CALL, so the controller moves from READ to WRITE.

It needs no ALU edge. The ALU is gates. From the READ edge on, HA holds R4 and the constant is in IR, so the ALU's result is ready by the WRITE edge.

A jump also takes the PC from the ALU at the first edge after READ. For a jump that edge is in ALU; here it is in WRITE.
