# Brief 5A: lesson `new-instruction` (Module 9, lesson 5), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. Every Module 9 term is
allowed: "control unit", "illegal instruction", "instruction register", "micro-operation". This
lesson introduces no term.

Keys to write: `question`, `motivation`, `callAndJumpLead`, `prediction`, `p1Question`,
`p1Explain`, `chooseLead`, `chooseAfter`.

## question (about 70 words)

1. Lesson 4 ended on a question. The course's machine leaves out a call through a register:
   RY ← PC + 4, and PC ← RA + c. What would the machine need to run it? Which parts would change?
2. In this lesson you add it to your own copy of the machine, end to end.
3. End on the question: how much of the machine must change for one new instruction?

## motivation (above the table; about 120 words, a list allowed)

1. The new instruction does two things at its last edge:
   - RY ← PC + 4, as a call does: register Y keeps the address of the next instruction;
   - PC ← RA + c, as a jump does: the address comes from a register.
2. A call goes to PC + 4c, a place fixed when the program is written. The new instruction goes to
   the address in RA, so the program can choose the place while it runs.
3. It takes kind 9, job 0. Kind 9 is the first kind the machine leaves free.
4. Its word for `R15 ← PC + 4, PC ← R4 + 0` is `9040F000`: kind 9, job 0, A is R4, B is R0, Y is
   R15, constant 0.

## callAndJumpLead (above the table of kinds 6 and 7; about 50 words)

1. The table shows the decoder's columns for a call, kind 6, and a jump, kind 7.
2. The call sets WRITEY and CALL: register Y takes PC + 4.
3. The jump sets BCONST, OP1 (add) and JUMP: the PC takes the ALU's result, RA + c.

## p1Question (one or two sentences)

The PC is `004`, the call through R4. How many edges does it take, from its fetch to the edge
where the PC moves on?

## p1Explain (about 110 words, a list allowed)

1. It takes 3 edges, as a call does:
   - FETCH: IR ← memory[PC];
   - READ: HA ← R4, HB ← R0;
   - WRITE: R15 ← PC + 4, which is `008`, and PC ← HA + c, which is `00C`.
2. The decoder sets CALL, so the controller goes from READ to WRITE.
3. It needs no ALU edge. The ALU is gates. From the READ edge on, HA holds R4 and the constant
   is in IR, so the ALU's result is ready before the WRITE edge.
4. A jump also takes the PC from the ALU at the first edge after READ. For a jump that edge is
   in ALU; here it is in WRITE.

## chooseLead (above the investigation's figure; about 140 words, a list allowed)

1. The office chooses at run time which room's reading the display shows. R4 holds the address
   of the routine to call.
   - `000` R4 ← `00C`, the address of showA
   - `004` `9040F000`: R15 ← PC + 4, PC ← R4 + 0
   - `008` stop
   - `00C` showA: R2 ← memory[`7D8`] (room A)
   - `010` memory[`7C0`] ← R2 (the display)
   - `014` `70F00000`: jump, PC ← R15
   - `018` showB: R2 ← memory[`7E0`] (room B)
   - `01C` memory[`7C0`] ← R2
   - `020` jump, PC ← R15
2. With R4 ← `018` instead, the same call would run showB.
3. Press "Clock edge" or "Run until it stops", and watch the views of each edge.

## chooseAfter (below the figure; about 70 words)

2. R15 holds `008`, the address after the call.
3. The call through R4 takes 3 edges. The jump back at `014` takes 3, and returns to `008`, the
