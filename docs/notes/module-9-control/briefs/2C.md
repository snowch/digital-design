# Brief 2C: lesson `illegal-instructions` (Module 9, lesson 2), explanation to the end

Read `00-module.md` (the shared fact sheet) first; it applies here. "control unit" and
"illegal instruction" are allowed. "instruction register" and "micro-operation" must not
appear.

Keys to write: `explanation`, `kindMapLead`, `kindMapAfter`, `generalisation`,
`writeChecksLead`, `c2Task`, `c2Hints.1` to `c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (above the map; about 100 words)

1. ILLEGAL is an OR of three checks: no kind line, a bad job, a bad number.
2. The checks read the kind lines, the job's bits and the constant's bits. They are gates, like
   the control signals, and settle in the same edge.
3. The cause block gives CAUSED `21` when ILLEGAL is 1. The stop logic then stops the machine,
   and the figures say why.
4. An illegal instruction changes no register and no memory word.

## kindMapLead (above the map figure; about 60 words)

1. The map is read off the decoder's own circuit: the figure gives it every kind and job twice,
   with the constant 0 and with 5, and reads CAUSED.
2. One row per kind, `0` to `F`; one column per job, `0` to `F`: 256 cells.
3. A tick marks an instruction, a dot an illegal word, and c a word that is an instruction only
   when its constant is 0 to 4.

## kindMapAfter (below the map; about 70 words)

1. 37 cells are instructions, 2 depend on the constant, and 217 are illegal.
2. The two c cells are jobs 2 and 3 of kind 8.
3. Rows 0 and 9 to F are all dots: no kind line.
4. Row 1, a register job, has ticks for jobs 0 to 7. Row 3, a load, has ticks for jobs 0, 1, 8
   and 9.

## generalisation (about 90 words)

1. A decoder that knows its kinds can refuse every other word. Each kind's line is a check: a
   word with no line is illegal.
2. Giving the machine a new kind gives it a line. The kind check then passes it, and the job
   check must learn which of its jobs exist.
3. A word can reach the decoder by mistake: a jump to a wrong address runs whatever word is
   there. The checks stop the machine there, instead of letting it run on.

## writeChecksLead (above the challenge; one sentence)

Write the whole check: ILLEGAL from K, J and C.

## c2Task (about 130 words)

1. The module `checks` has inputs K, J (4 bits each) and C (12 bits), and output ILLEGAL.
2. The start has the kind check only: `assign ILLEGAL = (K == 4'h0) | (K[3] & (K != 4'h8));`.
   K3 is 1 for kinds 8 to F, so the second term is kinds 9 to F.
3. Add a term, ORed in, for each other reason: a job its kind does not define, and job 2 or 3 of
   kind 8 with a number outside 0 to 4. Use your OUTSIDE expression from the last challenge.
4. The tests give every kind and job with the constant 0, and jobs 2 and 3 of kind 8 with 12
   other constants: 280 tests. The start fails 105 of them.

## c2Hints (five rungs; the fifth gives the whole answer)

1. Write one term per group of kinds that share their jobs: kinds 1, 2 and 5; loads and stores;
   calls and jumps; kind 8.
2. A common mistake: ORing OUTSIDE in on its own. Then `stop` with constant 5 is refused.
   OUTSIDE counts only for jobs 2 and 3 of kind 8: `(J[3:1] == 3'b001)`.
3. Kinds 1, 2 and 5: `(((K == 4'h1) | (K == 4'h2) | (K == 4'h5)) & J[3])`. Loads and stores:
   `(((K == 4'h3) | (K == 4'h4)) & (J[2] | J[1]))`.
4. Calls and jumps: `(((K == 4'h6) | (K == 4'h7)) & (J != 4'h0))`. Kind 8's jobs 5 to F:
   `((K == 4'h8) & (J[3] | (J[2] & (J[1] | J[0]))))`.
5. The whole answer:

   ```
   assign ILLEGAL = (K == 4'h0) | (K[3] & (K != 4'h8))
     | (((K == 4'h1) | (K == 4'h2) | (K == 4'h5)) & J[3])
     | (((K == 4'h3) | (K == 4'h4)) & (J[2] | J[1]))
     | (((K == 4'h6) | (K == 4'h7)) & (J != 4'h0))
     | ((K == 4'h8) & (J[3] | (J[2] & (J[1] | J[0]))))
     | ((K == 4'h8) & (J[3:1] == 3'b001) & ((C[11:3] != 9'h0) | (C[2] & (C[1] | C[0]))));
   ```

## reflection (about 90 words)

1. Every word now either runs as one of the machine's instructions or stops the machine with
   cause `21`.
2. The decoder is the whole control unit of Module 8's machine: gates from K, J and C.
3. That machine runs each instruction in one edge, so it reaches memory twice in that edge: the
   fetch at the PC, and a load's or a store's word at the ALU's result.
4. End on the question: what if the machine had one memory reached by one address, as Module 6's
   memory was? How could one instruction use it twice?

## modelVsReality (about 80 words)

1. A real machine does not stop at an illegal instruction. It goes to a program that deals with
   it. Module 12 builds that.
2. Real makers keep some kinds free, as this machine keeps kinds 9 to F. A later machine can give
   them a meaning.
3. A program written for that later machine still runs here until it reaches a new kind. There
   this machine stops with cause `21`.
