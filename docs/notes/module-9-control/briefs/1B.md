# Brief 1B: lesson `control-signals` (Module 9, lesson 1), construction and faults

Read `00-module.md` (the shared fact sheet) first; it applies here. "control unit" is allowed
(this lesson introduced it). "illegal instruction", "instruction register" and
"micro-operation" must not appear.

Keys to write: `construction`, `writeWritesLead`, `c1Task`, `c1Hints.1` to `c1Hints.5`,
`decoderFaultsLead`, `decoderFaultsOutcomes`.

## construction (about 70 words)

1. Two signals as text, each read off the kinds that need it.
2. WRITEY is 1 for the kinds that write register Y: register jobs (1), constant jobs (2), loads
   (3) and calls (6).
3. BCONST is 1 for the kinds whose ALU takes the constant as B: constant jobs (2), loads (3),
   stores (4) and jumps (7).
4. In text, a kind's line is a comparison: `(K == 4'h3)` is 1 only for kind 3. An OR of
   comparisons is the OR of kind lines.

## writeWritesLead (above the challenge; one sentence)

Write WRITEY and BCONST from K.

## c1Task (about 90 words)

1. The module `writes` has input K (4 bits) and outputs WRITEY and BCONST.
2. The start sets both to 0: `assign WRITEY = 1'b0;` and `assign BCONST = 1'b0;`.
3. Replace each with an OR of comparisons on K, one for each kind that needs the signal.
4. The tests try all 16 values of K, `0` to `F`. Kinds 0 and 9 to F set neither signal, nor does
   kind 8.
5. Allowed: `assign`, `==`, `|`, `&`, `~`.

## c1Hints (five rungs, one step each; the fifth gives the whole answer)

1. Name the kinds that write register Y. Which kinds' ALU takes the constant?
2. A common mistake: a jump writes no register. Its WRITEY is 0, though its BCONST is 1.
3. One kind's line: `(K == 4'h6)` is 1 only for a call.
4. `assign WRITEY = (K == 4'h1) | (K == 4'h2) | (K == 4'h3) | (K == 4'h6);`
5. The whole answer:

   ```
   assign WRITEY = (K == 4'h1) | (K == 4'h2) | (K == 4'h3) | (K == 4'h6);
   assign BCONST = (K == 4'h2) | (K == 4'h3) | (K == 4'h4) | (K == 4'h7);
   ```

## decoderFaultsLead (above the fault lab; about 90 words)

1. The figure shows the decoder's "control signals" block. Each fault breaks one part of it.
2. "orOp0 made an AND": the OR gate for OP0 becomes an AND gate. OP0's OR joins JOBS AND J0 with
   BRANCH.
3. "LOAD stuck at 0": kind 3's line is 0 whatever K is.
4. Choose a fault, then press "Run checks". The checks give the decoder seven
   instructions, one of each kind 1 to 7. Before you run them, say which instructions you think
   will fail. [Do not say which fail; that is in the outcomes.]

## decoderFaultsOutcomes (shown after a run; about 120 words, a list allowed)

1. "orOp0 made an AND": two checks fail, both on OP0. The subtract (kind 1, job 3) needs OP0 at
   1, from JOBS AND J0. The branch (kind 5, job 6) needs OP0 at 1, from BRANCH. An AND of the two
   is 1 for neither, since no instruction is both kinds. The other five need OP0 at 0, and get it.
   A wrong gate breaks one signal, for some kinds.
2. "LOAD stuck at 0": only the load fails, on five outputs: WRITEY, LOAD, BCONST and OP1 are 0,
   and CAUSED is `21`. With its line at 0, no kind line is 1 for the load, so the checks treat it
   as a word the decoder does not know. A lost kind line breaks every signal of one kind.
