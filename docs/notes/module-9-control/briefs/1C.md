Keys to write: `explanation`, `signalsTableLead`, `signalsTableAfter`, `generalisation`,

## explanation (above the table; about 110 words)

1. The decoder is built as Module 5 built next-state logic from a table.
2. Module 5: Module 3's decoder gave one line per state; each row was an AND gate; each bit of
   the next state was an OR of the rows that give it a 1.
3. Here: two of Module 3's decoders and an AND gate per kind give one line per kind. Each
   control signal is an OR of the kind lines that need it.
4. Where a signal follows the job, an AND gate joins the kind's line with that job bit first.
5. The decoder has no register. Its signals change as soon as K or J changes, and settle before
   the next edge.

## signalsTableLead (above the table figure; about 60 words)

1. The table is read off the decoder's own circuit: the figure gives it each kind with every job
   the kind defines, and reads its outputs.
2. One column per kind, 1 to 8; one row per signal.
3. A cell is 1 or 0, or J2, J1 or J0 where the signal is that bit of the job digit.
4. Read down a column for what one kind needs.

## signalsTableAfter (below the table; about 100 words, a list allowed)

1. Read along a row for the kinds an OR gate joins. WRITEY is 1 for kinds 1, 2, 3 and 6. BCONST
   is 1 for kinds 2, 3, 4 and 7.
2. For kinds 1 and 2, OP2, OP1 and OP0 are J2, J1 and J0: the job digit is the ALU's code. There
   is no second decoder for the ALU.
3. A load, a store and a jump add, `010`: they work out an address. A branch subtracts, `011`.
4. For a load or a store, AZERO is J3 and BYTE is J0.
5. Kind 8, a system job, sets every signal to 0.

## generalisation (about 100 words)

1. This way of building a decoder works for any list of kinds. Each kind gets one line. Each
   signal is an OR of the lines that need it.
2. Adding a kind adds one line and joins it to the OR of every signal the kind needs. No other
   kind's signals change.
3. Kinds 0 and 9 to F have no line, so every signal is 0 for them.
4. Gates suffice because Module 8's machine runs each instruction in one edge. A machine that
   takes several edges for one instruction needs signals that change from edge to edge. Lesson 3
   adds them.

## writeSignalsLead (above the challenge; one sentence)

Write all twelve control signals as one `case` on K.

## c2Task (about 120 words)

1. The module `signals` has inputs K and J (4 bits each) and outputs the twelve control signals:
   WRITEY, LOAD, STORE, BYTE, AZERO, BCONST, OP2, OP1, OP0, BRANCH, CALL, JUMP.
2. In an `always_comb` block, every signal is first set to 0. Then a `case (K)` arm per kind sets
   the signals that kind needs.
3. The start has the arms for kinds 1 and 2. Add the arms for kinds 3 to 7. Kind 8 needs no arm:
   every signal stays 0.
4. A signal that follows the job is set to the job's bit: `OP2 = J[2];`.
5. The tests give each kind every job it defines, and system jobs 0 to 4: 39 tests.

## c2Hints (five rungs; the fifth gives the whole answer)

1. Copy kind 2's arm and change it for kind 3. Use the table above for each kind's column.
2. A common mistake: setting OP1 for a load from J. A load always adds: OP1 is 1, OP2 and OP0
   stay 0.
3. Kind 3: `4'h3: begin WRITEY = 1'b1; LOAD = 1'b1; BCONST = 1'b1; OP1 = 1'b1; AZERO = J[3]; BYTE = J[0]; end`
4. Kind 5: `4'h5: begin BRANCH = 1'b1; OP1 = 1'b1; OP0 = 1'b1; end`. Kind 6:
   `4'h6: begin WRITEY = 1'b1; CALL = 1'b1; end`
5. The five arms, after kind 2's:

   ```
   4'h3: begin WRITEY = 1'b1; LOAD = 1'b1; BCONST = 1'b1; OP1 = 1'b1; AZERO = J[3]; BYTE = J[0]; end
   4'h4: begin STORE = 1'b1; BCONST = 1'b1; OP1 = 1'b1; AZERO = J[3]; BYTE = J[0]; end
   4'h5: begin BRANCH = 1'b1; OP1 = 1'b1; OP0 = 1'b1; end
   4'h6: begin WRITEY = 1'b1; CALL = 1'b1; end
   4'h7: begin JUMP = 1'b1; BCONST = 1'b1; OP1 = 1'b1; end
   ```

## reflection (about 90 words)

1. The decoder is gates: one line per kind, and an OR per signal, with a job bit ANDed in where
   the job matters.
2. The table of signals is the decoder's circuit written out.
3. Every word with a kind from 1 to 8 gets that kind's signals. A word of kind 0 or 9 to F gets
   none.
4. End on the question: what should the machine do with a word that is no instruction: kind 0,
   kind 9, or a job its kind does not define, such as job 8 of a register job?

## modelVsReality (about 80 words)

1. Real design tools simplify the gates. They share terms between signals and drop gates that
   change nothing.
2. The course keeps one OR per signal, so each gate matches a row of the table. Both give the
   same signals.
3. In the model the decoder settles in a few steps of the settle model. A real decoder's gates
   take time, and that time adds to each instruction's path from the fetch to the register
   write. [Say "steps of the settle model" once, as Module 8 did; do not give a number.]
