# Brief 3B: lesson `several-edges` (Module 9, lesson 3), construction and faults

Read `00-module.md` (the shared fact sheet) first; it applies here. "control unit", "illegal
instruction" and "instruction register" are allowed. "micro-operation" must not appear.

Keys to write: `construction`, `writeFetchportLead`, `c1Task`, `c1Hints.1` to `c1Hints.5`,
`edgeFaultsLead`, `edgeFaultsOutcomes`.

## construction (about 90 words)

1. Two parts make one memory port serve both the fetch and the data.
2. A selector chooses the memory's address, ADDR. While FETCHING is 1 it is the PC. Otherwise it
   is HR, the address the ALU worked out.
3. FETCHING comes from the controller: it is 1 in the state FETCH.
4. The instruction register takes FETCHED, the memory's word at the address, at an edge where
   IREN is 1. At a reset it becomes 0.

## writeFetchportLead (above the challenge; one sentence)

Write the memory's address and the instruction register.

## c1Task (about 120 words)

1. The module `fetchport` has inputs CLK, RST, FETCHING, IREN, PC and HR (64 bits each) and
   FETCHED (32 bits). Its outputs are ADDR (64 bits) and IR (32 bits).
2. The start is Module 8's way: `assign ADDR = PC;` and `assign IR = FETCHED;`.
3. Make ADDR a selector on FETCHING: the PC when it is 1, HR when it is 0.
4. Make IR a register: at a rising edge of CLK it takes 0 if RST is 1, otherwise FETCHED if IREN
   is 1. Otherwise it keeps its word.
5. The tests reset IR, fetch `380027D8`, then check that IR keeps it while FETCHED changes. One
   test changes IREN while CLK is 1: IR must not change. 8 tests.

## c1Hints (five rungs; the fifth gives the whole answer)

1. ADDR is a selector, as in Module 3: `always_comb` with `case (FETCHING)`.
2. A common mistake: leaving IR as an `assign`. Then IR follows FETCHED at every moment, and the
   instruction is lost when the address moves on to HR.
3. The selector: `always_comb case (FETCHING) 1'b0: ADDR = HR; 1'b1: ADDR = PC; endcase`
4. The register: `always_ff @(posedge CLK)`, with `if (RST)` first, then `else if (IREN)`.
5. The whole answer:

   ```
   always_comb
     case (FETCHING)
       1'b0: ADDR = HR;
       1'b1: ADDR = PC;
     endcase
   always_ff @(posedge CLK)
     if (RST) IR <= 32'h0;
     else if (IREN) IR <= FETCHED;
   ```

## edgeFaultsLead (above the fault figure; about 110 words)

1. The figure runs the margin program from Module 8, which stores R1 - R2 to the display. With
   no fault it stops after 18 edges, and the display shows 66.
2. The bus table shows IR and ADDR, the memory's address.
3. "FETCHING stuck at 1": the address is always the PC.
4. "Row 4 stuck at 0": row 4 of the controller's table, ALU to MEMORY when MEM is 1, never gives
   1.
5. Choose a fault and press "Run until it stops". Before you do, say what you think the display
   will show. [Do not say what happens; that is in the outcomes.]

## edgeFaultsOutcomes (shown after a run; about 130 words, a list allowed)

1. "FETCHING stuck at 1": the first three instructions run as they should. R1 is -184, R2 -250
   and R3 66. The store at `00C` goes wrong. At its MEMORY edge the address is the PC, `00C`,
   not HR, `7C0`. A word at `00C` is not at a multiple of 8, so the machine stops after 16 edges
   with cause `33`. The display shows 0.
2. "Row 4 stuck at 0": the store never reaches MEMORY. At its ALU edge MEM is 1, but row 4 gives
   0, and no other row applies. The next state is FETCH, so the edge ends the store, and nothing
   is written. The machine stops after 17 edges, and the display shows 0.
