# Brief 4C: lesson `micro-operations` (Module 9, lesson 4), explanation to the end

Read `00-module.md` (the shared fact sheet) first; it applies here. "control unit", "illegal
instruction", "instruction register" and "micro-operation" are allowed.

Keys to write: `explanation`, `generalisation`, `writeControllerLead`, `c2Task`, `c2Hints.1`
to `c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 130 words)

1. In Module 5, the output logic read the state alone. Here it reads the state and the decoder's
   signals.
2. The decoder's signals come from IR, which changes only at a fetch edge. So they stay the same
   through the instruction's other edges.
3. PCEN uses the next-state logic: it is 1 when the next state is FETCH. The edge that ends the
   instruction is the edge that leads back to FETCH.
4. Each micro-operation needs its signals at 1 before its edge. Between edges the state, the
   decoder and the output logic settle, and the signals wait at the registers' enables. At the
   edge, the registers whose enables are 1 take their words.

## generalisation (about 100 words)

1. Every instruction of the machine is a list of micro-operations, a few per edge.
2. Every control signal is the state's line, AND what the kind needs, AND GO. A new kind needs
   no new signal if its micro-operations are ones the machine already makes: a list of states,
   and a column of signals in the decoder.
3. The four views read the same simulator: the instruction, its micro-operations, the signals
   and the circuit. A wrong signal shows in all four at once.

## c2Task (about 130 words)

1. The module `controller` has inputs CLK, RST, GO, CALL, MEM, WRITEY, LOAD and STORE. Its
   outputs are the ten control signals of the last challenge and S.
2. The start has lesson 3's state register and next-state logic. Every output but S is 0.
3. Write each output as an `assign` on `state`, the `typedef enum` names, and the inputs. For
   PCEN, compare `next` with FETCH.
4. The tests take a load, a store, a branch and a call through their states from a reset. They
   check S and every output before each edge. Then a stop: GO falls while CLK is 1, and the
   state stays READ. 35 tests.

## c2Hints (five rungs; the fifth gives the whole answer)

1. Each output is one `assign`. The state's line is a comparison: `(state == READ)`.
2. A common mistake: ANDing GO into CHECKING. When GO falls in READ, CHECKING must stay 1: the
   stop logic reads it.
3. `assign HOLDAB = (state == READ) & GO;`
4. `assign PCEN = (next == FETCH) & GO;` The edge that leads back to FETCH ends the instruction.
5. The whole answer, in place of the ten zeros:

   ```
   assign FETCHING = (state == FETCH);
   assign IREN = (state == FETCH) & GO;
   assign CHECKING = (state == READ);
   assign HOLDAB = (state == READ) & GO;
   assign HOLDR = (state == ALU) & GO;
   assign MLOAD = (state == MEMORY) & LOAD;
   assign MSTORE = (state == MEMORY) & STORE;
   assign HOLDM = (state == MEMORY) & LOAD & GO;
   assign WREG = (state == WRITE) & WRITEY & GO;
   assign PCEN = (next == FETCH) & GO;
   ```

## reflection (about 100 words)

1. The control unit is complete. The decoder says what the kind needs. The controller's state
   says which edge it is. Each control signal is the two together, AND GO.
2. Each edge makes its micro-operations, and the instruction's transfer is all of them together.
3. The course's machine leaves out a call through a register: RY ← PC + 4, and PC ← RA + c, so
   that the routine called can be chosen while the program runs.
4. End on the question: what would the machine need to run it? Which parts would change?

## modelVsReality (about 100 words)

1. After an edge, the state changes, and the output logic settles. On the way, a signal can
   take a passing value, as Module 8 showed.
2. The course's registers and its RAM take a word only at an edge. A passing value that settles
   before the next edge does no harm.
3. Many real memories write while their write signal is 1, not at an edge. A passing 1 on that
   signal can write a wrong word.
4. Real designs take such signals from a register, or time them so they cannot pass through 1.
