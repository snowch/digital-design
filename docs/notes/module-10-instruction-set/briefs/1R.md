## question (about 90 words)

1. Module 9 ended on a question. Which instructions a machine has is a choice, and so is how their
   words are laid out. Why are the course's instructions the ones they are?
2. Before that question, this lesson settles what a program can rely on.
3. Two machines in the course run the same programs. Module 8's machine takes one edge for each
   instruction. Module 9's takes 2 to 5, with one memory port, an IR register and held words.
4. Both ran the colder-room program and showed -250 on the display.
5. End on the questions: what is the same between the two machines? What can a program rely on,
   whichever machine runs it?

## motivation (about 90 words)

1. The two machines have different parts. Module 9's machine has an IR register, held words HA,
   HB, HR and HM, and the controller's state. Module 8's has none of these; its IR is a bus, the
   ROM's output at the PC.
2. Both have R0 to R15, the PC, the memory (the ROM and the RAM) and the shop's devices.
3. The course ran Module 8's 37 programs on Module 9's machine. After every instruction, the two
   machines agreed on every register, the PC, the memory and the devices.

## sideBySideAfter (about 80 words)

1. The program runs 6 instructions, the stop among them.
2. Module 8's machine takes 1 edge for each: 6 in all.
3. Module 9's takes 5, 5, 3, 4 and 4 edges, then 2 for the stop: its fetch, and the edge at which
   it halts the machine, in READ. 23 in all.
4. After every instruction, the machines agree on the PC, R2, R3 and the display. The figure also
   checks every other register, the RAM and the devices: all agree. Both displays show -250.
5. Between instructions, Module 9's machine holds words in its IR, HA, HB, HR and HM. Module 8's
   machine has no parts for them.

## construction (about 90 words)

1. A program sees a part of the machine only through an instruction: through a field that names a
   register, an address a load or a store reaches, or the PC, which branches, calls and jumps move.
2. Running an instruction moves the circuit's own parts too, but no field, address or PC reaches
   them, so the program does not see them. No field names HB or HM.
3. Every machine that runs the same programs must agree, after every instruction, on what a
   program can see. What a circuit does with its own parts is its own choice.

## faultHoldr (keep the heading line `**HOLDR stuck at 1**`; about 70 words)

1. The machines agree after every instruction. Both displays show -250.
2. HR takes a word at every edge. After the ALU edge it takes the same result again, because HA,
   HB and the IR do not change until the next fetch. At FETCH and READ it takes words that no
   later edge reads.
3. The course ran Module 8's 37 programs on both machines with this fault. None differs on what a
   program can see.

## faultPcen (keep the heading line `**PCEN stuck at 1**`; about 110 words)

1. The machines differ after the first edge, on R2.
2. The controller still takes the load's 5 edges, FETCH to WRITE, but the PC moves on at every one
   of them. Each of those edges ends an instruction, so Module 8's machine runs one instruction
   for each.
3. Module 9's machine writes R2, -184, at the load's WRITE edge. By then its PC is at `014`, so it
   fetches the stop next and skips the four instructions between. R3 stays X on Module 9's
   machine, and its display shows 0, where Module 8's shows -250.
4. Both machines halt on the stop at `014`. Module 9's PC has moved on to `01C` by then (the halting edge moves it too, while PCEN is stuck at 1).
5. All 37 of Module 8's programs differ with this fault.

## explanation (about 170 words)

1. The list of instructions a machine runs, each with its word's layout and what it does to the
   parts a program can see, is the machine's **instruction set**. The parts a program can see are
   R0 to R15, the PC, the memory and the devices. Programs are written for the instruction set.
2. Every machine that runs the course's programs must agree on those parts after every
   instruction. The agreement says nothing about the edges inside an instruction, nor about a
   circuit's own parts.
3. The timer counts instructions, not edges, so both machines read the same count after every
   instruction.
4. A **microarchitecture** is one circuit that runs an instruction set: one edge an instruction or
   several, one memory port or two, held words or none. Module 8's machine and Module 9's are two
   microarchitectures of one instruction set.
5. The test for a fault: does a wrong word reach a part a program can see? HOLDR stuck at 1 puts
   words only into HR, which no program sees: the agreement holds. PCEN stuck at 1 moves the PC.
   HOLDR stuck at 0 leaves HR unwritten; Module 9's state goes to X after the first load's MEMORY
   edge, and 29 of the 37 programs differ.

2. Make the register jobs and constant jobs write register Y at the ALU edge and end there:

3. The memory holds one program, run three times from a reset, the shop's signals choosing the

   Third, with WARM at 1, R3 is stored to the display: the registers keep their words through a

4. There are 73 tests. The start fails 48 of them. The first failure is "Margin: 004, edge 3
   (ALU): FETCH after it, PC 008".

## c2Hint2

A common mistake: changing only the next-state logic. The jobs then take 3 edges but write
nothing: R6 stays unknown, and the branch at `008` cannot tell where to go.

## reflection (about 70 words)

1. The instruction set is the agreement. A microarchitecture is one circuit that runs it. Your
   third circuit ran the tests' program to the same results as Module 9's.
2. The agreement covers what each instruction does, and how each instruction's word is laid out:
   K, J, A, B, Y and three digits of constant, each field in the same place in every instruction.
3. End on the question: why does every field keep one place in every instruction, and what does
   that cost?

## modelVsReality (about 70 words)

1. The figures compare the two machines with each other, after every instruction. The course's
   tests compare Module 9's machine with a model of the machine that runs one instruction at a
   time, on Module 8's 37 programs. Makers of real machines test a new circuit the same way:
   against such a model, on many programs.
2. A maker may sell a small, slow circuit and a large, fast one that run the same programs. How
   long an instruction takes is not part of the agreement, on the course's machines or on real
   ones.
