# Brief 5C: lesson `design-an-instruction` (Module 10, lesson 5), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. Every Module 10 term is
allowed. No new term. Never write "assembly" or "assembler".

Keys to write: `explanation`, `generalisation`, `writeMachineLead`, `c3Task`, `c3Hints.1` to
`c3Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 170 words, a list allowed)

1. What set if changed, part by part:
   - the decoder: a column for kind A, whose line is the new control signal SET. WRITEY, OP1 and
     OP0 take kind A into their ORs. The checks learn kind A, and refuse its jobs 8 to F;
   - the controller: no change. Set if takes a register job's 4 edges. At WRITE, MET is worked out
     again from the held words;
   - the datapath: a new source for the word register Y takes, MET as a word, chosen by SET. In
     the machine's text it is the line `if (SET) YIN = {63'h0, MET};`.
2. The instruction set changed in your copy only. The course's machine still refuses kind A, with
   cause `21`.
3. Module 9's call through a register needed a column and the checks. Set if needs those and a new
   source in the datapath.

## generalisation (about 120 words)

1. A new instruction can need four things: a column in the decoder, a place in the checks, states
   of its own, and new parts in the datapath.
2. The call through a register needed the first two. Set if needed three: a column, the checks,
   and a new source for register Y.
3. A shift or a multiplication would need a new part beside the ALU.
4. Every program written for your copy before kind A still runs on it: no old word changed its
   meaning.

## writeMachineLead (one sentence)

Join SET to the datapath and run the whole machine.

## c3Task (about 170 words, a list allowed)

1. The text is your whole copy of Module 9's machine, with kind A in its decoder: the module
   `machine`, the controller and the decoder.
2. The decoder gives SET, but the module `machine` does not use it, so set if writes HR, the
   subtraction.
3. Make three changes in the module `machine`:
   - declare SET among the control signals;
   - join the decoder's SET port: `.SET(SET)`;
   - in the block that chooses YIN, add a line so that when SET is 1, YIN takes MET as a word,
     `{63'h0, MET}`.
4. The memory holds the program that counts the cold rooms with set if.
5. The tests reset the machine, check the state and the PC after every edge of every instruction,
   then HALT and the display, 1, at the stop. There are 33 tests.
6. The start fails 1: at the stop it displays -34, not 1.

## c3Hints (five, in this order)

1. The idea: the decoder already raises SET. The datapath must give register Y the condition when
   it does.
2. A common mistake: writing `YIN = MET;`. MET is 1 bit and YIN is 64, so the text does not
   elaborate. Put 63 zeros in front of MET.
3. A smaller example, the decoder's port: `.SET(SET)` beside `.MEM(MEM)`.
4. Part of the answer, after the line `if (CALL) YIN = PC4;`:
   `if (SET) YIN = {63'h0, MET};`
5. The whole answer: SET added to the line that declares STOP and the other control signals; the
   port in hint 3; the line in hint 4.

## reflection (about 100 words)

1. You designed, justified and built an instruction. Your copy runs it; the course's machine still
   refuses kind A.
2. Module 10 asked what a program may rely on: the instruction set, each instruction's layout and
   what it does to the parts a program can see.
3. Every program so far was given to you as words and transfers. Writing a longer program word by
   word is slow, and a wrong digit is easy to make.
4. End on the question: how could you write programs in a form a person reads, and let a tool make
   the words?

## modelVsReality (about 70 words)

1. Your kind A lives in your copy of the machine's text only.
2. A maker who adds an instruction makes a new chip. Programs that use the new instruction need
   that chip; the older chips refuse it, as the course's machine refuses kind A.
