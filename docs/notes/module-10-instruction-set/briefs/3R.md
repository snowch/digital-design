## question (about 90 words)

1. Lesson 2 ended on three questions. Quote them: What can one instruction say in 12 bits? How
   far can a branch reach? What does a program do with a number too wide for the constant?
2. A fourth thread: a branch compares two registers, but the machine has no "greater than" test.
3. End on the question: how does a program say "greater than"? Then: is 12 bits enough for what

## motivation (about 130 words)

1. The constant is digits 2 to 0: 12 bits, read signed, widened to 64 bits by copying bit 11
   (Module 8's lesson 2). It holds -2048 to 2047.
2. `000` to `7FF` widen to 0 to 2047. `800` to `FFF` have bit 11 at 1, so they widen to negative
   numbers, -2048 to -1. A load at the constant `800` stops the machine with cause `31`: the
   address is outside the memory.
3. So the largest address a constant names is `7FF`. The memory has 2 KB, `000` to `7FF`: it was
   given exactly that much. Module 8's lesson 4 said every address fits in the constant; this is
   why.
4. A branch's constant counts instructions, not bytes: the target is PC + 4c. Lesson 2 said a
   branch reaches the whole ROM of 256 instructions; this is why: 2047 instructions forward,
   2048 back.

## prediction (about 80 words)

1. A branch tests a condition: equal, differs, less, or not less, with less and not less read
   signed or unsigned. There is no "greater than".
2. A program must branch if R1 > R2, read signed.
3. The figure's table shows three pairs of values for R1 and R2: 5 and -3; -3 and 5; 5 and 5.
4. Choose the branch that is taken for every pair exactly when R1 > R2, then press "Check my
   prediction".
5. The figure then shows, for each pair, whether R1 > R2 holds and whether each branch is taken.

## comparisonsLead (about 70 words)

1. Choose a pair of values for R1 and R2 from four: 5 and -3, -3 and 5, 5 and 5, and the largest
   signed number and -1.
2. The table has a row for each comparison, read signed and read unsigned.
3. Each row shows the branch that says it, the subtraction that branch makes with its flags, and
   whether the machine takes the branch.
4. Rows where the branch names its registers swapped are marked.

## comparisonsAfter (about 90 words)

1. In every row, the branch is taken exactly when the comparison holds.
2. "Greater than" is "less than" with R1 and R2 swapped. "Not greater", R1 <= R2, is "not less"
   swapped.
3. With the last pair, the rows R1 < R2 and R1 >= R2 subtract R2 from R1. That subtraction
   overflows: MINUS 1, OVER 1, so MINUS XOR OVER is 0 and R1 < R2, signed, is false.
4. The rows R1 > R2 and R1 <= R2 subtract R1 from R2. That one does not overflow: MINUS 1, OVER 0,
   so MINUS XOR OVER is 1 and R1 > R2, signed, is true.
5. Read unsigned, -1 is the largest word of all, so R1 > R2 is false. The same bits answer
   differently when read differently.

## p2Question

How many instructions does the first program run to show 5000, the store to the display and the
stop among them?

## p2Explain (about 70 words)

1. 5 instructions: R1 ← 2047, R1 ← R1 + 2047, R1 ← R1 + 906, the store, the stop.
2. Each constant job adds at most 2047, and 5000 needs three of them.
3. Module 8's lesson 2 built 3600 by doubling: R6 ← 1800, then R6 ← R6 + R6.
4. Doubling builds 5000 in three jobs too: R1 ← 1250, then R1 ← R1 + R1 twice.

## wideAfter (about 70 words)

1. Both programs put 5000 into R1 and onto the display.
2. The first: 5 instructions written and run, 20 bytes of ROM.
3. The second: 3 instructions written and run, 24 bytes of ROM: the three instructions, 4 bytes
   of padding so the word starts at a multiple of 8, and the word's 8 bytes.
4. A word in the ROM holds any 64-bit number for one load. Sums or doublings need more jobs as
   numbers grow.

## explanation (about 90 words)

1. A number kept inside the instruction itself is what books call an **immediate**. It is there
   as soon as the instruction is read. The course's immediate is the 12-bit constant, read
   signed and widened to 64 bits.
2. The branch conditions test for less and not less, read signed or unsigned. With the two
   registers in order or swapped, they give all four comparisons: less, not less, greater, not
   greater.
3. The machine needs no job for "greater than": a program names the registers the other way round
   and uses the less test.
4. Each branch decides from one subtraction's flags; the swapped branch makes the other
   subtraction, so it has flags of its own.

## generalisation (about 80 words)

1. A number too wide for the constant can be kept as a word in the ROM. One load reads it, and it
   can be any 64-bit number.
2. Or a program builds it from jobs: sums of constants, each adding at most 2047, or doubling a
   register.
3. A number used once and not much wider than the constant can be built. A larger one, or one used
   in many places, is better kept as a word.
4. An instruction set's constant is a balance: it must fit in the instruction, and the course's
   memory was sized so that its 12 bits name every address.

## reflection (about 50 words)

1. Twelve bits name every address and reach every branch target in the ROM. The swap gives every
   comparison.
2. On the course's machine, kinds 0 and 9 to F name no instruction.
3. End on two questions: What does the machine do with an instruction's 32 bits that name no
   instruction? What else does the instruction set leave out, and what would each cost to add?

## modelVsReality (about 70 words)

1. The programs in this lesson's figures run on a model of the machine that runs one instruction
   at a time (lesson 1's). It leaves out the clock edges and the parts a program cannot see: the
   IR, the held words, the controller's state.
2. Many real machines have constants wider than 12 bits and memories far larger than 2 KB. On them,
   not every address fits in one instruction: a program builds a large address in several.
