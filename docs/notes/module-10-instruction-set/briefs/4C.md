# Brief 4C: lesson `room-to-grow` (Module 10, lesson 4), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. "Instruction set",
"microarchitecture", "opcode" and "immediate" are allowed. No new term.

Keys to write: `explanation`, `generalisation`, `countLoopLead`, `c2Task`, `c2Hints.1` to
`c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 150 words, with this table)

1. Every instruction the machine leaves out would cost the circuit something, and would save
   programs something.
2. Give this table as a Markdown table, with these rows and these facts, in short phrases:

| Left out | What the circuit would need | What a program does without it |
| --- | --- | --- |
| Multiplication | a new part beside the ALU | adds in a loop, 3 instructions run each time round |
| A shift | a new part beside the ALU: a shift is not a chain of one-bit slices | doubles a number by adding it to itself, one instruction a place |
| Set if less | a new source for register Y, the condition as a word, and a control signal | a branch and a count around each comparison |
| Call through a register | a decoder column and two terms of the checks (Module 9) | chooses among fixed calls with branches |
| Comparison with zero | a 0 on the ALU's B, as AZERO gives a 0 on A | keeps 0 in a register: one instruction, once |
| A wider constant | a second layout, with selectors (lesson 2) | a word in the ROM and one load, or sums of constants |

3. An instruction pays for itself where many programs run it often and the circuit needs little.

## generalisation (about 110 words)

1. The free kinds are room for instructions not yet thought of.
2. A new instruction takes a free kind, so every old word keeps its meaning. Old programs run
   unchanged on the new machine.
3. A word the machine refuses today stops the program with cause `21`. If unused words did
   something today, a later instruction could not take them without changing what old programs
   do.

## countLoopLead (one sentence)

Count the instructions the loop runs.

## c2Task (about 90 words)

1. The loop that works out 7 × n runs 4 instructions before the loop, 3 each time round, and 2
   after it: the store and the stop.
2. How many instructions does it run, the stop among them, for 7 × 9? And for 7 × 50?
3. There are 2 tests, one for each answer.

## c2Hints (five, in this order)

1. The idea: count the instructions run once, and the instructions run each time round.
2. A common mistake: counting the instructions written, 9, not the instructions run.
3. A smaller example: 7 × 5 runs 4 + 15 + 2, which is 21.
4. Part of the answer: 7 × 9 runs 4 + 27 + 2.
5. The whole answer: 33 and 156.

## reflection (about 80 words)

1. A free kind can hold a new instruction.
2. End on the questions: which one would you add? How would you show it is worth what it costs the
   circuit? The next lesson designs one, justifies it with a program it shortens, and builds it into
   your copy of the machine.

## modelVsReality (about 70 words)

1. Real instruction sets grow over many years.
2. A maker adds new instructions in codes the older machines refused, so old programs keep
   running.
3. A program that uses a new instruction needs a machine that has it, as a program using kind 9
   needs your copy here.
