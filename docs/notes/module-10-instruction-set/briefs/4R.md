## question (about 80 words)

1. Module 8's lesson 3 ran a program with no stop into the ROM's zeros. Module 9's lesson 2
   mapped the kinds and jobs the decoder refuses, and why.
2. This lesson asks what is left: why is an instruction of zeros refused on purpose? What does the
   machine do with data placed after a program? Why refuse unused codes at all, and how much room
   do they leave? What would each instruction the machine leaves out cost, and save?

## p1Explain (about 90 words)

1. At `00C`, with cause `21`, after one more instruction.
2. The word's low 32 bits, at `008`, are `12345678`: kind 1, job 2, so the machine runs it as
   R5 ← R3 + R4. The next 32 bits, at `00C`, are the word's top half, `00000000`: kind 0, refused.
3. The display shows 66, and 3 instructions ran.
4. Other data halts sooner: 5000 puts `00001388` at `008`, kind 0; -250 puts `FFFFFF06`, kind F.
   Both halt at `008`.

## multiplyLead (about 70 words; the facts of the current text)

1. The first program adds 7 into R3 five times, in a loop. R2 counts down from 5, and the branch
   goes back while R2 differs from R0, which holds 0: the machine has no comparison with zero, so
   the program keeps 0 in a register.
2. The second doubles 7 twice and adds 7 once: 7 + 7 is 14, 14 + 14 is 28, 28 + 7 is 35. It works
   only for a factor known when the program is written.
3. Press "Run the programs".

## multiplyAfter (about 50 words)

1. Both programs display 35.
2. The loop has 9 instructions and runs 21: 3 each time round. For 7 × n it runs 4 + 3n + 2, the
   stop among them.
3. The doubling has 6 instructions and runs 6.

## construction (about 80 words)

1. A code the machine refuses today is room for an instruction later. A later instruction can take
   any refused code except the instruction of zeros, which must stay refused to halt a program that
   runs off its end.
2. A code an instruction has today is taken: an old program may use it, and giving it a new
   meaning would change what that program does.
3. On the course's machine, kind 9 is free. In your copy, the call through a register took it.

## explanation (a sentence, a table, a sentence; about 230 words)

1. Every instruction the machine leaves out would cost the circuit something and save programs
   something. Each needs a decoder column and a place in the checks, as every instruction does;
   the table gives what more it needs.
2. The table, three columns (Left out | What the circuit would need besides | What a program does
   without it), five rows:
   - Multiplication | a multiplier beside the ALU: two 64-bit words multiplied by adding up to 64
     shifted copies takes 63 adders of 64 bits, where the ALU has one; and a new source for
     register Y's word, with a control signal to choose it | adds in a loop, 3 instructions run
     each time round
   - A left shift by any number of places | a shifter beside the ALU: 6 layers of 64 two-way
     selectors, one layer for each bit of the number of places; and a new source for register Y's
     word, with a control signal | adds a number to itself, one instruction for each place
   - A call through a register | nothing more: register Y already takes PC + 4 for a call (Module
     9's lesson 5) | sets the return address with one constant job and jumps through the
     register: one more instruction run, and 4 more bytes of ROM, for each call
   - A comparison with zero, `if RA < 0` or `if RA >= 0` | a 0 on the ALU's B; AZERO's 0 on A
     gives 0 - RB, which compares RB with 0 the other way round | keeps 0 in a register: one
     instruction, once
   - A wider constant | a second layout, with selectors (lesson 2) | a word in the ROM and one
     load, or sums of constants (lesson 3)
3. Lesson 5 designs one more: set if less, which writes 1 to a register when one register is less
   than another, and 0 when it is not.

## generalisation (about 80 words)

1. The machine refuses every code it does not define. If an unused code did something today, a
   program could come to rely on it, and a later instruction could not take that code without
   changing what the program does.
2. Refused codes stay free. A new instruction takes one, every old instruction keeps its meaning,
   and old programs run unchanged on the new machine.
3. A program that uses the new instruction needs the new machine: on the course's machine, your
   copy's kind 9 halts with cause `21`.

## c2Task (about 130 words)

1. Your copy runs this program, which shows room A's reading, then room B's, each by a routine
   called through R4. Give the listing as a code block:

```
R4 <= showA
call R4, R15
R4 <= showB
call R4, R15
stop
showA: R2 <= word[sensorA]
word[display] <= R2

showB: R3 <= word[sensorB]

```

2. The course's machine has no call through a register. There, each call becomes two
   instructions: a constant job that puts the return address in R15, and a jump through R4.
3. How many instructions does each run, the stop among them: the program above on your copy, and
   the same program without the call through a register on the course's machine?
4. There are 2 tests, one for each count.

## c2Hints (five)

1. The idea: follow the run, instruction by instruction, through each routine and back.
2. A common mistake: counting the instructions written, not those run.
3. A smaller example: one call, to a routine of three instructions, then the stop: 1 + 1 + 3 + 1
   is 6 with the call through a register.
4. Part of the answer: without the call through a register, each call runs one instruction more.
5. The whole answer: 11 with the call, 13 without.

## modelVsReality (about 70 words)

1. The course's ROM holds 0s after a program, so a program that runs off its end halts at once.
2. A real flash memory, erased and not written, reads all 1s. On the course's machine `FFFFFFFF` is kind F,
   refused as well; a real machine must refuse whatever its unwritten memory reads.
