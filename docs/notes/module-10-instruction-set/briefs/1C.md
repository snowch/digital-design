# Brief 1C: lesson `instruction-set` (Module 10, lesson 1), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. This part introduces two
terms, each in **bold** once, with its plain meaning first: **instruction set** and
**microarchitecture**. After that, use them plainly. No other Module 10 term.

Keys to write: `explanation`, `generalisation`, `writeShortJobsLead`, `c2Task`, `c2Hints.1` to
`c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 160 words)

1. The list of instructions a machine runs, each with its word's layout and what it does to the
   parts a program can see, is the machine's **instruction set**. The parts a program can see are
   R0 to R15, the PC, the memory and the devices.
2. Every machine that runs the course's programs must agree on those parts after every
   instruction.
3. The agreement says nothing about the edges inside an instruction, and nothing about the parts
   no instruction names.
4. A circuit that keeps the agreement, and how it does it, is a **microarchitecture**: one edge an
   instruction or several, one memory port or two, held words or none.
5. Module 8's machine and Module 9's machine are two microarchitectures of one instruction set.
6. So a fault in a part only the circuit knows can leave the agreement whole: HOLDR stuck at 1 did.
   A fault in the PC's enable breaks it.

## generalisation (about 130 words)

1. A third circuit could take fewer edges for some kinds.
2. In Module 9's machine a register job takes 4 edges. At ALU, HR takes the ALU's result; at
   WRITE, register Y takes HR.
3. The ALU's result is ready at the ALU edge. So register Y could take it there, and the job would
   end at that edge, in 3 edges.
4. Every program would run to the same result. The instruction set would not change.
5. Programs written for one microarchitecture run on another. A circuit's makers can make it
   faster without asking anyone to change a program.
6. The challenge asks you to write that circuit.

## writeShortJobsLead (above the challenge; one sentence)

Change Module 9's machine so its register and constant jobs take 3 edges.

## c2Task (about 170 words, a list allowed)

1. The text is Module 9's whole machine, the course's, without the call through a register: the
   module `machine`, the controller and the decoder. It uses the course's modules for the
   register file, the ALU, the condition, the memory and the stop logic.
2. Make the register jobs and constant jobs write register Y at the ALU edge, and end there:
   FETCH, READ, ALU, 3 edges. Every other kind keeps its edges.
3. Three lines change:
   - in the controller's next-state logic, the arm for ALU: a job no longer goes to WRITE;
   - the controller's WREG: also 1 at ALU, for an instruction that writes register Y and does not
     use the memory;
   - in the module `machine`, the word register Y takes: the ALU's result, RESULT, where it was HR.
4. The memory holds the margin program.
5. The tests reset the machine, then check the state and the PC after every edge of every
   instruction, then HALT and the display, 66, at the stop. There are 16 tests.
6. The start fails 13 of them. The first failure is "000, edge 3 (ALU): FETCH after it, PC 004".

## c2Hints (five, in this order)

1. The idea: a job's result is ready at the ALU edge. Write it there, and let that edge end the
   instruction.
2. A common mistake: changing only the next-state logic. The jobs then take 3 edges but write
   nothing, so the display does not show 66.
3. A smaller example, the arm for ALU in the next-state logic:
   `ALU: begin if (MEM) next = MEMORY; else next = FETCH; end`
4. Part of the answer, WREG, with `~MEM` so a load's ALU edge writes nothing:
   `assign WREG = ((state == WRITE) | ((state == ALU) & ~MEM)) & WRITEY & GO;`
5. The whole answer: the arm in hint 3, WREG in hint 4, and in the module `machine` the line
   `YIN = HR;` becomes `YIN = RESULT;`.

## reflection (about 90 words)

1. The instruction set is the agreement. The microarchitecture is how one circuit keeps it.
2. You wrote a third circuit, and every program ran to the same result.
3. The agreement covers what each instruction does. It also covers how each instruction's word is
   laid out: K, J, A, B, Y and three digits of constant, each field in the same place.
4. End on the question: why that layout, of whole hexadecimal digits? What does it cost?

## modelVsReality (about 80 words)

1. The simulator compares the two machines after every instruction, against a model that runs one
   instruction at a time.
2. Makers of real machines test a new circuit the same way: against such a model, on many
   programs.
3. A real maker may sell a small, slow circuit and a large, fast one that run the same programs.
4. How long an instruction takes is not part of the agreement, on the course's machines or on
   real ones.
