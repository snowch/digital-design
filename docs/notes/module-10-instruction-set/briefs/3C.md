# Brief 3C: lesson `immediates` (Module 10, lesson 3), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. "Instruction set",
"microarchitecture" and "opcode" are allowed. This part introduces **immediate**, in **bold** once,
with its plain meaning first.

Keys to write: `explanation`, `generalisation`, `writeGreaterLead`, `c2Task`, `c2Hints.1` to
`c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 150 words)

1. A number kept inside the instruction itself, there as soon as the instruction is read, is what
   books call an **immediate**. The course's immediate is the constant: 12 bits, read signed,
   widened to 64.
2. Three things fit in it:
   - every address of the 2 KB memory;
   - every branch target in the ROM;
   - the small numbers jobs use most.
3. The branch conditions give less and not less, each read signed or unsigned. With the two
   registers in order or swapped, they give all four comparisons: less, not less, greater, not
   greater.
4. So the machine needs no job for "greater than": a program names the registers the other way
   round.

## generalisation (about 110 words)

1. A number too wide for the constant can be kept as a word in the ROM and read by one absolute
   load. It can be any 64-bit number.
2. Or it can be built from constant jobs, each adding at most 2047.
3. A number used once and not much wider than the constant can be summed. A larger number, or one
   used in many places, is better kept as a word.
4. An instruction set's constant is a balance between the instruction's width and what programs
   need most often. The course's 12 bits hold every address.

## writeGreaterLead (one sentence)

Write "greater than" from the ALU's subtraction.

## c2Task (about 140 words, a list allowed)

1. Write the module `greater`. Inputs A and B, 64 bits each; output GT, 1 when A > B, read signed.
2. Use the course's module `alu`, Module 7's ALU at 64 bits: A, B, OP2, OP1 and OP0 in; Y, ZERO,
   MINUS, COUT and OVER out. You need not connect every output.
3. The start uses the ALU to subtract B from A, and sets GT to MINUS XOR OVER: that is A < B, read
   signed. Change it so GT is A > B.
4. You may use `module`, ports, `logic`, multi-bit signals, `assign`, `~`, `&`, `|`, `^`, and one
   module inside another.
5. There are 10 tests: pairs of A and B among them equal words, the largest and the smallest signed
   numbers, and -1. The start fails 8. The first failure is "A 5, B -3".

## c2Hints (five, in this order)

1. The idea: A > B is B < A.
2. A common mistake: turning the start's GT over. NOT (A < B) is A >= B, which is 1 when A equals
   B.
3. A smaller example: the ALU subtracts its B from its A when OP2, OP1 and OP0 are 0, 1 and 1.
4. Part of the answer: connect the ALU's A input to B, and its B input to A: `.A(B), .B(A)`.
5. The whole answer, as a code block:

```
alu a1 (.A(B), .B(A), .OP2(1'b0), .OP1(1'b1), .OP0(1'b1), .MINUS(M), .OVER(V));
assign GT = M ^ V;
```

## reflection (about 80 words)

1. Twelve bits say every address, reach every branch target in the ROM, and hold the small numbers
   jobs use. The swap gives every comparison.
2. Kinds 0 and 9 to F say nothing.
3. End on the questions: what does the machine do with a word it has no instruction for? What
   else does it leave out, and what would each cost to add?

## modelVsReality (about 70 words)

1. The figures run every program on the reference, one instruction at a time.
2. Many real machines have wider constants, and memories far larger than 2 KB. On those, not every
   address fits in one instruction, and a program builds an address in more than one.
