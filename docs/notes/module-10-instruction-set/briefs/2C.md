# Brief 2C: lesson `encoding` (Module 10, lesson 2), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. "Instruction set" and
"microarchitecture" are allowed. This part introduces **opcode**, in **bold** once, with its plain
meaning first. "Immediate" must not appear.

Keys to write: `explanation`, `generalisation`, `writeYdigitLead`, `c2Task`, `c2Hints.1` to
`c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 170 words)

1. K and J together say what an instruction does: its kind and its job. Books call the bits that
   choose what an instruction does its **opcode**. In the course's layout the opcode is digits 7
   and 6.
2. Of the 256 pairs of K and J, 37 are instructions whatever the constant. Two more, kind 8's jobs
   2 and 3, are instructions only when the constant is 0 to 4.
3. The packed layout gives longer constants: 16 bits for a constant job, a load, a store and a
   branch; 20 bits for a call and a jump.
4. It pays with selectors. Y sits in digit 3, 4 or 5 by kind, so the register file's write
   address needs a selector chosen by K. The constant is 12, 16 or 20 bits, so the widening needs
   one too.
5. On the course's machine the longer branch buys nothing. The ROM holds 256 instructions, and a
   12-bit constant already reaches 2047 instructions forward. Every address fits in 12 bits.
6. Only the jobs' numbers would gain.

## generalisation (about 110 words)

1. Every instruction set chooses an encoding: how each instruction becomes bits.
2. One layout keeps the decoder and the register file simple, and a person can read a word.
3. Several layouts give longer constants, and pay with selectors and with words that are harder
   to read.
4. The course's machine chose one layout of whole digits, for people to read.
5. The digits left unused are not all waste. Kinds 9 to F are free. A new instruction takes a free
   kind, as the call through a register took kind 9 in your copy.

## writeYdigitLead (one sentence)

Write the selector the packed layout needs in front of the register file's write address.

## c2Task (about 130 words, a list allowed)

1. Write the module `ydigit`. Input IR, 32 bits; output WA, 4 bits: the register file's write
   address for a word in the packed layout.
   - WA is digit 4, `IR[19:16]`, for kinds 2 and 3.
   - WA is digit 5, `IR[23:20]`, for kind 6.
   - WA is digit 3, `IR[15:12]`, for every other kind.
2. The start is the course's layout: `assign WA = IR[15:12];`.
3. You may use `module`, ports, `logic`, multi-bit signals, `assign`, selects, `always_comb` and
   `case`.
4. There are 11 tests, each a word in the packed layout, named by its digits. The start fails 6.
   The first failure is `22120064`.

## c2Hints (five, in this order)

1. The idea: WA is a selector, and the kind, `IR[31:28]`, chooses which digit it passes.
2. A common mistake: forgetting kind 3. A load writes register Y too, and leaves B unused, so its
   Y moves as a constant job's does.
3. A smaller example: inside `always_comb`, `case (IR[31:28])` with the arm
   `4'h6: WA = IR[23:20];`.
4. Part of the answer: `4'h2: WA = IR[19:16];`, `4'h3: WA = IR[19:16];` and
   `default: WA = IR[15:12];`.
5. The whole answer, as a code block:

```
always_comb
  case (IR[31:28])
    4'h2: WA = IR[19:16];
    4'h3: WA = IR[19:16];
    4'h6: WA = IR[23:20];
    default: WA = IR[15:12];
  endcase
```

## reflection (about 70 words)

1. The course's layout keeps every field in place, and pays with a 12-bit constant.
2. End on the questions: what can one instruction say in 12 bits? How far can a branch reach? What
   does a program do with a number too wide for the constant?

## modelVsReality (about 70 words)

1. The course's machine has one layout of whole digits, for people to read.
2. Real machines cut their words by bits, not digits, and many have several layouts.
3. The figures read every word with the same split of its fields that the course's machine
   uses.
