# Brief 6X: what a failed answer says (decision A)

Read `00-module.md` first. When a learner's answer to a choice or a worked-out number is wrong,
the book no longer shows the right answer. It shows one sentence instead, under the test's name
(the test's name already says which part, code or count it is). Each sentence says which rule or
fact the wrong answer misses. It must never name the right option or the right value. A slot
`{actual}` holds the learner's own answer, in lower case when it is an option's words; use it only
where the key says. One sentence each, with a full stop. No em dashes. Backticks round hexadecimal
values and addresses.

Return each key as `key: text`.

## Lesson 1, sorting the parts (one sentence for all nine)

- `partSeen`: ask whether a program can see this part, through a field that names it, an address
  a load or store reaches, or the PC.

## Lesson 3, the reach

- `reachLargest`: the constant is 12 bits read signed; `{actual}` is not the largest number it
  holds.
- `reachBack`: a branch's constant is (T - P) / 4, the target's address less the branch's, divided
  by 4, written as 12 bits read signed; `{actual}` is not that for this branch.
- `reachFurthest`: a branch at `000` reaches `000` + 4 × c, with c no larger than the largest
  constant; `{actual}` is not that address.

## Lesson 4, the codes and the calls

- `codeFate`: read K, then J: is the code an instruction on the course's machine today, and is it
  the instruction of zeros, which must stay refused?
- `countWith`: count each instruction the run makes, through each routine and back, the stop among
  them; `{actual}` is not that count.
- `countWithout`: without the call through a register, each call runs two instructions, a constant
  job and a jump through R4; `{actual}` is not that count.

## Lesson 5, the design

- `designKind`: ask whether the code is free in your copy of the machine.
- `designField`: ask whether the field keeps the place every instruction gives the register it
  writes.
- `designCondition`: ask whether the condition comes from a field that keeps one meaning in every
  kind that uses it.
- `designProgram`: ask which program set if shortens, counted in instructions run.
- `designCost`: ask what the circuit must gain that it does not already have.
