# Brief 3B: lesson `immediates` (Module 10, lesson 3), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. "Instruction set",
"microarchitecture" and "opcode" are allowed. "Immediate" must not appear in these keys.

Keys to write: `investigation`, `comparisonsLead`, `comparisonsAfter`, `wideLead`, `wideAfter`,
`construction`, `workReachLead`, `c1Task`, `c1Hints.1` to `c1Hints.5`, `equalTrapLead`,
`equalTrapAfter`.

## investigation (one or two sentences, above two figures)

The first figure gives every comparison for four pairs of words. The second puts a number too
wide for the constant into a register, two ways.

## comparisonsLead (above the first figure; about 80 words)

1. Choose a pair of words for R1 and R2: 5 and -3; -3 and 5; 5 and 5; the largest signed number,
   9223372036854775807, and -1.
2. For each comparison, read signed and read unsigned, the table gives the branch that says it and
   whether the machine takes that branch.
3. A marked row names its registers swapped.

## comparisonsAfter (below the first figure; about 100 words)

1. In every row, for every pair, the branch is taken exactly when the comparison holds.
2. "Greater than" is "less than" with the registers swapped. "Not greater", R1 <= R2, is "not
   less" with the registers swapped.
3. The last pair: R1 - R2 overflows, so MINUS is 1 and OVER is 1. MINUS XOR OVER is 0 and still
   right: read signed, R1 > R2.
4. Read unsigned, -1 is the largest word of all, so R1 > R2 is false.

## wideLead (above the second figure; about 90 words)

1. 5000 does not fit in the constant.
2. Two programs put 5000 into R1 and onto the display.
   - The first adds constants: R1 ← 2047, then R1 ← R1 + 2047, then R1 ← R1 + 906.
   - The second keeps 5000 as a word of data in the ROM, after the program, at an address the
     constant holds. One absolute load reads it into R1.
3. Press "Run the programs".

## wideAfter (below the second figure, shown once the programs have run; about 100 words)

1. Both put 5000 into R1 and onto the display.
2. The sums: 5 instructions written and run, 20 bytes of ROM.
3. The word in the ROM: 3 instructions written and run, 24 bytes of ROM. That is three
   instructions, 4 bytes left empty so the word starts at a multiple of 8, and the word's 8 bytes.
4. A word in the ROM holds any 64-bit number, for one load. Sums of constants need more
   instructions as the number grows.

## construction (about 100 words)

1. A branch at address P to a target T has the constant (T - P) / 4, written as three digits,
   read signed.
2. An example from the colder-room program: the branch at `008` goes to `010`. (`010` - `008`) / 4
   is 2, written `002`.
3. A branch back from `010` to `008` would have -2, written `FFE`.
4. The largest number a constant job puts into a register in one instruction is the constant's
   largest: R ← c, the job copy B, with c at most 2047.

## workReachLead (one sentence)

Work each number out by hand, then run the tests.

## c1Task (about 90 words, a list allowed)

1. Give three answers:
   - the largest number one constant job can put into a register, in decimal;
   - the constant of a branch at `01C` whose target is `008`, as three hexadecimal digits;
   - the highest address a branch at `000` can name, in hexadecimal.
2. There are 3 tests, one for each answer.

## c1Hints (five, in this order)

1. The idea: the constant is 12 bits, read signed. A branch's target is PC + 4c.
2. A common mistake: counting bytes for a branch. The constant counts instructions, so divide the
   distance by 4.
3. A smaller example: a branch at `008` to `010` has (`010` - `008`) / 4, which is 2: `002`.
4. Part of the answer: (`008` - `01C`) / 4 is -5, and -5 in 12 bits is `FFB`.
5. The whole answer: 2047, `FFB`, and `1FFC`, which is `000` + 4 × 2047. The ROM ends at `3FF`, so
   a fetch at `1FFC` would stop the machine with cause `11`.

## equalTrapLead (above the failure figure; about 120 words)

1. The program counts how many rooms are warmer than the limit, -200, and shows the count.
2. Room A reads -200 and room B reads -250.
3. A room is warmer when the limit is less than its reading: R1 < R2 for room A.
4. The program skips a room's count when the room is not warmer: `if R1 >= R2 signed`, the limit
   not less than the reading.
5. A second program writes the skip as "colder": `if R2 < R1 signed`.
6. Before you run them, say what each displays. Then press "Run the programs".

## equalTrapAfter (below the figure, shown once the programs have run; about 80 words)

1. The first displays 0: neither room is warmer than -200.
2. The second displays 1. It counts room A, whose reading equals the limit.
3. "Not warmer" is "not greater": the reading <= the limit. The machine says it as "not less" with
   the registers swapped, `if R1 >= R2`.
4. "Colder", `if R2 < R1`, skips only a reading strictly less than the limit, so a reading equal
   to the limit is counted.
