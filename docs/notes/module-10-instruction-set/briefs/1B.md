# Brief 1B: lesson `instruction-set` (Module 10, lesson 1), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**instruction set** and **microarchitecture**, but only in the explanation, which another brief
writes: neither word may appear in these keys.

Keys to write: `sideBySideLead`, `sideBySideAfter`, `construction`, `sortPartsLead`, `c1Task`,
`c1Hints.1` to `c1Hints.5`, `compareFaultsLead`, `faultHoldr`, `faultPcen`.

## sideBySideLead (above the investigation's figure; about 120 words, a list allowed)

1. The figure runs the colder-room program on both machines from the start.
2. The table "What a program can see" gives the PC, R2, R3 and the display on each machine, and

5. The table "Instructions run" lists each instruction, the edges each machine took, and whether

## sideBySideAfter (below the figure, shown once the program has run to its stop; about 80 words)

1. The program runs 5 instructions, then the stop.
2. Module 8's machine takes 1 edge for each. Module 9's takes 5, 5, 3, 4 and 4: 21 edges. Then it
   takes 1 more edge to fetch the stop, and halts.
3. After every instruction, the machines agree on the PC, R2, R3 and the display. The figure also
   checks every other register, the RAM and the devices: they agree too.
4. Both displays show -250.
5. Between instructions, Module 9's machine keeps words in IR, HA, HB, HR and HM, and Module 8's
   machine has no parts for them.

## construction (about 100 words)

1. The instructions a program runs name some parts of the machine and not others.
2. A register job names three registers. A load names a register and an address. A store writes
   the memory or a device. A branch reads two registers and may move the PC.
3. No field can say HR, HA or the IR, so no instruction reads or writes them.
4. So every machine that runs the same programs must agree, after every instruction, on the parts
   the instructions name. What it does with the other parts is its own choice.

## sortPartsLead (above the challenge; one sentence)

Sort each part: one every machine must agree on, or one a circuit keeps of its own.

## c1Task (about 90 words, a list allowed)

1. For each of nine parts, choose "Every machine agrees on it" if an instruction can read it or
   change it, or "One circuit's own" if none can.
2. The parts: R7, the PC, the IR, HR, the controller's state, the word at `400` (in the RAM), the
   display, HA, and the timer's count.
3. There are 9 tests, one for each part. A test names the part and what you chose.

## c1Hints (five, in this order)

1. The idea: ask whether any instruction can read or change the part, through a field, an address
   or the PC.
2. A common mistake: counting the IR as a part every machine agrees on because Module 8's machine
   has an IR too. In Module 8's machine IR is a bus, the ROM's output at the PC, not a register.
   No instruction names it.
3. A smaller example: R7. A register job can name R7 as A, B or Y, so every machine agrees on it.
   HR: no field names it, so it is one circuit's own.
4. Part of the answer: branches, calls and jumps move the PC; loads and stores reach the word at
   `400` and the display. The timer is a device at `7E8` that loads and stores reach, and it
   counts instructions, not edges.
5. The whole answer: every machine agrees on R7, the PC, the word at `400`, the display and the
   timer's count. The IR, HR, the controller's state and HA are one circuit's own.

## compareFaultsLead (above the failure figure; about 110 words, a list allowed)

1. The figure runs the colder-room program on both machines, with a fault you choose in Module
   9's machine.
   - "HOLDR stuck at 1": HR takes the ALU's result at every edge, not only at ALU.
   - "PCEN stuck at 1": the PC takes its next value at every edge, so every edge ends an
     instruction.
2. Choose a fault and press "Run until it stops".
3. Before you press, say for each fault whether the two machines will still agree after every
   instruction.

## faultHoldr (shown once that fault has run; about 80 words)

Start with the fault's name in bold: **HOLDR stuck at 1**.

1. The machines agree after every instruction. Both displays show -250.
2. HR takes a word at every edge. After the ALU edge it takes the same result again, because HA,
   HB and the IR do not change until the next fetch. At FETCH and READ it takes words that no
   later edge reads.
3. The course's tests ran Module 8's 37 programs on Module 9's machine with this fault: every
   program agrees with the model after every instruction.

## faultPcen (shown once that fault has run; about 90 words)

Start with the fault's name in bold: **PCEN stuck at 1**.

1. The machines differ after the first edge, on R2.
2. The controller still takes the load's 5 edges, FETCH to WRITE, but the PC moves on at every
   one of them. Each of those edges ends an instruction, so Module 8's machine runs one
   instruction for each.
3. Module 9's machine writes R2, -184, at the load's WRITE edge. By then its PC is at `014`, so it
   fetches the stop next and skips the four instructions between, at `004` to `010`.
4. R3 stays X on Module 9's machine. Its display shows 0, where Module 8's shows -250.
5. Module 8's machine halts at the stop, at `014`. Module 9's PC has moved on to `018` when its
   machine halts.
6. With this fault, every one of Module 8's 37 programs differs.
