# Brief 8S: the words inside Module 11's figures

Read `00-module.md` (the shared fact sheet) first; it applies here. These words appear inside
Module 11's figures on every Module 11 page, from lesson 1 on. Allowed terms: **assembly**,
**assembler**, **debugger** only. Never "breakpoint", "stack", "function" or any later term,
except where a key below says the words appear only from a later lesson.

Write plain text, no Markdown, no backticks. Words in braces, such as `{line}`, are slots the
figure fills: keep each slot exactly as written, and use no other braces. Buttons and headings
have no full stop; a sentence has one. Keep every text short: they sit in a figure on a phone.

## The program and the assembler

- `programLabel`: the heading over the box where the program's text is written.
- `restore`: a button that puts back the program the lesson gave.
- `assembled`: a sentence after the assembler accepts the program: it made {n} instructions, and
  the program and its data take {bytes} bytes of the ROM.
- `refusedTitle`: a sentence: the assembler refuses {n} lines (the list follows).
- `refusedLine`: one refused line: "Line {line}: {sentence}".
- The assembler's refusals, one sentence each, naming what to change. Each is shown after
  "Line 3:". Facts for each:
  - `refusals.notNumber`: {text} should be a number and is not one.
  - `refusals.notRegister`: {text} is not a register; the registers are R0 to R15.
  - `refusals.constantRange`: {value} does not fit in an instruction's constant, which holds
    -2048 to 2047. A larger number can be kept as a word of data and loaded.
  - `refusals.notWhole`: {name} is not a whole number of instructions away (it names an address
    that is not a multiple of 4 from the branch).
  - `refusals.tooFar`: {name} is too far away for a branch's constant, which counts -2048 to 2047
    instructions.
  - `refusals.noGreater`: the language has no `>`; swap the two registers and write `<`.
  - `refusals.signedOrUnsigned`: after `<` or `>=`, write signed or unsigned, to say how to read
    the two words.
  - `refusals.noCallThroughRegister`: the course's machine has no call through a register (lesson
    9.5's copy had one).
  - `refusals.noSetIf`: the course's machine has no set if (lesson 10.5's copy had one).
  - `refusals.unreadable`: the assembler cannot read the line as any instruction. Each line is one
    instruction, written as its transfer, such as R3 <= R1 + R2.
  - `refusals.romFull`: the program and its data need {bytes} bytes, and the ROM holds {rom}.
  - `refusals.unknownName`: no line of the program is named {name}. Check its spelling, or add the
    name before a line with a colon.
  - `refusals.twice`: {name} already names another line; each name names one line.
  - `refusals.dataTarget`: {name} names data, not an instruction, so a branch or a call cannot go
    there.
  - `refusals.wordTooWide`: {text} does not fit in a {size} ({size} is "word" or "byte").
  - `refusals.useArrow`: the transfer's arrow is written <= , not = .
  - `refusals.noMultiply`: the machine has no multiplication, division or shift; add in a loop
    instead.
  - `refusals.twoJobs`: one line does one job: split the work over two lines.
  - `refusals.storeRegister`: a store writes a register's word; put the number in a register
    first.
  - `refusals.compareRegisters`: a branch compares two registers; put the number in a register
    first (to compare with 0, keep 0 in a register).
  - `refusals.callRegister`: a call names the register that keeps the return address, as in
    call above, R15.
  - `refusals.addressForm`: an address is a register plus or minus a number, or a name; it cannot
    add two registers.
  - `refusals.reservedName`: {name} is a word the language uses (a register, a device, or a word
    such as goto), so it cannot name a line.

## The listing

- `listingCaption`: the listing's caption: the program as the assembler made it.
- `address`, `word`, `line`: three column headings: the address, the instruction's word, the line
  of text.
- `data`: written in the word column for a line of data instead of an instruction word: the word
  "data".
- `pauseBefore`: a button's name for a screen reader, on each instruction's row: pause the run
  before the instruction at {address}. (It appears only from lesson 2 on; it may use the word
  "breakpoint" and nothing else from a later lesson: "Breakpoint before {address}" style.)
- `nextMark`: a word for a screen reader beside ▶: the line runs next.
- `namesCaption`: the caption of a second table: the names the program defines and their
  addresses.
- `name`: its column heading.
- `goesTo`: written under a branch or a call in the listing: it goes to the line {name} names, at
  {address}, and its constant is {c}.

## The debugger's buttons and status line

- `step`, `back`, `run`, `runToPause`, `reset`: buttons. Run one instruction; go back one
  instruction; run until the program stops; run until the next breakpoint or the program stops
  (lesson 2 on; may say "breakpoint"); go back to the start.
- `atStart`: the status line before anything has run.
- `ran`: a sentence: {n} instructions have run.
- `next`: a sentence: the next instruction is the one at {address}.
- `paused`: a sentence (lesson 2 on; may say "breakpoint"): the run paused at the breakpoint before
  the instruction at {address}.
- Why a run ended, one sentence each:
  - `stops.stop`: the program stopped: it ran stop, at {address}.
  - `stops.later`: the instruction at {address} is one a later module builds; the machine halts.
  - `stops.cause11`: the machine halted with cause 11: {address} is outside the ROM, so there is
    no instruction there.
  - `stops.cause12`: cause 12: {address} is not a multiple of 4.
  - `stops.cause21`: cause 21: the word at {address} is not an instruction. A run that goes past a
    program's end meets data or 0s.
  - `stops.cause31`: cause 31: the instruction at {address} used an address with no memory.
  - `stops.cause33`: cause 33: the instruction at {address} used a word's address that is not a
    multiple of 8.
  - `stops.cause34`: cause 34: the instruction at {address} stored to the ROM or to a sensor.
  - `stops.cause41`: cause 41: the instruction at {address} is call system, which Module 12 builds.
  - `stops.unknown-address`: the debugger paused before {address}: its address needs {reg}, and
    nothing has set {reg}.
  - `stops.unknown-branch`: the same for a branch: the branch at {address} compares {reg}, which
    nothing has set.
  - `stops.unknown-jump`: the same for a jump at {address}, which goes to {reg}'s address.
  - `stops.cutOff`: the debugger cut the run off after {n} instructions: the program may never
    stop.

## What the debugger shows

- `registersCaption`: heading over R0 to R15 and the PC.
- `pc`: "PC".
- `unknown`: "X".
- `changed`: for a screen reader, after a register's name: the last instruction wrote it.
- `devicesCaption`: heading over the display, the lamps and the sensors: the shop's devices.
- `display`, `lamps`: the display and the lamps, short.
- `lampNames`: ALARM, NIGHT, CLASH (as they are).
- `lampOn`, `lampOff`: on, off.
- `sensorA`, `sensorB`: room A's sensor, room B's sensor.
- `hex`: for a screen reader, before a register's word in hexadecimal: the word "hexadecimal".

## The watch (lesson 2 on)

The watch shows chosen values after every instruction: a register (R3), the PC, or a word in
memory written as a load writes it (word[R1], word[log + 8], word[0x400]).

- `watchCaption`: heading: Watch.
- `watchLabel`: the box's label: a register or a word to watch, such as R1 or word[R1].
- `watchAdd`: the button that adds what is typed.
- `watchRemove`: a button's name for a screen reader: stop watching {name}.
- `watchBad`: a sentence: the debugger cannot read {text} as a register or a word; write R1, PC,
  or word[...] with an address.
- `watchWas`: after a value the last instruction changed: it was {value}.
- `watchNone`: a sentence: nothing is watched yet.

## Memory and the stack

- `memoryValue`: column heading for a word of memory.
- `pointsHere`: beside a word in memory: {names} holds this word's address ({names} is one or more
  registers, such as R1).
- From lesson 4 on (may say "stack" and "frame"):
  - `stackCaption`: heading: the stack.
  - `stackEmpty`: a sentence: nothing is on the stack.
  - `stackUnset`: a sentence: R14 is not set, so there is no stack yet.
  - `frameMain`: the heading of the words the main program pushed: the main program.
  - `frameCall`: the heading of one call's frame: {name}, called from {address}. ({name} is the
    line the call went to.)

## The question in a figure

- `answer`: a sentence after the learner commits: the run gives {answer}.

## The stack's depth over a run (lesson 4 on; may say "stack")

- `depthCaption`: the chart's heading: how many words are on the stack after each instruction.
- `depthAxis`: the short name of the upright axis: words.
- `depthRan`: after a count, at the end of the flat axis: instructions run.
- `depthMost`: a sentence: at its deepest the stack held {n} words.
- `depthCalls`: the short name of the ticks that mark each call: calls.

## A program run on several logs

- `logCol`: the hidden heading of the column of names: what is checked.
- `readingsCol`: "Readings" (before the list of a log's readings).
- `asks`: column heading: what the task asks for.
- `left`: column heading: what the program left.
- `empty`: the word for an empty log or an empty list: none.
- `matches`: a sentence: the program left what the task asks for.
- `differs`: a sentence: the program left something else.
- `runAll`: a button: run the program on every log.
- `limitNote`: after a log's readings, in brackets: (limit {limit}).

## The program editor in a challenge

- `runWith`: the label of a list of the tests' runs, to run your program with one of them.
- `dataAdded`: a sentence before some lines of data: the tests add these lines after your program.
- `startSkeleton`, `startEmpty`: two buttons: start from the outline the lesson gives; start from
  an empty program.

## A failed test

- `checks.display`, `checks.lamps`, `checks.end`, `checks.shown`, `checks.stackWords`,
  `checks.kept`, `checks.returned`, `checks.calls`: the short name of each thing a test checks,
  each to be followed by a value: the display; the lamps; how the run ended; what the display
  showed, in order; how many words were on the stack at its deepest (may say "stack"); registers
  a function did not put back (may say "function"); whether the run came back to R15; how many
  calls returned.
- `end`: heading: how the run ended.
- `notAssembled`: a sentence: the program does not assemble, so no test could run.
- `failedLeft`: a sentence: your program left {left}.
- `checkRegister`: a register's name in that sentence: {name} (keep as the slot alone).
- `checkWord`: the word at {address}.
- `checkValue`: a thing and its value in that sentence: {name} {value}.
- `nothingWritten`: a sentence: there is no program yet.
