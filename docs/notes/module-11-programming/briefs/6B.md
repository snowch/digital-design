# Brief 6B: lesson `debugging` (Module 11, lesson 6), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use every Module 11
term (not in bold). Do not use "bug" or "debug" as words of your own: say "mistake", "find",
"mend".

The lesson's first program is the count of warm readings with `R2 <= R2 - 1` at `008`, as brief 6A
gives it, run on log 1: -190, -181, -175, -170, limit -180, with `log` at `050`.

The second program is lesson 4's: the main program at `000` sets R14, calls `total` and shows R1;
`total` pushes R15 and R10, calls `above` twice, pops them and returns. In this lesson's version
the first line is `R14 <= 0x400` instead of `R14 <= 0x7C0`.

Keys to write: `investigation`, `findLead`, `findAfter`, `construction`, `mendCountLead`,
`c1Task`, `c1Hints` (five), `failureExperiment`, `stackInRomLead`, `stackInRomAfter`.

## investigation (about 30 words)

The figure runs log 1 with a breakpoint on `next`, a watch on R1, R2 and R3, and the log shown with
the word R1 points at.

## findLead (about 50 words, above the figure)

1. Press "Run to a breakpoint" again and again, and say before each press where R1 should point and
   what R2 should hold.
2. Watch the view of the log: which readings does R1 reach?

## findAfter (about 70 words, below the figure; shown from the start)

1. At the four pauses at `next`, R1 holds `050`, `058`, `060` and `068`, and R2 holds 3, 2, 1 and
   0.
2. At the fourth pause R2 is already 0, so the loop ends. R1 points at the last reading, -170, but
   no instruction loads it.
3. The display shows 1, from -175. 28 instructions run, and the program stops at `038`.

## construction (about 20 words)

Mend the count. The tests run it on several logs, the empty log among them.

## mendCountLead (one sentence, above the challenge)

Find the mistake with the debugger, mend it, then run the tests.

## c1Task (about 90 words, a list allowed)

1. The starting text is the lesson's program, which counts the readings warmer than the limit and
   misses one. Mend it so that the display shows how many readings are warmer than the limit.
2. The tests add `count`, `limit` and `log` after your program. There are 6 tests, each a log, all
   with the limit -180:
   - -190, -181, -175, -170
   - -170, -190
   - -190, -170
   - -170
   - an empty log
   - -200, 25, -150, 30
3. Each checks the display and that the program ends at its `stop`.

## c1Hints (five, in this order)

1. The idea: R2 counts the readings left. It must start at the count.
2. A common mistake: deleting the wrong `R2 <= R2 - 1`. The one at `02C`, in the loop, counts each
   reading done; without it R2 never reaches 0, and the loop walks on past the log until the debugger
   pauses on a word nothing has set (corrected after drafting: the brief said the loop never ends).
3. A smaller example: for a log of one reading, the loop must go round once, so R2 must start at 1.
4. Part of the answer: the line at `008` is the mistake.
5. The whole answer: delete the line `R2 <= R2 - 1         // the readings are numbered from 0`.

## failureExperiment (about 50 words)

1. Some mistakes stop the run instead of giving a wrong answer. The figure's program is lesson 4's
   `total`, with its first line changed to `R14 <= 0x400`.
2. `400` is the RAM's first word.

## stackInRomLead (one sentence, directly above the figure)

Predict how the run ends, then press "Run to the end".

## stackInRomAfter (about 80 words, shown once the run has ended)

1. The machine halts with cause `34` at `01C`, after 5 instructions: a store to the ROM.
2. `01C` is `total`'s first push. R14 holds `3F8`: the push took 8 off `400` before it stored, and
   `3F8` is the ROM's last word.
3. The halt is at `01C`, but the mistake is at `000`. The stack must start past the RAM's last
   word, at `7C0`, because it grows down.
4. Read the cause, then ask which earlier line set the value the halting instruction used.
