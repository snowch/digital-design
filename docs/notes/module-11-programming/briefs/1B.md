# Brief 1B: lesson `assembly` (Module 11, lesson 1), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**assembly**, **assembler** and **debugger**; all three may appear in these keys. Set
**debugger** in bold where it is first used, in `investigation`, plain meaning first. No later term
(breakpoint, function, argument, calling convention, stack, frame, recursion) may appear.

Keys to write: `investigation`, `debuggerLead`, `debuggerAfter`, `construction`, `warmerLead`,
`c1Task`, `c1Hints` (five), `mistakesLead`, `mistakesAfter`.

## investigation (about 90 words, above a figure)

1. A **debugger** is a program that runs another program one instruction at a time and shows what
   each instruction changed.
2. The course's debugger runs the instruction set: one instruction at a time, as the model both
   of your circuits were tested against does (lesson 10.1). It shows what a program can see and
   nothing of either circuit: no edges, no control signals.
3. The figure is the debugger, on the program from the prediction, with room A's sensor reading
   -170.

## debuggerLead (about 70 words, directly above the figure; a short list allowed)

1. The listing marks the line about to run with ▶.
2. Under it: R0 to R15, the PC, and the shop: the display, the lamps and the two sensors. A
   register nothing has set shows X.
3. The buttons: "Step" runs one instruction; "Step back" goes back one; "Run to the end" runs until
   the program stops; "Reset" goes back to the start.
4. The line under the buttons says what comes next, or why the run ended.
5. Press "Step" until the program stops, and watch which register each instruction writes.

## debuggerAfter (about 50 words, below the figure; shown from the start)

1. With room A at -170, the branch at `008` is not taken, since -170 is not less than -180.
2. ALARM turns on at `010`, the display shows -170 at `014`, and the program stops at `018`.
3. 7 instructions run.
4. With a reading below -180, the branch goes to `fine` and only 5 run.

## construction (about 40 words)

1. Now you write a program as text. The assembler turns it into words as you type, or lists the
   lines it refuses.
2. Under your text, the debugger runs it with the readings of any of the tests.

## warmerLead (one sentence, above the challenge)

Write the program, step through it in the debugger, then run the tests.

## c1Task (about 90 words, a short list allowed)

1. Write a program that shows the warmer room's reading on the display: the higher of room A's and
   room B's readings, read signed. Then it stops.
2. The starting text reads both sensors and shows room A's reading.
3. There are 5 tests. Each runs your program with a pair of readings: room A at -184 and room B at
   -250; -250 and -184; -200 and -200; -30 and 15; 20 and -5. Each checks the display and that the
   program ends at its `stop`.
4. A failed test says what your program left on the display and how the run ended.

## c1Hints (five, in this order)

1. The idea: a branch chooses which register goes to the display.
2. A common mistake: writing `unsigned`. Read unsigned, -30 is a larger number than 15, so a
   reading below 0 looks warmer than one above it.
3. A smaller example: the colder-room program shows the lower reading with
   `if R2 < R3 signed goto show`, then `R2 <= R3`.
4. Part of the answer: `if R3 < R2 signed goto show` jumps when room A's reading, in R2, is the
   higher.
5. The whole answer:

```
      R2 <= word[sensorA]
      R3 <= word[sensorB]
      if R3 < R2 signed goto show
      R2 <= R3
show: word[display] <= R2
      stop
```

## mistakesLead (about 70 words, above a figure in which the program can be changed)

1. The figure holds room A's program again, with three mistakes. You can change its text.
2. The assembler refuses three lines, each with its line's number and why: line 3,
   `R3 <= -18000`; line 4, `if R2 < R3 goto fine`; line 7, `word[dispaly] <= R2`.
3. Mend each line. When the assembler refuses no line, the listing and the debugger appear.
4. "Put the program back" brings back the three mistakes.

## mistakesAfter (about 60 words, below the figure; shown from the start)

1. A constant holds -2048 to 2047. The limit is -180 in tenths of a degree, which fits.
2. The assembler checks the form of each line, not what you meant.
3. `if R2 < R3 unsigned goto fine` is an instruction, and the assembler takes it. With readings of
   both signs it chooses wrongly.
4. A program the assembler takes can still be wrong. The debugger is how you find out where.
