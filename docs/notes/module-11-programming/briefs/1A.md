# Brief 1A: lesson `assembly` (Module 11, lesson 1), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**assembly**, **assembler** and **debugger**. In these keys you may use "assembly" and
"assembler"; set each in bold where it is first used, in the motivation, plain meaning first.
"Debugger" must not appear in these keys. No later term (breakpoint, function, argument, calling
convention, stack, frame, recursion) may appear.

Keys to write: `question`, `listingLead`, `motivation`, `prediction`, `p1Question`, `p1Explain`.

## question (about 70 words, above a figure)

1. Lesson 10.5 ended on a question: every program so far was given as words and transfers.
   Writing a longer one word by word is slow, and a wrong digit is easy to make.
2. Each figure since Module 8 also wrote each instruction as a line of text, such as
   `R2 <= word[sensorA]`.
3. End on the question: could you write a program as those lines, and let a tool make the words?

## listingLead (one or two sentences, directly above the opening figure)

1. The figure shows the colder-room program from Module 8: each line of text beside its address
   and the word the machine runs.
2. The table under it lists the one name the program defines, `show`, and its address, `010`.

## motivation (about 140 words, a short list allowed)

1. A program written as lines of text is **assembly**: one line for each instruction, written as
   the transfer it makes.
2. An **assembler** is a program that turns those lines into the words the machine runs.
3. It puts the first instruction at `000` and each next one 4 bytes on.
4. A name followed by a colon names a line's address: `show:` in the colder-room program names
   `010`. A branch can say `goto show`, and the assembler works out the constant that reaches it.
   You never count instructions by hand.
5. The assembler also refuses a line it cannot turn into an instruction, and says why, with the
   line's number.
6. The table it makes is the listing: each line beside its address and its word.

## prediction (above the figure; about 60 words)

1. The figure shows a new program: room A's reading against its limit, -180 (-18.0 degrees).
2. It reads room A's sensor into R2 and puts -180 in R3.
3. If R2 is less than R3, read signed, the branch at `008` goes to `fine`, which shows R2 on the
   display.
4. Otherwise the program turns ALARM on (R4 ← 1, stored to the lamps) and then shows R2.
5. Choose an answer and press "Check my prediction". The words then appear.

## p1Question (one sentence)

What constant does the assembler give the branch at `008`, `if R2 < R3 signed goto fine`?

## p1Explain (about 70 words)

1. The constant is `003`.
2. `fine` is the line at `014`. The branch is at `008`. They are `00C` bytes apart, which is 3
   instructions of 4 bytes.
3. A branch's constant counts instructions from the branch itself, so c = 3.
4. The branch's word is `56230003`: kind 5, job 6 (less, read signed), A is R2, B is R3, and the
   constant `003`.
5. `014` is the address the name stands for; the constant is the distance to it.
