# Brief 3RL: lesson `functions` (Module 11, lesson 3), revised titles, captions and labels

Read `00-module.md` (the shared fact sheet) first; it applies here. Every term up to and
including lesson 3's is allowed (never in bold here).

Short texts, plain text with no Markdown. A title, a heading, an option or a name starts with a
capital letter and has NO full stop. A caption is one short sentence with a full stop that names
what the figure shows, not an instruction to the reader ("The function overBy, called twice, in
the debugger." not "See overBy in the debugger."). An objective starts with a verb and ends with a
full stop. Function names in these short texts have no backticks; write them exactly as given,
and never use one as an ordinary word.

Keys to write:

- `objectives.1` to `objectives.4`: call a function and return from it with R15; pass arguments in
  R1 to R4 and take the result from R1; keep a word through a call in a register the calling
  convention keeps; write a function a test can call on its own.
- `titles.prediction`: what R15 holds when the program stops.
- `titles.investigation`: a function called twice.
- `titles.construction`: an agreement on registers.
- `titles.challenge`: the function outOfRange.
- `challengeTitles.c1`: the larger amount.
- `challengeTitles.c2`: the function outOfRange.
- `captions.twoWays`: the same work, written twice, then written once and called twice.
- `captions.predict`: the program's listing, with a question about R15.
- `captions.callReturn`: the function overBy, called twice, in the debugger.
- `captions.larger`: the larger amount: a main program that calls overBy twice, and its tests.
- `captions.spoiled`: two programs, one whose overBy changes R10.
- `captions.range`: the function outOfRange and its tests.
- `programs.keeps`: its overBy keeps R10. `programs.spoils`: its overBy changes R10.
- `fridgePrefix`: "Fridge at" (a test's name begins with it, then the reading).
