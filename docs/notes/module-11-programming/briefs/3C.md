# Brief 3C: lesson `functions` (Module 11, lesson 3), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler**, **debugger**, **breakpoint**, **function**, **argument** and **calling
convention** (not in bold). No later term (stack, frame, recursion) may appear.

Keys to write: `explanation`, `generalisation`, `aboveLead`, `c2Task`, `c2Hints` (five),
`reflection`, `modelVsReality`.

## explanation (about 130 words)

1. The machine knows nothing of functions. `call above, R15` is kind 6: it writes the address of
   the next instruction into the register its Y digit names, and goes to `above`. R15 is the one
   it names here only because programs agree on it.
2. `goto R15` is a jump to the address a register holds, like any other jump.
3. Nothing in the machine checks that a function puts R10 to R13 back, or that its result is in
   R1. The failure experiment's program broke the agreement, and the machine ran it without a word.
4. The calling convention is an agreement between programs, not a part of the machine. It lets a
   function written by one person be called from a program another person wrote, and lets a test
   call a function on its own.

## generalisation (about 100 words)

1. A function is written once and used from anywhere a call can reach. A mistake in it is mended
   once.
2. A function can be tested alone: give it arguments, call it, and check its result and the
   registers it must keep. The challenge's tests do that.
3. Each use costs a call and a jump back: 2 instructions run. For a short piece used twice, as
   here, the program is hardly shorter. For a longer piece, or one used many times, the saving in
   lines grows.

## aboveLead (one sentence, above the challenge)

Write `above`, test it in the debugger, then run the tests.

## c2Task (about 120 words, a list allowed)

1. The starting text is the lesson's main program. Its `above` returns 0 every time.
2. Write `above`: R1 holds a reading and R2 a limit. Return in R1 how far the reading is above
   the limit, or 0 if it is not above. A reading equal to the limit is not above it.
3. Keep the calling convention: put back any of R10 to R14 that you change, and return with
   `goto R15`.
4. There are 9 tests.
   - Six call `above` alone, with R1 and R2 set: -170 and -180; -190 and -180; -180 and -180; 25
     and -180; -150 and -200; -205 and -200. Each checks R1, that R10 to R14 hold what they held
     before the call, and that the run came back through R15.
   - Three run the whole program with room A and room B at -170 and -190; -185 and -210; 25 and
     -150. Each checks the display, the lamps and that the program ends at its `stop`.

## c2Hints (five, in this order)

1. The idea: compare the reading with the limit, then either subtract or give 0.
2. A common mistake: comparing `unsigned`. A reading of 25 read unsigned is smaller than -180 read
   unsigned, so the function would say it is not above.
3. A smaller example: for a reading of -170 and a limit of -180, the result is -170 - (-180), which
   is 10.
4. Part of the answer: `if R2 < R1 signed goto over` jumps when the limit is less than the reading.
5. The whole answer:

```
above: if R2 < R1 signed goto over
       R1 <= 0
       goto R15
over:  R1 <= R1 - R2
       goto R15
```

## reflection (about 70 words)

1. `above` calls no other function. The office now wants one function that checks both rooms by
   calling `above` twice.
2. Its own call to `above` writes R15, the register that held its own return address.
3. End on the question: what must a function that calls another keep, and where?

## modelVsReality (about 80 words)

1. Every real machine has a calling convention, written down for its programs and its tools, so
   that functions from different authors and tools work together. The course's convention is its
   own and follows none of them.
2. Many real machines have a call that always writes one register. The course's call writes the
   register its Y digit names, so the choice of R15 is the convention's.
