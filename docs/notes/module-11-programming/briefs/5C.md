# Brief 5C: lesson `recursion` (Module 11, lesson 5), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use every term up to
**recursion** (not in bold).

Keys to write: `explanation`, `generalisation`, `depthsLead`, `c2Task`, `c2Hints` (five),
`reflection`, `modelVsReality`.

## explanation (about 130 words, a list allowed)

1. Recursion works because each call has its own frame. At the deepest, five calls of `newest`
   were running at once; the four with a reading each kept its own return address and its own
   reading's address on the stack. Registers
   are shared by every call; the stack is not.
2. Every call but the last case does the same three things: push what it needs after the call, call
   itself on a smaller list, pop and finish.
3. The last case must come, and must call nothing. The list shrinks by one reading each call, so
   the call on the empty list is reached.
4. The reading is shown after the call returns, so the newest is shown first.
5. For a log of n readings, `newest` is called n + 1 times, and the stack holds 2n words at its
   deepest.

## generalisation (about 110 words)

1. A recursive function suits a job whose answer for a list is built from the answer for the rest
   of it: here, the rest newest first, then the first reading.
2. The same job can be done by a loop that walks the log from its end. That loop needs no stack.
   Recursion keeps on the stack what the loop would work out from the count.
3. Each level of recursion costs stack. The course's machine has 120 words of RAM for the stack, so
   `newest` can show at most 60 readings.
4. Every recursive function needs a last case that calls nothing, reached for every argument.

## c2Task (about 70 words)

1. For `newest` on a log of 5 readings, give:
   - how many words the stack holds at its deepest;
   - the address R14 holds then, in hexadecimal;
   - the most readings a log can have for `newest` to show them all on the course's machine.
2. There are 3 tests, one for each answer.

## c2Hints (five, in this order)

1. The idea: each reading's call pushes a frame of 2 words, and the call on the empty list pushes
   nothing.
2. A common mistake: counting a frame for the call on the empty list.
3. A smaller example: for the lesson's log of 4 readings, the stack holds 8 words at its deepest,
   and R14 holds `780`.
4. Part of the answer: 5 readings make 10 words, and 10 words are `050` bytes below `7C0`.
5. The whole answer: 10 words, `770`, and 60 readings.

## reflection (about 70 words)

1. Every program so far did what it was meant to, or failed at once with a clear reason.
2. The office's programs will not always be right. A count can be one short, a push can be
   forgotten, a comparison can read signed readings unsigned.
3. Such a program runs and gives an answer, and the answer is wrong.
4. End on the question: how do you find the mistake in a program that runs and gives a wrong
   answer?

## modelVsReality (about 80 words)

1. On a real machine, a stack that grows too far writes over whatever memory lies below it, often
   with no halt at all, and the program fails later in a way that is hard to trace.
2. The course's machine keeps its program in a ROM, so a stack that grows too far halts at the
   first push into the ROM, with cause `34`. The mistake shows where it happens.
