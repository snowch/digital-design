# Brief 2R: lesson `lists` (Module 11, lesson 2), revised keys

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler** and **debugger** (not in bold). This lesson introduces **breakpoint**: set it in
bold where it is first used, in `investigation`, plain meaning first. "Breakpoint" must not appear
in `logLead`, `prediction`, `p1Question` or `p1Explain`. No later term may appear.

The lesson's program counts the log's readings warmer than -180:

```
000        R1 <= log            // the address of the next reading
004        R2 <= word[count]    // how many readings are left
008        R3 <= 0              // how many were warmer
00C        R4 <= -180           // the limit
010        R0 <= 0
014 next:  if R2 == R0 goto done
018        R5 <= word[R1]
01C        if R4 >= R5 signed goto skip   // not warmer than the limit
020        R3 <= R3 + 1
024 skip:  R1 <= R1 + 8
028        R2 <= R2 - 1
02C        goto next
030 done:  word[display] <= R3
034        stop
038 count: word 6
040 log:   word -184, -190, -176, -181, -172, -188
```

The readings sit at `040`, `048`, `050`, `058`, `060` and `068`.

Keys to write: `logLead`, `prediction`, `p1Question`, `p1Explain`, `investigation`,
`generalisation`.

## logLead (about 80 words, directly above the figure)

1. The log is stored after the program as `word` data: `count: word 6` holds how many readings
   there are, then `log:` and the six readings, oldest first. `count` is at `038` and `log` at
   `040`. Each reading is one word, 8 bytes on from the one before.
2. The figure runs the lesson's program and stops each time it is about to load a reading. It
   shows R1 and the log, with the word R1 holds the address of marked.
3. Press "Next reading" and watch R1 move down the log.

## prediction (about 40 words, above the figure)

1. The figure lists the program.
2. Choose an answer and press "Check my prediction". The listing's words then show.
3. Do not say how many times the loop goes round, or what R1 holds after the last reading.

## p1Question (one sentence)

When the program stops, what address does R1 hold?

## p1Explain (about 80 words, shown once the learner has answered)

1. R1 holds `070`, the address just past the log.
2. R1 starts at `040`. Each time round, after the reading is loaded, `R1 <= R1 + 8` moves it on.
3. The loop goes round six times, once for each reading. After the last reading, at `068`, R1
   moves on once more, to `070`.
4. Then R2 is 0, and `if R2 == R0 goto done` leaves the loop. Nothing reads the word at `070`.
5. `068` is the last reading's address, where R1 was while that reading was loaded.

## investigation (about 90 words)

1. A mark on a line that makes the run pause before that line runs is a **breakpoint**. In the
   figure, the round mark beside each line sets or clears one. One is set on `next`.
2. "Run to a breakpoint" runs until the next instruction is on a line with a breakpoint, or until
   the program stops.
3. A watch shows the values you choose. Where one changed since the run last paused, the watch
   shows what it was before.
4. A view of the log shows its six words, and marks the word whose address a register holds.

## generalisation (about 90 words, a list allowed)

1. Any question about a list fits this shape. Only the body changes: count, find, or compare.
2. One register walks the list by address. Another tracks when to stop. Here the count comes first
   in the log. A list could end with a marker word instead, and the test would look for that word.
3. The body can keep a value from one time round to the next in a register, such as the reading
   before.
4. Readings are signed, so a comparison of two readings says `signed`. A count or an address is
   never below 0: read signed or unsigned, it gives the same comparison.
