## explanation (about 140 words, a list allowed)

1. The words one call of a function pushes are its **frame**. `total`'s frame is two words: its
   return address, at `7B8`, and the word R10 held, at `7B0`. `above` pushes nothing, so it has no
   frame.
2. The debugger's stack view groups the words by frame, naming each function and where it was
   called from. The machine knows nothing of frames: the debugger works them out from the calls
   it has run.
3. The calling convention's last rows:
   - R14 holds the stack's address, the word last pushed. A function leaves R14 as it found it, by
     popping everything it pushed.
   - R10 to R13 are kept: a function that changes one pushes it first and pops it before it
     returns.
   - A function that calls another pushes R15 first, and pops it before `goto R15`.

## depthLead (about 50 words, above a figure)

1. The figure counts the words on the stack after each instruction of the run, from the first to
   the stop.
2. The marks under the line are the three calls: `total`, then `above` twice.
3. The stack holds 2 words at most, while `total` runs, and is empty again at the end.

## generalisation (about 100 words)

1. The last word pushed is the first popped. So a call made inside another call ends first, and
   each frame lies under the frame of the call made after it.
2. Calls can go as deep as the RAM allows. Its 960 bytes from `400` to `7BF` hold 120 words, and
   the stack grows down from `7C0`.
3. A function that calls nothing and changes no kept register, such as `above`, needs no frame.
4. Whatever pushes a word must pop it, on every path through the function.

## addressesLead (one sentence, above the challenge)

Work out each address from the program in this lesson, then run the tests.

## c2Task (about 70 words)

1. In the run of this lesson's program, with `total` and `above`, give four addresses in
   hexadecimal:
   - the address of the word that holds `total`'s return address;
   - the address of the word that holds what R10 held when `total` started;
   - what R14 holds while `above` runs;
   - what R14 holds after `total` returns.
2. There are 4 tests, one for each address.

## c2Hints (five, in this order)

1. The idea: start R14 at `7C0` and take 8 off for each push.
2. A common mistake: writing to `7C0` for the first push. A push takes 8 off R14 before it stores,
   so the first word goes to `7B8`.
3. A smaller example: a function that pushes only R15 keeps its return address at `7B8`, and R14
   is `7B8` while it runs.
4. Part of the answer: `total` pushes R15 first, then R10.
5. The whole answer: `7B8`, `7B0`, `7B0` and `7C0`.

## reflection (about 70 words)

1. Each call of a function has its own frame, so the same function could be running in two calls
   at once, each with its own return address on the stack.
2. The office wants the log shown newest first. A function could show the rest of the log first,
   then its own reading.
3. End on the question: can a function call itself?

## modelVsReality (about 80 words)

1. Real machines keep a stack in memory as this one does, and most give one register the stack's
   address by agreement. Some machines have push and pop instructions; this one uses two ordinary
   instructions each.
2. A real stack can grow until it overwrites other data, with no warning. On the course's machine
   a stack that grows past `400` reaches the ROM, and the store halts the machine with cause `34`.
