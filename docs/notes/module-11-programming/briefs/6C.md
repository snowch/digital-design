# Brief 6C: lesson `debugging` (Module 11, lesson 6), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use every Module 11
term (not in bold). Do not use "bug" or "debug" as words of your own.

Keys to write: `explanation`, `generalisation`, `mendTotalLead`, `c2Task`, `c2Hints` (five),
`reflection`, `modelVsReality`.

## explanation (about 170 words, a list)

How a run ends tells you where to look. The debugger says one of these:

- **The program ran `stop`.** The run finished. Check what it left against what it should.
- **The debugger cut the run off.** A loop never ends, or a return address was lost, as in lesson 4.
- **The debugger paused: a register nothing has set.** A start is missing, such as `R14 <= 0x7C0`,
  or a line names the wrong register.
- **Cause `21`, not an instruction.** The run went past the program's end into data or 0s: a
  missing `stop`, or a branch to the wrong name.
- **Cause `31`, no memory at the address.** An address register went too far: a list walked past
  its end, or more pops than pushes.
- **Cause `33`, a word's address not a multiple of 8.** An address stepped by 4 where a word needs
  8.
- **Cause `34`, a store to the ROM or a sensor.** A stack started in the wrong place, or a store to
  the log, which is in the ROM.

The instruction that halts is rarely the one that is wrong. Find which earlier line set the value
it used.

## generalisation (about 100 words)

1. A mistake hides until a test reaches it. The count one short was right on two logs of five.
2. So test on logs chosen to reach the edges: an empty log; one reading; the reading that decides
   the answer first or last; a reading equal to the limit; readings of both signs.
3. Fix one mistake at a time, and run every test again after each. A mended halt can uncover a
   second mistake behind it.
4. The method does not depend on the program: what each part should leave, a pause before it, and
   the first value that differs.

## mendTotalLead (one sentence, above the challenge)

Use the method to find each mistake in turn, mend it, then run the tests.

## c2Task (about 100 words, a list allowed)

1. The starting text is lesson 4's program with `total` and `above`, with two mistakes in it. It
   should show on the display both rooms' amounts above their limits, added: room A's above -180
   and room B's above -200.
2. Find and mend both mistakes.
3. There are 4 tests, each a pair of readings for room A and room B: -170 and -190; 25 and -210;
   -185 and 30; -185 and -210. Each checks the display and that the program ends at its `stop`.

## c2Hints (five, in this order)

1. The idea: run, read how the run ends, find the line, mend it; then run again for the next
   mistake.
2. A common mistake: stopping when the program stops at its `stop`. The second mistake shows only
   on readings above 0.
3. A smaller example: lesson 4's `total` pushes R15 before R10, and pops R15 after R10.
4. Part of the answer: every run halts with cause `31` at `044`. `total` never pushes R15, so its
   `goto R15` goes back into `total`, and each pop takes R14 another word up, past the RAM and the
   devices, until it reads `7F8`, where there is no memory.
5. The whole answer: add `R14 <= R14 - 8` and `word[R14] <= R15` at the start of `total`, and
   `R15 <= word[R14]` and `R14 <= R14 + 8` after the pop of R10. Then in `above`, change
   `unsigned` to `signed`.

## reflection (about 70 words)

1. You can now write a program as text, walk a log, write functions that keep the calling
   convention, use the stack and recursion, and find a mistake with the debugger.
2. The office wants a report on each day's log, from one program it can rely on.
3. End on the question: can you write a program the shop can use?

## modelVsReality (about 80 words)

1. The course's debugger can step back, because it keeps the states of the model. Most debuggers
   for real machines cannot; some record a run so it can be replayed.
2. On a real machine, a mistake like the stack started at `400` would write over the memory below
   it without a halt, and fail later, far from the line that is wrong. The course's machine halts
   at the first store to the ROM.
