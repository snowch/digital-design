# Brief 3L: lesson `functions` (Module 11, lesson 3), titles, captions and short labels

Read `00-module.md` (the shared fact sheet) first; it applies here. Terms allowed: **assembly**,
**assembler**, **debugger**, **breakpoint**, **function**, **argument**, **calling convention**
(never in bold here). No later term.

Short texts, plain text with no Markdown and no backticks. A title or heading has no full stop. A
caption is one short sentence with a full stop. Option and field labels have no full stop.

Keys to write:

- `title`: the lesson's title, as a question: how can a program use one piece of program from two
  places?
- `objectives.1` to `objectives.4`, each starting with a verb: call a function and return from it
  with R15; pass arguments in R1 to R4 and take the result from R1; say what the calling
  convention lets a function do with each register; write a function a test can call on its own.
- `titles.question` … `titles.reflection`: one heading each, a few words. (question) one check,
  two rooms; (motivation) a call and its return; (prediction) where R15 points; (investigation) a
  function called twice; (construction) an agreement on registers; (failureExperiment) a function
  that spoils its caller; (explanation) what the machine knows; (generalisation) written once,
  tested alone; (challenge) writing above; (reflection) a function that calls another.
- `challengeTitles.c1`: each register's role. `challengeTitles.c2`: the function above.
- `captions.twoWays`: the same work written twice and written once as a function, counted.
- `captions.predict`: predict R15 after the second call, then run the program.
- `captions.callReturn`: the function above, called twice, in the debugger.
- `captions.roles`: choose each register's role and run the tests.
- `captions.spoiled`: two programs, one whose function changes R10.
- `captions.above`: write the function and run the tests.
- `programs.twice`, `programs.once`: written out twice; written once, as a function.
- `programs.keeps`, `programs.spoils`: its function keeps R10; its function changes R10.
- `options.r00C`, `options.r018`, `options.r01C`: three answers, each the address and a few words
  after a colon: 00C: after the first call; 018: the second call; 01C: after the second call.
- `registers.r1`, `registers.r3`, `registers.r7`, `registers.r12`: R1, R3, R7, R12 (as they are).
- `roles.result`, `roles.free`, `roles.kept`: carries the result back; the function may change
  it; the function must put it back.
- `callPrefix`: the word before a test's registers in its name: "Call".
- `roomPrefixA`, `roomPrefixB`: "Room A", "room B" (before a reading in a test's name).
- `details.registerRole`: a sentence a wrong choice adds: the calling convention gives R1 to R4,
  R5 to R9 and R10 to R13 one role each, and R1 carries the result.
- `details.aboveCall`: a sentence a failed call adds: R1 must hold how far the reading in R1 is
  above the limit in R2, or 0, with R10 to R14 as they were and a return through R15.
- `details.twoRooms`: a sentence a failed run adds: the display must show room A's amount above
  -180, and ALARM must be on only when room B is above -200.
