Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler**, **debugger**, **breakpoint**, **function**, **argument**, **calling convention**
and **stack** (not in bold). "Frame" and "recursion" must not appear in these keys.

The new program, as the figures show it (`above` is lesson 3's):

```
000         R14 <= 0x7C0
004         R1 <= word[sensorA]
008         R2 <= word[sensorB]
00C         call total, R15
010         word[display] <= R1
014         stop
018 total:  R14 <= R14 - 8
01C         word[R14] <= R15     // push R15
020         R14 <= R14 - 8
024         word[R14] <= R10     // push R10
028         R10 <= R2            // keep room B's reading through the first call
02C         R2 <= -180
030         call above, R15
034         R5 <= R10
038         R10 <= R1            // keep room A's amount through the second call
03C         R1 <= R5
040         R2 <= -200
044         call above, R15
048         R1 <= R1 + R10
04C         R10 <= word[R14]     // pop R10
050         R14 <= R14 + 8
054         R15 <= word[R14]     // pop R15
058         R14 <= R14 + 8

```

Keys to write: `investigation`, `pushedLead`, `pushedAfter`, `construction`, `bothLead`,

## investigation (about 30 words)

The figure runs the new program, with room A at -170 and room B at -190. A breakpoint is set on
`above`, and the stack is shown under the registers.

## pushedLead (about 70 words, above the figure; a short list allowed)

1. The watch shows R14, R15 and `word[R14]`, the word on top of the stack.
2. Press "Step" through `total`'s first four lines and watch each push: R14 goes down by 8, and
   the word goes into the RAM.
3. Then press "Run to a breakpoint" to reach each call of `above`.
4. Step on through the two pops at the end of `total`, and watch R15 take back `010`.

## pushedAfter (about 70 words, below the figure; shown from the start)

1. `7B8` holds `010`, the address after the main program's call: `total`'s return address.
2. `7B0` holds what R10 held when `total` started. The main program never set R10, so it is X.
   The pop puts that back too.
3. The display shows 20. 30 instructions run, and the program stops at `014`.
4. At the end R14 is back at `7C0`.

## construction (about 40 words)

1. The challenge's function calls `above` twice and keeps two words through the calls.
2. Two kept registers hold them, so the function must push both, and R15, and pop them before it
   returns.

## bothLead (one sentence, above the challenge)

Write `both`, step through it with the stack shown, then run the tests.

## c1Task (about 130 words, a list allowed)

1. Write the function `both`. R1 holds room A's reading and R2 room B's. Return in R1 how many
   rooms are above their limits: 0, 1 or 2. Room A's limit is -180 and room B's is -200; a reading
   equal to its limit is not above it.
2. Use `above`, which the starting text gives: it returns 0 when a reading is not above its limit.
3. Keep the calling convention: R10 to R14 as they were when `both` returns, and the return through
   R15.
4. The starting text's main program sets R14, calls `both` and shows the result. Its `both`
   returns 0.
5. There are 9 tests.
   - Six call `both` alone, with R1 and R2: -170 and -190; -185 and -210; -170 and -210; -185 and
     -190; 25 and 30; -180 and -200. Each checks R1, R10 to R14, and the return through R15.
   - Three run the whole program with room A and room B at -170 and -190; -185 and -210; -170 and
     -210. Each checks the display and that the program ends at its `stop`.

## c1Hints (five, in this order)

1. The idea: push R15, and every kept register you use, when `both` starts; pop them in the
   opposite order before `goto R15`.
2. A common mistake: popping in the order you pushed. The first pop then gives R15 the word you
   pushed last.
3. A smaller example: `total` in this lesson pushes R15 and R10, and pops R10 first.
4. Part of the answer: keep room B's reading in R11 and the count in R10. After each call of
   `above`, `if R1 == R0 goto` skips `R10 <= R10 + 1` when the result is 0, with R0 holding 0.
5. The whole answer:

```
both:   R14 <= R14 - 8
        word[R14] <= R15
        R14 <= R14 - 8
        word[R14] <= R10
        R14 <= R14 - 8
        word[R14] <= R11
        R11 <= R2
        R10 <= 0
        R0 <= 0
        R2 <= -180
        call above, R15
        if R1 == R0 goto roomB
        R10 <= R10 + 1
roomB:  R1 <= R11
        R2 <= -200
        call above, R15
        if R1 == R0 goto done
        R10 <= R10 + 1
done:   R1 <= R10
        R11 <= word[R14]
        R14 <= R14 + 8
        R10 <= word[R14]
        R14 <= R14 + 8
        R15 <= word[R14]
        R14 <= R14 + 8
        goto R15
```

## failureExperiment (about 40 words)

1. The figure's program is the new one with its first line left out: it never sets R14.
2. R14 holds X, so the push's address is unknown.

## noStartLead (one sentence, directly above the figure)

Predict where the run pauses, then press "Run to the end".

## noStartAfter (about 50 words, shown once the run has ended)

1. The debugger pauses before `014`'s next line, `word[R14] <= R15` at `018`: the store's
   address needs R14, which nothing has set.
2. 4 instructions have run. `R14 <= R14 - 8` at `014` ran, and gave X, since R14 was X.
3. Every program that uses the stack starts by setting R14.
