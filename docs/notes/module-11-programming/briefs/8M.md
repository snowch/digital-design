# Brief 8M: the debugger's and the grader's short texts, after the reading review

Read `00-module.md` (the shared fact sheet) first; it applies here. Plain text, no Markdown, no
backticks. Keep every {placeholder} exactly as written. A sentence ends with a full stop; a button's
name or a label has none.

## How a run ends: one word each

- A run *stops* at its `stop`. The machine *halts* with a cause. The debugger *pauses* at a
  breakpoint, and the run can go on. The debugger *cuts off* a run after 5000 instructions.
- New: when the next instruction needs a register nothing has set (for an address, a branch's
  comparison, or a jump), the debugger *ends* the run before that instruction. The run cannot go
  on. Use "ends the run" for this and for nothing else.

Keys to write:

- `stops.unknown-address`: the debugger ended the run before the instruction at {address}: the
  address needs {reg}, which nothing has set.
- `stops.unknown-branch`: the same, the branch compares {reg}, which nothing has set.
- `stops.unknown-jump`: the same, the jump goes to the address in {reg}, which nothing has set.
- `stops.fellOff`: a test called a function, and the function ran past its last line without a
  return through R15. (The tests put a word that is not an instruction after the program, so the
  machine halted there.)
- `mustStop`: a whole run must end at the program's own `stop`.
- `ranOne`: "1 instruction run." (the plural is "{n} instructions run.").
- `depthRan`: the chart's label on its last instruction: "{n} instructions run". `depthRanOne`:
  "1 instruction run".
- `depthCalls`: a line under the chart: the marks under its axis are the {n} calls the run made.
- `stackFolded`: in the stack view, a run of like calls drawn as one line: {n} more calls, each
  {name} (the group's name, such as "warmRooms, called from 05C"), holding {words} words between
  them.
- `assemblerAnswer`: the verdict of a question about what the assembler made: "The assembler gives
  {answer}." (a question about a run says "The run gives {answer}.").
- `watchName`: a watch names {name}, and no line of the program names it.
- `watchAlign`: a watch's address, {address} ({decimal} in decimal), is not a multiple of 8, so
  no word starts there.
- `watchOutside`: a watch's address, {address} ({decimal} in decimal), has no word of memory: the
  ROM and the RAM run from 000 to 7BF.
- `watchBad`: the debugger cannot read {text}: write a register (R1, PC) or word[...] with an
  address; a number is decimal, or hexadecimal after 0x, as in a program.
- `replaceConfirm`: a button that replaces the learner's program with the chosen start
  ("Replace my program"). `replaceCancel`: a button that keeps it ("Keep my program").

## Module 10's comparison figure (`program-compare`), used in Modules 10 and 11

A run that ends at its `stop` stops; only a cause halts. These labels show beside each run:

- `registerAfter`: "R{n} at the end: {value}"
- `displayAfter`: "Display at the end: {value}"
- `stoppedAtStop`: the run stopped at its stop, at {address}.
- `notStopped`: the run did not end: it neither stopped nor halted.
