# Brief 2C: lesson `lists` (Module 11, lesson 2), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler**, **debugger** and **breakpoint** (not in bold). No later term (function, argument,
calling convention, stack, frame, recursion) may appear.

Keys to write: `explanation`, `generalisation`, `riseLead`, `c2Task`, `c2Hints` (five),
`reflection`, `modelVsReality`.

## explanation (about 150 words, a numbered list allowed)

The lesson's loop has five parts, and most loops over a list have the same five.

1. Set up, before the loop: R1 takes the address of the first reading, R2 the count, R3 the answer
   so far (0), and R0 holds 0 to compare with.
2. The test, at the top: `if R2 == R0 goto done` leaves when no readings are left. Because the
   test comes first, an empty log, with a count of 0, runs the loop's body no times.
3. The body: `R5 <= word[R1]` loads the reading R1 points at, and a branch decides what to do
   with it.
4. The step: `R1 <= R1 + 8` moves to the next word, since a word is 8 bytes, and `R2 <= R2 - 1`
   counts one reading done.
5. Back: `goto next` returns to the test.

The program's length does not depend on the log's. The same lines run for six readings or sixty.

## generalisation (about 100 words)

1. Any question about a list fits this shape. Only the body changes: count, find, or compare.
2. One register walks the list by its address; another says when to stop. Here the count comes
   first in the log. A list could instead end with a word no reading can hold, and the test would
   look for that word.
3. A body can keep a value from one time round to the next in a register, such as the reading
   before.
4. Readings are signed, so a comparison of readings says `signed`. A count or an address is never
   below 0, and either reading gives the same answer.

## c2Task (about 100 words, a list allowed)

1. A sudden rise in a room's readings can mean a door left open. Show on the display the largest
   rise from one reading to the next: the later reading minus the earlier, for each pair of
   neighbours in the log.
2. If the readings only fall, every rise is below 0, and the largest is still the one to show.
3. The tests add `count` and `log` after your program. Every log has at least two readings.
4. There are 6 tests, each a log:
   - -190, -181, -175, -170
   - -190, -195, -200
   - -170, -190
   - -185, -180, -179
   - -200, 25, -150, 30
   - -181, -182, -183, -184, -185, -186, -170
5. Each checks the display and that the program ends at its `stop`.
6. The starting text shows 0 and stops.

## c2Hints (five, in this order)

1. The idea: walk the log keeping the earlier reading of each pair in a register, and the largest
   rise so far in another.
2. A common mistake: starting the largest rise at 0. A log that only falls, such as -190, -195,
   -200, has a largest rise of -5, and a start of 0 would show 0.
3. A smaller example: for the log -190, -181, the only pair's rise is -181 - (-190), which is 9.
4. Part of the answer: start the largest rise at the first pair's rise, `R3 <= R6 - R5`, with R5
   the first reading and R6 the second; there is one pair fewer than readings.
5. The whole answer:

```
         R1 <= log
         R2 <= word[count]
         R2 <= R2 - 1
         R0 <= 0
         R5 <= word[R1]
         R6 <= word[R1 + 8]
         R3 <= R6 - R5
next:    if R2 == R0 goto done
         R6 <= word[R1 + 8]
         R7 <= R6 - R5
         if R7 < R3 signed goto smaller
         R3 <= R7
smaller: R5 <= R6
         R1 <= R1 + 8
         R2 <= R2 - 1
         goto next
done:    word[display] <= R3
         stop
```

## reflection (about 70 words)

1. The office wants two checks: room A's reading against its limit, -180, and room B's against
   its own, -200.
2. The check is the same lines each time, with a different reading and a different limit.
3. Written out twice, a mistake in the check must be found and mended twice.
4. End on the question: how can a program use one piece of program from two places?

## modelVsReality (about 100 words)

1. The log here is `word` data that the assembler puts in the ROM with the program. A real shop's
   log would be written into the RAM by a recorder, one reading at a time, as each arrives.
2. A real debugger sets a breakpoint by putting a special instruction in place of the line's word,
   or by having the machine compare the PC with an address. The course's debugger checks the PC
   before each instruction it runs.
3. A watch on a real machine reads the registers and the memory each time the machine pauses. The
   course's watch reads the model after every instruction.
