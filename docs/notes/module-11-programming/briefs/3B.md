# Brief 3B: lesson `functions` (Module 11, lesson 3), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler**, **debugger**, **breakpoint**, **function** and **argument** (not in bold). This
lesson introduces **calling convention**: set it in bold where it is first used, in
`construction`, plain meaning first. No later term (stack, frame, recursion) may appear.

The lesson's program checks room A against -180 and room B against -200 with the function
`above` (R1 the reading, R2 the limit, the result in R1), called from `008` and from `018`;
`above` is at `030`, and the program stops at `02C`. Brief 3A gives the whole listing.

Keys to write: `investigation`, `callLead`, `callAfter`, `construction`, `rolesLead`, `c1Task`,
`c1Hints` (five), `failureExperiment`, `spoiledLead`, `spoiledAfter`.

## investigation (about 30 words)

The figure runs the program in the debugger, with a breakpoint on `above`'s first line. Each pause
comes just after a call has gone to the function.

## construction (about 130 words, a list allowed)

1. Which registers carry the arguments, which the result, and which a function may change, is not
   up to each function. It is an agreement every program on the machine keeps: a **calling
   convention**. The course's is:
   - R1 to R4 carry a function's arguments. R1 carries its result back.
   - R5 to R9 are free: a function may change them. A caller cannot rely on what they hold after a
     call.
   - R10 to R13 are kept: a function that changes one puts it back before it returns. A caller can
     keep a word in one through a call.
   - R15 holds the return address.
   - R14 has a role lesson 4 gives it. R0 is free.
2. A function may change its own arguments, R1 to R4, as `above` changes R1.

## rolesLead (one sentence, above the challenge)

Say what the calling convention lets a function do with each register, then run the tests.

## c1Task (about 60 words)

1. For each of R1, R3, R7 and R12, choose what the calling convention says a function does with
   it: carries the result back; may change it; or must put it back before it returns.
2. Choose one answer for each register.
3. There are 4 tests, one for each register.

## c1Hints (five, in this order)

1. The idea: the convention gives each group of registers one role: R1 to R4, R5 to R9, R10 to
   R13.
2. A common mistake: treating an argument as kept. A function may change R1 to R4; `above` changes
   R1 to give its result.
3. A smaller example: R9 is free, so a function may change it.
4. Part of the answer: R1 carries the result back, and R12 must be put back.
5. The whole answer: R1 carries the result back; R3 and R7 may be changed; R12 must be put back.

## failureExperiment (about 70 words)

1. This program adds room A's and room B's amounts above their limits, with room A at -170 and room
   B at -150.
2. After the first call, it keeps room A's amount in R10, `R10 <= R1`, through the second call.
   R10 is kept, so the convention allows that.
3. The second program is the same, except that its `above` uses R10 as a spare register on the way
   to its result, and does not put R10 back.

## spoiledLead (one sentence, directly above the figure)

Predict what each program shows, then press "Run the programs".

## spoiledAfter (about 70 words, shown once the programs have run)

1. The first shows 60: room A's 10 and room B's 50. R10 still holds 10 at the end.
2. The second shows 100. Its `above` left room B's 50 in R10, so the program added 50 and 50.
3. The function gives the right result every time. It breaks its caller, by changing a register
   the convention says it keeps.
