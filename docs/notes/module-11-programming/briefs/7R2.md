term (not in bold). This lesson introduces nothing. Never write "frame", "stop for good" or "the

## Words on this page

- "the outline": the program the challenge starts from, and what the button "Start from the
  outline" puts back. Call it that everywhere, and only once the question's figure has said what
  it is.
- "return" means only going back through R15. What a function leaves in R1 is its "result".
- "how many readings are warmer than the limit", never "the warm count" or "the count" (`count` is
  only the data word).
- Function names as given, with no possessive: "the first line of `report`", never "`report`'s".
- Addresses: in prose and on the page, `400` and `408` are addresses in hexadecimal. In a program
  they must be written `0x400` and `0x408`: a number without `0x` is decimal, and `word[400]` is
  the address 400 decimal, in the ROM, where a store halts with cause `34`.

## The program

The report has four functions and a main program.

- The main program: `R14 <= 0x7C0`; `R1 <= log`; `R2 <= word[count]`; `R3 <= word[limit]`;
  `call report, R15`; it stores R1 to the display; if R1 is not 0 it stores 1 to the lamps (bit 0
  is ALARM); `stop`.
- `report` takes the list's address in R1, how many readings in R2, the limit in R3. It calls
  `lowestOf` and stores the result at `0x400`; calls `highestOf` and stores the result at `0x408`;
  calls `warmCount`, whose result, how many readings are warmer than the limit, is its own result
  in R1. Because it calls, it pushes R15. It keeps the list's address, its count and the limit in
  R10, R11 and R12 through the calls, because a called function may change R1 to R9; so it pushes
  R10, R11 and R12 when it starts and pops them, in the opposite order, before `goto R15`.
- `lowestOf` and `highestOf` take the list's address in R1 and how many readings in R2; the result
  in R1 is the lowest (or highest) reading, or 0 for an empty list. `warmCount` also takes the limit
  in R3; its result in R1 is how many readings are warmer than the limit. These three call nothing
  and change none of R10 to R14, so they need no stack.
- Who reads `400` and `408`: the office's computer reads the words at `400` and `408` each morning,
  for its record of the week. No device of the shop shows them.

## The outline

The outline has the main program and `lowestOf` whole. `report`, `highestOf` and `warmCount` are
each two lines, `R1 <= 0` and `goto R15`, under a comment that says what the function takes and
gives. The buttons "Start from the outline" and "Start from an empty program" ask before they
replace a program you have changed.

## p1Question (one short question)

What does R2 hold once `lowestOf` has returned?

## p1Explain (about 70 words, shown once the learner has answered)

1. R2 holds 0. `lowestOf` takes 1 off R2 each time it moves to the next reading, and returns when R2
   reaches 0. (Its result, in R1, is -190.)
2. A called function may change R1 to R9, and `lowestOf` changes R2.
3. So `report`, which needs the list's count again for `highestOf` and `warmCount`, must keep it
   where a call does not change it: in a kept register, R11, whose own word it pushes first.

## construction (about 160 words, a list)

The specification, one item per part:

- The main program: as in "The program" above. It starts with `R14 <= 0x7C0`, because `report`
  pushes words (lesson 4).
- `report`: pushes R15 and R10 to R12 when it starts; copies R1, R2 and R3 into R10, R11 and R12;
  calls `lowestOf` and stores R1 with `word[0x400] <= R1`; puts R10 and R11 back into R1 and R2 and
  calls `highestOf`, storing R1 with `word[0x408] <= R1`; puts R10 to R12 back into R1 to R3 and
  calls `warmCount`, whose result is already in R1; pops R12, R11, R10 and R15 in that order;
  `goto R15`.
- `highestOf` is `lowestOf` with one comparison turned round.
- `warmCount` walks the list as lesson 2's counting program did, with the limit in R3.
- `lowestOf`, `highestOf` and `warmCount` call nothing and change none of R10 to R14, so they push
  nothing. Each returns with `goto R15`.
- Write the addresses `0x400` and `0x408` with `0x`, as the facts above say why.

## explanation (about 130 words: one sentence, then a list)

The report uses each of the module's lessons:

- lesson 1: the log is `word` data the assembler puts after the program;
- lesson 2: each function walks a list with an address register and a count;
- lesson 3: the functions take arguments and give results by the calling convention, so the tests
  can call each alone;
- lesson 4: `report` calls, so it pushes R15; it keeps the address, the count and the limit in R10
  to R12 through its calls, and pushes their own words first; the main program sets R14;
- lesson 5: no recursion: in a log each reading leads only one way on, to the next, so a loop does
  the job;
- lesson 6: the tests' logs reach the edges: an empty log, one reading, readings of both signs, a
  reading equal to the limit.

## generalisation (about 60 words)

   reach every edge.
2. Each function tested alone can be used again: next week's report on room B's log calls the same
   `lowestOf`.
3. Do not mention the display, the lamps or the shop's devices (the reflection does).

## c1Hints (five, in this order, each starting with its label)

1. The idea: write one function at a time, and run its call test from "Run with" in the debugger
   before you write the next. The functions you have not written yet can stay as the outline's two
   lines.
2. A common mistake: calling `highestOf` with R2 as `lowestOf` left it. `lowestOf` leaves R2 at 0,
   so `highestOf` sees an empty list and gives 0. `report` must keep the count in R11 and put it
   back in R2 before each call.
3. A smaller example: lesson 4's `sumOver` pushed R15 and R10 when it started, and popped R10, then
   R15, before `goto R15`. `report` does the same with R15, R10, R11 and R12.
4. Part of the answer: `highestOf` is `lowestOf` with `if R6 < R5 signed goto highNext` in place of
   `if R5 < R6 signed goto lowNext`, and its own names. `warmCount` counts with
   `if R3 >= R6 signed goto warmSkip`.
5. The whole answer: replace the outline's `report`, `highestOf` and `warmCount` with the code
   below, exactly as given (it goes in a code block, unchanged):

```
report:   R14 <= R14 - 8
          word[R14] <= R15
          R14 <= R14 - 8
          word[R14] <= R10
          R14 <= R14 - 8
          word[R14] <= R11
          R14 <= R14 - 8
          word[R14] <= R12
          R10 <= R1
          R11 <= R2
          R12 <= R3
          call lowestOf, R15
          word[0x400] <= R1
          R1 <= R10
          R2 <= R11
          call highestOf, R15
          word[0x408] <= R1
          R1 <= R10
          R2 <= R11
          R3 <= R12
          call warmCount, R15
          R12 <= word[R14]
          R14 <= R14 + 8
          R11 <= word[R14]
          R14 <= R14 + 8
          R10 <= word[R14]
          R14 <= R14 + 8
          R15 <= word[R14]
          R14 <= R14 + 8
          goto R15

highestOf: R0 <= 0
          if R2 == R0 goto highNone
          R5 <= word[R1]
highNext: R1 <= R1 + 8
          R2 <= R2 - 1
          if R2 == R0 goto highDone
          R6 <= word[R1]
          if R6 < R5 signed goto highNext
          R5 <= R6
          goto highNext
highDone: R1 <= R5
          goto R15
highNone: R1 <= 0
          goto R15

warmCount: R0 <= 0
          R5 <= 0
warmNext: if R2 == R0 goto warmDone
          R6 <= word[R1]
          if R3 >= R6 signed goto warmSkip
          R5 <= R5 + 1
warmSkip: R1 <= R1 + 8
          R2 <= R2 - 1
          goto warmNext
warmDone: R1 <= R5
          goto R15
```

## reflection (about 60 words)

1. Your program reaches the display and the lamps itself, with stores.
2. When a program does something the machine refuses, the machine halts and nothing more runs.
3. A shop's machine runs more than one program; one program's mistake should not end them all.
4. Ask: what if, instead of halting, the machine went to a program of its own, said why, and
   carried on?

## modelVsReality (about 60 words)

1. A real program would read the day's log from a store that keeps it, not as data added after
   the program. The tests add the log so every log can be tried without changing the program.
2. Real programs are tested the same way: on chosen inputs, and with each function called alone.
3. Tests can only show the mistakes their inputs reach.

## Feedback sentences (one sentence each; shown when a test or an answer fails)

- `details.report` (a whole run fails): the display must show how many readings are warmer than the
  limit, ALARM must be on when that is not 0, and the words at 400 and 408 must hold the lowest and
  highest readings.
- `details.report-report` (a call of `report` fails): R1 must hold how many readings are warmer than
  the limit in R3, the words at 400 and 408 the lowest and highest, from 3 calls, with R10 to R14
  as they were and a return through R15.

For lesson 5 (`recursion`): the learner works out a run of `warmRooms` on a second store and
answers three numbers. Each sentence starts "{actual} is not it;" and then gives the rule, not the
answer:

- `answers.details.storeCalls`: `warmRooms` is called once for the hall, then once for what lies
  behind each door of every room it finds, a room or nothing.
- `answers.details.storeWords`: a call that finds a room pushes 4 words, and the words of every call
  not yet returned are on the stack together.
- `answers.details.storeR14`: R14 starts at 7C0, and each word pushed takes 8 off it; give the
  address as three hexadecimal digits.

For lesson 6 (`debugging`), the question "which log shows the mistake":

- `answers.details.edgeLog` (no `{actual}`): on that log the program and a right one show the same
  number, so it cannot show the mistake.
