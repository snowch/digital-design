# Brief 1L: lesson `assembly` (Module 11, lesson 1), titles, captions and short labels

Read `00-module.md` (the shared fact sheet) first; it applies here. Terms allowed: **assembly**,
**assembler**, **debugger** (not in bold here). No later term.

Short texts. A title or heading has no full stop. A caption is one short sentence with a full
stop. Option and field labels have no full stop.

Keys to write:

- `title`: the lesson's title, as a question, about the lesson's question: how can you write a
  program as text and let a tool make the words?
- `objectives.1` to `objectives.4`, each starting with a verb: write a program as lines of text
  with names for addresses; say what the assembler makes of each line, a branch's constant and a
  word of data among them; read why the assembler refuses a line and mend it; step through a run in
  the debugger and say what each instruction changed.
- `titles.question` … `titles.reflection`: one heading for each of the ten sections, a few words,
  naming what the section contains. The sections: (question) words or text; (motivation) what the
  assembler does; (prediction) a branch's constant; (investigation) a run, one instruction at a
  time; (construction) your first program as text; (failureExperiment) lines the assembler refuses;
  (explanation) how the assembler works, in two readings; (generalisation) a translation, line for
  word; (challenge) being the assembler; (reflection) more than one or two readings.
- `challengeTitles.c1`: the warmer room. `challengeTitles.c2`: being the assembler.
- `captions.listing`: the colder-room program's lines, addresses and words.
- `captions.predictListing`: predict the branch's constant, then see the words.
- `captions.debugger`: room A's program in the debugger.
- `captions.warmer`: write the warmer-room program and run the tests.
- `captions.mistakes`: mend the lines the assembler refuses.
- `captions.dataListing`: a word of data after the program, and the address it gets.
- `captions.beAssembler`: work out the addresses and words, and run the tests.
- `options.c003`, `options.c014`, `options.c005`: the three choices for the branch's constant,
  each the three digits in backticks followed by a few words: `003` (instructions from the branch
  to `fine`), `014` (the address `fine` names), `005` (the position of `fine` counting from
  `000`'s line as 1).
- `fields.cold`, `fields.limit`, `fields.branch`, `fields.load`: the four answers' labels: the
  address `cold` names; the address `limit` names; the word of `if R2 < R1 signed goto cold`; the
  word of `R1 <= word[limit]`.
- `runs.1` to `runs.5`: the warmer challenge's five tests, each naming its readings: room A -184,
  room B -250; room A -250, room B -184; both -200; room A -30, room B 15; room A 20, room B -5.
- `details.warmerDisplay`: one sentence a failed test adds: the display does not show the higher of
  the two readings, read signed.
- `details.address`: one sentence for a wrong address, with `{actual}` the learner's answer: it is
  not the address; give each instruction 4 bytes from `000`, and start a word at a multiple of 8.
- `details.branchWord`: one sentence for a wrong branch word, with `{actual}`: kind 5, the
  condition's job, A and B, and a constant that counts instructions from the branch.
- `details.loadWord`: one sentence for a wrong load word, with `{actual}`: a load from an address
  the constant gives is kind 3, job 8, with Y the register written and the address in the constant.
