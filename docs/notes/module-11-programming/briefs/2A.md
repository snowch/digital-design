# Brief 2A: lesson `lists` (Module 11, lesson 2), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **assembly**,
**assembler** and **debugger** (lesson 1). This lesson introduces **breakpoint**: set it in bold
where it is first used, in `prediction`, plain meaning first. No later term (function, argument,
calling convention, stack, frame, recursion) may appear.

The program of this lesson, as the figures show it:

```
// How many of the log's readings are warmer than -180?
       R1 <= log            // the address of the next reading
       R2 <= word[count]    // how many readings are left
       R3 <= 0              // how many were warmer
       R4 <= -180           // the limit
       R0 <= 0
next:  if R2 == R0 goto done
       R5 <= word[R1]
       if R4 >= R5 signed goto skip   // not warmer than the limit
       R3 <= R3 + 1
skip:  R1 <= R1 + 8
       R2 <= R2 - 1
       goto next
done:  word[display] <= R3
       stop
count: word 6
log:   word -184, -190, -176, -181, -172, -188
```

Keys to write: `question`, `logLead`, `motivation`, `prediction`, `p1Question`, `p1Explain`.

## question (about 60 words, above a figure)

1. Lesson 1 ended on a question: how does a program work through a list of readings kept in
   memory?
2. The shop keeps a log of room A's readings. The figure shows today's: six readings.
3. The office asks how many of them are warmer than the limit, -180.

## logLead (about 50 words, directly above the figure)

1. The log is kept as `word` data after a program: first `count: word 6`, the number of
   readings, then `log:` and the six readings, oldest first.
2. The assembler puts `count` at `038` and `log` at `040`.
3. Each reading is one word, so each starts 8 bytes after the one before: `040`, `048`, `050` and
   on to `068`.

## motivation (about 130 words, a short list allowed)

1. One line for each reading would make the program as long as the log, and a new program for
   every log.
2. Instead the same lines run once for each reading: a loop, as in Module 8's programs that went
   back with a branch.
3. Three registers do the work:
   - R1 holds the address of the next reading. `R5 <= word[R1]` loads it. `R1 <= R1 + 8` moves R1
     on to the next word.
   - R2 counts the readings left. It starts at `word[count]` and goes down by 1 each time round.
   - R3 counts the readings warmer than the limit.
4. `if R2 == R0 goto done` leaves the loop when no readings are left. R0 holds 0, because a branch
   compares two registers.

## prediction (above the figure; about 90 words)

1. The figure is the debugger on the program, with a **breakpoint** on the line `next`: a mark on
   a line where the run pauses before running that line. The round mark beside each line sets or
   clears one.
2. "Run to a breakpoint" runs until the next instruction is a line with a breakpoint, or until
   the program stops.
3. The run pauses at `next` once before each reading, and once more when none are left.
4. Choose an answer and press "Check my prediction". The buttons then work.

## p1Question (one sentence)

When the run pauses at `next` for the fourth time, what address does R1 hold?

## p1Explain (about 70 words)

1. R1 holds `058`, the fourth reading's address: `log` + 24.
2. The first pause comes before any reading is read, with R1 at `040`. Each time round adds 8, so
   three times round makes `058`.
3. The debugger shows R1 as 88, with `58` under it in hexadecimal.
4. By then 24 instructions have run, R2 holds 3 (three readings left), and R3 holds 1: -176 was
   warmer than -180.
