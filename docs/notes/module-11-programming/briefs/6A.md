# Brief 6A: lesson `debugging` (Module 11, lesson 6), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use every Module 11
term (not in bold): assembly, assembler, debugger, breakpoint, function, argument, calling
convention, stack, frame, recursion. This lesson introduces no term. Do not use "bug" or "debug"
as a noun or verb of your own: say "mistake" and "find" or "mend".

The lesson's first program, as the figures show it with the tests' log after it:

```
// How many of the log's readings are warmer than the limit?
000        R1 <= log
004        R2 <= word[count]
008        R2 <= R2 - 1         // the readings are numbered from 0
00C        R3 <= 0
010        R4 <= word[limit]
014        R0 <= 0
018 next:  if R2 == R0 goto done
01C        R5 <= word[R1]
020        if R4 >= R5 signed goto skip
024        R3 <= R3 + 1
028 skip:  R1 <= R1 + 8
02C        R2 <= R2 - 1
030        goto next
034 done:  word[display] <= R3
038        stop
040 count: word 4
048 limit: word -180
050 log:   word -190, -181, -175, -170
```

Keys to write: `question`, `resultsLead`, `resultsAfter`, `motivation`, `prediction`,
`p1Question`, `p1Explain`.

## question (about 70 words, above a figure)

1. Lesson 5 ended on a question: how do you find the mistake in a program that runs and gives a
   wrong answer?
2. The figure's program counts the log's readings warmer than the limit, -180, as lesson 2's did.
   Someone changed one line.
3. It runs on every log and stops at its `stop`. On some logs its answer is wrong.

## resultsLead (one or two sentences, directly above the figure)

The figure gives five logs, each with the count it should show. Press "Run all" to run the program
on each, and compare.

## resultsAfter (about 60 words, shown once the program has run)

1. The program shows 1 for log 1, which asks for 2. It shows 0 for logs 4 and 5, which ask for 1.
   Logs 2 and 3 are right.
2. Logs 1, 4 and 5 end with a reading warmer than the limit, -170. Logs 2 and 3 do not.
3. The wrong answers are the first clue: the last reading never counts.

## motivation (about 140 words, a numbered list)

A method for finding the mistake, in five steps:

1. Choose a log that fails, the smallest you can, so that each run is short. Here, log 1.
2. Say what each part of the program should leave. Before the loop, R1 should hold `log`'s
   address, R2 the count, 4, and R3 0. Each time round, R2 goes down by one.
3. Set a breakpoint before the part you doubt, here `next`, and run to it.
4. Step and watch. The first value that differs from what you said is next to the mistake.
5. Mend the line, then run every log again, not only the one that failed.

## prediction (above the figure; about 40 words)

1. The figure is the debugger on the program, with log 1 after it.
2. The first time the run reaches `next`, 6 instructions have run.
3. Choose an answer and press "Check my prediction". The buttons then work.

## p1Question (one sentence)

When the run first reaches `next`, what does R2 hold?

## p1Explain (about 70 words)

1. R2 holds 3, where the count is 4.
2. Step 2 of the method says R2 should hold the count, 4. It holds 3, so the mistake is before
   `next`.
3. Line `008`, `R2 <= R2 - 1`, takes one off. Its comment says the readings are numbered from 0,
   but R2 is a count of readings, not a reading's number. With 3 left to count, the loop stops one
   reading early.
