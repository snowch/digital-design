# Brief 4L: lesson `stack` (Module 11, lesson 4), titles, captions and short labels

Read `00-module.md` (the shared fact sheet) first; it applies here. Terms allowed: **assembly**,
**assembler**, **debugger**, **breakpoint**, **function**, **argument**, **calling
convention**, **stack**, **frame** (never in bold here). "Recursion" must not appear.

Short texts, plain text with no Markdown and no backticks. A title, a heading, an option, a field
label or a name has NO full stop. A caption is one short sentence with a full stop. Keep the
lesson's own words for things: say "program", not "code".

Keys to write:

- `title`: the lesson's title, as a question, in the brief's words: what must a function that
  calls another keep, and where?
- `objectives.1` to `objectives.4`, each starting with a verb: say why a function that calls
  another loses its return address; push and pop words on a stack in the RAM with R14; say what
  a function's frame holds; write a function that keeps R15 and kept registers through its calls.
- `titles.question` … `titles.reflection`: one heading each, a few words. (question) a return
  address lost; (motivation) a stack in the RAM; (prediction) where R14 points; (investigation)
  pushes and pops; (construction) a function that keeps two words; (failureExperiment) a stack
  never started; (explanation) frames and the convention's last rows; (generalisation) last in,
  first out; (challenge) the stack's addresses; (reflection) a function that calls itself.
- `challengeTitles.c1`: the function both. `challengeTitles.c2`: the stack's addresses.
- `captions.lost`: total, with no stack, in the debugger.
- `captions.predict`: predict R14 when above starts, then run the program.
- `captions.pushed`: total with a stack, in the debugger.
- `captions.both`: write the function and run the tests.
- `captions.noStart`: the program with R14 never set.
- `captions.depth`: the words on the stack over the whole run.
- `captions.addresses`: work out the addresses and run the tests.
- `options.at7C0`, `options.at7B8`, `options.at7B0`: three answers, each the address and a few
  words after a colon: 7C0: where the program started R14; 7B8: one push down; 7B0: two pushes
  down.
- `fields.returnAt`, `fields.keptAt`, `fields.inAbove`, `fields.after`: the four answers' labels:
  the word holding total's return address; the word holding what R10 held; R14 while above runs;
  R14 after total returns.
- `callPrefix`: "Call". `roomPrefixA`: "Room A". `roomPrefixB`: "room B".
- `details.stackAddress`: one sentence for a wrong address, with `{actual}` the learner's answer
  (keep the slot): {actual} is not that address; R14 starts at 7C0 and each push takes 8 off it
  before it stores.
- `details.bothCall`: one sentence a failed call adds: R1 must hold how many rooms are above their
  limits, with R10 to R14 as they were and a return through R15.
- `details.bothRun`: one sentence a failed run adds: the display must show how many rooms are above
  their limits.
