# Brief 7C: lesson `log-report` (Module 11, lesson 7, the capstone), third part

Read `00-module.md` (the shared fact sheet) and brief `7A.md` (the report and `lowest`) first. You
may use every Module 11 term (not in bold). Spell "program"; say "starting text".

Keys to write: `explanation`, `generalisation`, `challenge`, `reportLead`, `c1Task`, `c1Hints`
(five), `reflection`, `modelVsReality`.

## explanation (about 120 words, a list allowed)

The report uses the module's lessons:

- the log is `word` data the assembler puts after the program (lesson 1);
- each function walks a list with an address register and a count (lesson 2);
- the functions take arguments and give results by the calling convention, so the tests can call
  each alone (lesson 3);
- R14 is set, and each function leaves it, and R10 to R13, as it found them (lesson 4);
- it does not need recursion (lesson 5): no part of the report depends on the readings' order;
- the tests' logs reach the edges: an empty log, one reading, readings of both signs, a reading
  equal to the limit (lesson 6).

## generalisation (about 90 words)

1. A program the shop can rely on is one that passes tests chosen to reach every edge, not one that
   looks right.
2. Each function, tested alone, can be used again: next week's report on room B's log calls the
   same `lowest`.
3. The program reaches the shop's devices directly, with stores to the display and the lamps. A
   later module asks whether every program should be allowed to.

## c1Task (about 160 words, lists allowed)

1. Write a program that reports on the log the tests add after it (`count`, `limit` and `log`):
   - the display shows how many readings are warmer than the limit;
   - ALARM is on when any reading is warmer, and no lamp is on otherwise;
   - the word at `400` holds the lowest reading and the word at `408` the highest, both 0 for an
     empty log;
   - the program ends at its `stop`.
2. Do the work with three functions: `lowest`, `highest` and `warmer`. Each takes the list's
   address in R1 and its count in R2, `warmer` also the limit in R3, and leaves its result in R1.
   Each keeps the calling convention: R10 to R14 as they were, and a return through R15.
3. There are 15 tests, on six logs:
   - log 1: -184, -190, -176, -181, -172, -188, limit -180;
   - log 2: -195, -200, -191, -199, limit -180;
   - log 3: -175, limit -180;
   - log 4: empty, limit -180;
   - log 5: -184, 35, -176, 12, -190, limit -180;
   - log 6: -150, -160, -155, limit -150.
4. Six run the whole program on each log and check the display, the lamps, the words at `400` and
   `408`, and the stop. Nine call each function alone on logs 1, 4 and 5, and check R1, R10 to R14
   and the return.

## c1Hints (five, in this order)

1. The idea: write one function at a time, and test it alone in the debugger before the next.
2. A common mistake: starting the highest so far at 0. On a log whose readings are all below 0,
   the highest is then 0.
3. A smaller example: `lowest` keeps a reading when `if R5 < R6 signed` finds it no lower; `highest`
   keeps one when it is no higher.
4. Part of the answer: `highest` is `lowest` with `if R6 < R5 signed goto highNext` in place of
   `if R5 < R6 signed goto lowNext`, and its own names. `warmer` counts with
   `if R3 >= R6 signed goto warmSkip`.
5. The whole answer:

```
highest:  R0 <= 0
          if R2 == R0 goto highNone
          R5 <= word[R1]
highNext: R1 <= R1 + 8
          R2 <= R2 - 1
          if R2 == R0 goto highDone
          R6 <= word[R1]
          if R6 < R5 signed goto highNext
          R5 <= R6
          goto highNext
highDone: R1 <= R5
          goto R15
highNone: R1 <= 0
          goto R15

warmer:   R0 <= 0
          R5 <= 0
warmNext: if R2 == R0 goto warmDone
          R6 <= word[R1]
          if R3 >= R6 signed goto warmSkip
          R5 <= R5 + 1
warmSkip: R1 <= R1 + 8
          R2 <= R2 - 1
          goto warmNext
warmDone: R1 <= R5
          goto R15
```

## reflection (about 80 words)

1. Your program reaches the display and the lamps itself, and when it does something the machine
   refuses, the machine halts, and nothing more runs.
2. A shop's machine runs more than one program, and should not stop for good on one program's
   mistake.
3. End on the question: what if, instead of halting, the machine went to a program of its own,
   said why, and carried on?

## modelVsReality (about 80 words)

1. A real program would read the day's log as it was written, from a store that keeps it, not as
   data added after the program. The tests add it so every log can be tried.
2. Real programs are tested the same way, on chosen inputs and with each function called alone.
   The tests can only show mistakes the chosen logs reach.
