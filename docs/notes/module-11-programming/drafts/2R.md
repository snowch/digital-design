logLead: The program's log holds six readings, stored after the program. `count: word 6` at `038` tells how many readings there are. `log:` at `040` holds the readings themselves, each one word, 8 bytes on from the one before.

The figure runs the program and stops each time it is about to load a reading. It shows R1, and marks which reading in the log R1 points to. Press "Next reading" and watch R1 move down the log.

prediction: The figure lists the program as eight-digit words. When the program stops, what address will R1 hold? Make your prediction, then press "Check my prediction". The listing's words then show.

p1Question: When the program stops, what address does R1 hold?

p1Explain: R1 holds `070`, the address just past the log. It starts at `040`. Each time the loop runs, after the reading loads, `R1 <= R1 + 8` moves it on.

The loop runs six times, once for each reading. After the last reading at `068`, R1 moves on to `070`. Then R2 is 0, so `if R2 == R0 goto done` leaves the loop. Nothing reads the word at `070`. `068` is the last reading's address.

investigation: A mark on a line that makes the run pause before that line runs is a **breakpoint**. The round mark beside each line in the figure sets or clears one. One is set on `next`.

Press "Run to a breakpoint". The program runs until the next instruction is on a breakpoint line, or stops. A watch shows values you choose. If a value changed since the run last paused, the watch shows what it was before. The log shows its words and marks the one whose address a register holds.

generalisation: Any question about a list fits this shape. Only the body changes:

- Count, find or compare

One register walks the list by address. Another register tracks when to stop. Here, the count comes first in the log. A list could end with a marker word instead, and the test would look for that marker.

The body can keep a value from one time round to the next, stored in a register. Here, no value is kept.

Readings are signed, so a comparison of two readings says `signed`. A count or an address is never below 0: read signed or unsigned, it gives the same comparison.
