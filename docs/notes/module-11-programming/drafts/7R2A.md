motivation:
The tests check the report like this:

- The display shows how many readings are warmer than the limit. A reading equal to the limit is not warmer.
- ALARM is on when any reading is warmer. Otherwise no lamp is on.
- The word at `400` holds the lowest reading, and the word at `408` holds the highest. Both are 0 for an empty log.
- The program ends at its `stop`.

The tests add `count`, `limit` and `log` after your program.

Four functions do the work: `report`, and the three it calls, `lowestOf`, `highestOf` and `warmCount`.

The result of `lowestOf` in R1 is the lowest reading, or 0 for an empty list. `highestOf` takes the same two inputs and gives the highest reading in the same way. `warmCount` also takes the limit in R3, and its result in R1 is how many readings are warmer than the limit. `report` takes the same three inputs, and its result in R1 is also how many readings are warmer than the limit.

The tests call each function alone, as in lessons 3 to 5, and run the whole program on each log.

p1Question: What does R2 hold once `lowestOf` has returned?

p1Explain:
R2 holds 0. `lowestOf` takes 1 off R2 each time it moves to the next reading. It returns when R2 reaches 0, and its result in R1 is -190.

A called function may change R1 to R9, and `lowestOf` changes R2.

So `report` must keep the count where a call does not change it. It needs the count again for `highestOf` and `warmCount`. It keeps the count in R11, and it pushes R11's own word first.

construction:
- The main program: `R14 <= 0x7C0`, `R1 <= log`, `R2 <= word[count]`, `R3 <= word[limit]` and `call report, R15`. It then stores R1 to the display. If R1 is not 0, it stores 1 to the lamps, where bit 0 is ALARM. It ends with `stop`. It starts with `R14 <= 0x7C0`, because `report` pushes words (lesson 4).
- `report`: it pushes R15, R10, R11 and R12 when it starts. It copies R1, R2 and R3 into R10, R11 and R12. It calls `lowestOf` and stores R1 with `word[0x400] <= R1`. It copies R10 and R11 back into R1 and R2, calls `highestOf`, and stores R1 with `word[0x408] <= R1`. It copies R10, R11 and R12 back into R1, R2 and R3 and calls `warmCount`, whose result is already in R1. It pops R12, R11, R10 and R15, in that order, and then runs `goto R15`.
- `highestOf` is `lowestOf` with one comparison turned round.
- `warmCount` walks the list as lesson 2's counting program did, with the limit in R3.
- `lowestOf`, `highestOf` and `warmCount` call nothing and change none of R10 to R14, so they push nothing. Each returns with `goto R15`.
- Write the addresses as `0x400` and `0x408`. Without `0x`, a number is decimal, and `word[400]` is address 400 decimal, in the ROM, where a store halts with cause `34`.
