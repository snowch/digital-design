explanation: Recursion works because each call has its own frame. When five calls of `newest` ran at once, the four handling readings each kept its own return address and its reading's address on the stack. Registers are shared by every call. The stack is not.

Every call but the last one:

- pushes what it needs after the call;
- calls itself on a smaller list;
- pops and finishes.

The last case must come. It must call nothing. The list shrinks by one reading each call, so the call on the empty list is reached.

The reading shows after the call returns, so the newest shows first. For a log of n readings, `newest` is called n + 1 times. The stack holds 2n words at its deepest.

generalisation: A recursive function suits a job whose answer for a list is built from the answer for the rest of it. Here, the rest comes newest first, then the first reading.

The same job can be done by a loop that walks the log from its end. That loop needs no stack. Recursion keeps on the stack what the loop would work out from the count.

Each level of recursion costs stack. The course's machine has 120 words of RAM for the stack, so `newest` can show at most 60 readings.

Every recursive function needs a last case that calls nothing, reached for every argument.

modelVsReality: On a real machine, a stack that grows too far writes over whatever memory lies below it, often with no halt at all, and the programme fails later in a way that is hard to trace.

The course's machine keeps its programme in a ROM, so a stack that grows too far halts at the first push into the ROM, with cause `34`. The mistake shows where it happens.
