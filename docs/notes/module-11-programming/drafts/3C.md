explanation: The machine knows nothing of functions. `call above, R15` is kind 6: it writes the address of the next instruction into the register its Y digit names, and goes to `above`. R15 is used here only because programs agree on it.

`goto R15` is a jump to the address a register holds, like any other jump.

Nothing in the machine checks that a function puts R10 to R13 back, or that its result is in R1. The failure experiment's program broke the agreement, and the machine ran it without a word.

A **calling convention** is an agreement between programs, not a part of the machine. It lets a function written by one person be called from a program another person wrote, and lets a test call a function on its own.

generalisation: A function is written once and used from anywhere a call can reach. A mistake in it is mended once.

A function can be tested alone: give it arguments, call it, and check its result and the registers it must keep. The challenge's tests do that.

Each use costs two instructions: the call and the jump back. For a short piece used twice, the program is hardly shorter. For a longer piece or one used many times, the saving in lines grows.

aboveLead: Write `above`, test it in the debugger, then run the tests.

c2Task: The starting text is the lesson's main program with `above` returning 0 every time.

Write `above`: R1 holds a reading and R2 a limit. Return in R1 how far the reading is above the limit, or 0 if it is not above. A reading equal to the limit is not above it.

Keep the calling convention: put back any of R10 to R14 you change, and return with `goto R15`.

There are 9 tests:

- Six call `above` alone, with R1 and R2 set: -170 and -180; -190 and -180; -180 and -180; 25 and -180; -150 and -200; -205 and -200. Each checks R1, that R10 to R14 hold what they held before the call, and that the run came back through R15.
- Three run the whole program with room A and room B at: -170 and -190; -185 and -210; 25 and -150. Each checks the display, the lamps and that the program ends at `stop`.

c2Hints.1: Compare the reading with the limit, then either subtract or give 0.

c2Hints.2: A common mistake is comparing unsigned. A reading of 25 read unsigned is smaller than -180 read unsigned, so the function would say it is not above.

c2Hints.3: For a reading of -170 and a limit of -180, the result is -170 - (-180), which is 10.

c2Hints.4: `if R2 < R1 signed goto over` jumps when the limit is less than the reading.

c2Hints.5: The whole answer:

```
above: if R2 < R1 signed goto over
       R1 <= 0
       goto R15
over:  R1 <= R1 - R2
       goto R15
```

reflection: `above` calls no other function. The office now wants a function that checks both rooms by calling `above` twice.

When it calls `above`, that call writes R15 with a new return address. But R15 already held this function's return address.

What must a function that calls another keep, and where?

modelVsReality: Every real machine has a calling convention written down for its programs and tools. This lets functions from different authors and tools work together. The course's convention is its own and follows none of them.

Many real machines have a call that always writes one register. The course's call writes the register its Y digit names. So the choice of R15 is the convention's, not the machine's.
