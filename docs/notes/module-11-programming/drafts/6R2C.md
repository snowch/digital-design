explanation: How a run ends tells you where to look.

- **The program ran `stop`.** The run finished. Check what it left against what it should.
- **The debugger cut the run off** after 5000 instructions. A loop never ends, or a return address was lost, as in lesson 4.
- **The debugger ended the run: a register nothing has set.** A start is missing, such as `R14 <= 0x7C0`; a line names the wrong register; or a log walked past its end into RAM nothing has written, whose words are not set (the counting program, with the wrong `R2 <= R2 - 1` deleted, walks off an empty log this way). [Check: with the line at `008` deleted, an empty log has 0 in R2 and ends at once. It walks off only with the line at `008` present. The brief may mean another line.]
- **Cause `11`, an instruction's address outside the ROM.** A `goto R15` with a word in R15 that is not an address in the ROM, such as a reading or a stack address.
- **Cause `12`, an instruction's address in the ROM but not a multiple of 4.** A `goto R15` with the wrong word in R15, as when pops run in the wrong order (lesson 4).
- **Cause `21`, not an instruction.** The run went past the program's end into data or 0s: a missing `stop`, or a branch to the wrong name.
- **Cause `31`, no memory at the address.** An address register went past the memory: a loop of pops that takes R14 up past `7C0` through the devices, or a log walked backwards past its first reading.
- **Cause `33`, a word's address not a multiple of 8.** An address stepped by a number that is not a multiple of 8.
- **Cause `34`, a store to the ROM or a sensor.** A stack started in the wrong place, or a store to the log, which is in the ROM, as in the failure experiment.

The instruction that halts is rarely the one that is wrong: find which earlier line set the value it used.

generalisation: A mistake hides until a test reaches it. The counting program was right on two of its five logs.

So test on logs chosen to reach the edges: an empty log; one reading; a log whose first or last reading is the one that changes the answer; a reading equal to the limit; readings of both signs.

Mend one mistake at a time, and run every test again after each. A mended halt can uncover a second mistake behind it.

The method does not depend on the program: say what each part should leave, set a breakpoint before it, and find the first value that differs.

c2Task: The starting text counts the log's readings above the limit with the function `overBy` from lesson 3. For each reading, it calls `overBy`, and counts the reading when the result is not 0.

It keeps the log's address in R10, the readings left in R11, the limit in R12 and the number of readings above the limit in R13.

It has two mistakes. Find and mend both. `overBy` is right: do not change it.

The tests add `count`, `limit` and `log` after your program, all with the limit -180. "Run with" lists the 6 logs, among them an empty log and a log with a reading equal to the limit. Each test checks the display and that the program ends at its `stop`.

c2Hints.1: The idea: run, read how the run ends, find the line, mend it. Then run every log again: one mistake can hide the other.

c2Hints.2: A common mistake: stopping once the program reaches its `stop`. With one mistake mended, the other can still give a wrong number, or a halt on some logs.

c2Hints.3: A smaller example: the readings are words, 8 bytes apart, so an address that walks them goes up by 8 each time round.

c2Hints.4: Part of the answer: on log -190, -181, -175, -170 the first run halts with cause `33` at `018`, the load, with R10 at `074`. A breakpoint on `next` shows, at its first pause, R11 holding 96, which is `060`, the address of `count`. The log has 4 readings.

c2Hints.5: The whole answer: change `R10 <= R10 + 4` to `R10 <= R10 + 8`, and `R11 <= count` to `R11 <= word[count]`.

modelVsReality: The course's debugger can step back, because it keeps the states of the model. Most debuggers for real machines cannot; some record a run so it can be replayed.

Real programmers choose test inputs at the edges in the same way, and keep the ones that once found a mistake, so the mistake cannot come back unseen.
