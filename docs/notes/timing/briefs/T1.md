# Brief T1: timing diagrams only where time matters

Read `docs/style.md` first. Write each key from its facts alone. Answer in the form
`lesson/key: text`. A key marked "(replaces ...)" gives the exact words it replaces: write only
the new words. Code names go in backticks in prose, never in a label. "Timing diagram" is now a
rationed term: 4.1 `remember` introduces it (bold there, once), and no lesson before 4.1 may use the
words. The figures before 4.1 no longer draw one.

What the figures now do, checked in the code:

- A prediction of one setting with no clock (2.1, 2.2, 3.1's first, 3.2's first, 3.3, 3.4, 7.1,
  7.2, 9.1, 9.2), once checked, writes the run's values on the circuit drawn above the question, and
  a table under the drawing lists each signal's value. Nothing is drawn against time.
- A prediction of two settings of a circuit with no memory (2.3, 3.1's second, 3.2's second), once
  checked, shows a table with one row for each setting and one column for each signal.
- A timing diagram draws each signal as a line: high for 1, low for 0; a hatched band for X; a word
  (more than one bit) as a box with its value written in it. Above the lines, the axis names each
  step at the moment its inputs change ("kick", "release" in 4.1). A clock's rises are numbered from
  the last reset, ↑1, ↑2 and so on, and the reset's own rise is named as the reset; a clock step the
  lesson names keeps its own name ("edge" in 5.1). A red line stands at a moment, after the run's
  last step unless moved; the table under the diagram gives each signal's value at the red line.

## Shared strings (shown inside figures; plain text, no backticks)

- `shared/timing.resetRise` — the axis's label on a rise of the clock while RST is 1: the reset's
  rise. Very short, two or three words at most, may begin with ↑. No full stop.
- `shared/timing.cursorAt` — the name of the slider that moves the red line: says where the red
  line stands; `{where}` is one of the three below. No full stop.
- `shared/timing.valuesAfter` — the caption of the table under a timing diagram: the values where
  the red line stands; `{where}` as above. No full stop.
- `shared/timing.afterRun` — `{where}` when the red line is at the run's end: after the run.
- `shared/timing.afterMark` — `{where}` after a named step: after `{mark}`, where `{mark}` is a label
  such as "↑3" or "kick". Keep `{mark}`.
- `shared/timing.atStart` — `{where}` before the axis names any step: before the first step.
- `shared/timing.valuesHere` — the table's caption in 4.1's gate-delay figures, where the slider
  already gives the time in units: the values at the red line. No time in it. No full stop.
- `shared/prediction.settingsCaption` — the caption of the table of settings: each setting the run
  made, and what the circuit gave. No full stop.
- `shared/prediction.settingHeading` — that table's first column's heading: the setting. One word.
- `shared/prediction.setting` — a row's name when its step has none: setting `{n}`. Keep `{n}`.
