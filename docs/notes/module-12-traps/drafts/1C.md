explanation: The return point is the address C2 holds, and `resume` goes there. After a fault, the return point is the instruction that faulted.

The handler then has two choices:

- mend what went wrong, and run the instruction again. C2 stays as it is.
- skip the instruction. Add 4 to C2 before `resume`.

The night program's handler skips with `R5 <= C2`, `R5 <= R5 + 4` and `C2 <= R5`.

To the handler, C2 is a register like any other. It reads C2 with `R5 <= C2` and writes it with `C2 <= R5`. The same two jobs read and write C0, C1, C3 and C4.

With C4 at 0, as at reset, a trap has nowhere to go. The machine halts with the cause, as it did in every module before this one. Every program from Modules 8 to 11 ran with C4 at 0.

A trap at the address C4 holds also halts the machine. A handler that faults on its own first instruction would trap there for ever.

generalisation: Every cause goes to the same handler, at the address C4 holds. The handler reads C3 to tell the causes apart.

One handler address serves every cause on this machine. Some machines keep a table of addresses instead, one for each cause.

c2Hints.1: The idea: read the cause with `R5 <= C3` and compare it with `0x34` before doing anything else.

c2Hints.2: A common mistake: counting every trap. Only a refused store, cause `34`, is counted and skipped.

c2Hints.3: A smaller example: the night program's handler skips with `R5 <= C2`, `R5 <= R5 + 4` and `C2 <= R5` before `resume`.

c2Hints.4: Part of the answer: `R6 <= 0x34` then `if R5 != R6 goto other`, with `other: stop` at the end.

c2Hints.5: The whole answer:

```
        R1 <= handler
        C4 <= R1
        R1 <= 0
        word[0x400] <= R1       // the count of refused stores
        goto program
handler: R5 <= C3
        R6 <= 0x34
        if R5 != R6 goto other
        R5 <= word[0x400]
        R5 <= R5 + 1
        word[0x400] <= R5
        R5 <= C2
        R5 <= R5 + 4
        C2 <= R5
        resume
other:  stop
```

reflection: The night program did not use R5. The handler wrote R5 three times.

A handler runs in the middle of another program, which may keep its own words in R5.

What must a handler leave as it found it, and where can it keep words while it works?

modelVsReality: Real machines go to a handler as this one does: a register for the return point, one for the cause, and the handler's address.

Many keep a table of handler addresses, one for each cause, in memory.

This machine takes one edge for a trap, as it does for each instruction.
