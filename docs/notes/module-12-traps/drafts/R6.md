motivation: A handler can let interrupts in. It does this by writing 3, `11`, to C0. Then an interrupt can come while the handler runs.

A fault in the handler's own lines is a trap too. It can come whether interrupts are on or off.

A trap inside the handler is like any other trap. Its edge writes C2, C1, C0 and C3. The PC takes C4, the handler's address, so the handler starts again from its first line.

C2 holds the program's return point, and C1 holds the program's status. A trap inside the handler writes over both. Unless the handler saved them first, the way back to the program is lost.

explanation: A handler that lets interrupts in takes four steps:

- saves C1 and C2 in two RAM words of its own;
- writes 3 to C0;
- writes 1 to C0 when it is done, so nothing can come in while it puts C1 and C2 back;
- puts C1 and C2 back, then runs `resume`.

The handler saves R8 and R9 at its start, at `400` and `408`. A trap inside the handler saves them there again. So job 5 puts the program's R8 and R9 back before it lets interrupts in. After that it uses only R1 and R2, the call's own registers, which lesson 4 said a system call may change.

A fault in the handler has no fix of this kind. The handler must check what a program gives it, such as a room number, before it uses it.

An event that comes in while interrupts are off is not lost. Its bit in "waiting" stays set, as lesson 5 showed, until the handler clears it.

c2Hints.4: The whole answer: job 6, from `count:` to its `resume`, is this:

```
count:  R8 <= word[0x400]       // the program's R8 and R9 back now:
        R9 <= word[0x408]       // a trap in the count saves them again
        R1 <= C1
        word[0x410] <= R1       // save C1
        R1 <= C2
        word[0x418] <= R1       // save C2
        R1 <= 3
        C0 <= R1                // system mode, interrupts on
        R1 <= 0
next:   word[display] <= R2     // show the count
        R2 <= R2 - 1
        if R2 != R1 goto next
        R1 <= 1
        C0 <= R1                // interrupts off again
        R1 <= word[0x410]
        C1 <= R1                // C1 and C2 put back
        R1 <= word[0x418]
        C2 <= R1
        resume
```
