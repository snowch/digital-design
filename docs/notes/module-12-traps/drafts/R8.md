c1Hints.0: The idea: keep the number of the program running in the RAM word at `480`. The start reads that word, finds the program's address in the table, writes 0 to C1 and the address to C2, and runs `resume`.

c1Hints.1: A common mistake: running `stop` for job 4. That stops the machine. Job 4 ends the program, and the handler starts the next one.

c1Hints.2: A smaller example: a table named `t` holds its first word at `t` and its second at `t` plus 8, so `R1 <= t` then `R1 <= word[R1 + 8]` loads its second word.

c1Hints.3: Part of the answer: the program's address is the word at `programs + 8 + 8k`. Multiply k by 8 by adding it to itself three times: each addition doubles it. Add `programs`, then load with `word[R1 + 8]`.

c1Hints.4: The whole answer: the outline's lines, with these two parts in place of its stubs. The start, in place of `start:  stop`:

```
start:  R1 <= word[0x480]       // run program number R1, if there is one
        R2 <= word[programs]
        if R1 == R2 goto done
        R1 <= R1 + R1
        R1 <= R1 + R1
        R1 <= R1 + R1           // 8 × R1
        R2 <= programs
        R1 <= R1 + R2
        R1 <= word[R1 + 8]      // its address, from the table
        C2 <= R1
        R1 <= 0
        C1 <= R1                // user mode, interrupts off
        resume
done:   stop
```

And the end of a program, in place of `finish: stop` and `ended:  stop`:

```
finish: R9 <= 0                 // job 4: the program ended; its record is 0
ended:  R8 <= word[0x480]       // record R9 for program R8, at 0x400 + 8 × R8
        R1 <= R8 + R8
        R1 <= R1 + R1
        R1 <= R1 + R1
        word[R1 + 0x400] <= R9
        R8 <= R8 + 1
        word[0x480] <= R8       // the next program
        goto start
```
