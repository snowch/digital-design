motivation: The program asks the handler, which runs in system mode, to do a job for it. It asks with the line `call system`. That line traps on purpose, with cause `41`, and user mode allows it.

A trap that a program makes on purpose, to ask the handler for a job, is a **system call**.

The program says which job it wants in R1, and gives the job its word in R2. The handler leaves the result in R1. R1 and R2 are the calling convention's first registers, as they are for a function whose first argument names the job.

The table lists the jobs by number.

| R1 | What the handler does |
| --- | --- |
| 1 | Shows R2 on the display |
| 2 | Reads a room's sensor. R2 is 0 for room A and 1 for room B. The reading comes back in R1 |
| 3 | Sets the lamps from R2's bits: bit 0 ALARM, bit 1 NIGHT, bit 2 CLASH |
| 4 | Ends the program |

The handler reads C3 to tell a system call from a fault. Then it reads R1 to choose the job. It runs the job, then `resume`.

This lesson's handler offers jobs 1 and 4.

p1Explain: C2 holds `070`, the instruction after the call. A system call's return point is the next instruction, not the call. The job is done, and the program goes on from the next line.

After a fault, the return point is the instruction that faulted. Here that would be `06C`.

`01C` is the handler's address. The PC takes it.

timelineAfter: Each call's return point is the line after the call. The handler shows 25, then 26. Each `resume` takes the program back to user mode. Job 4 ends the run: the handler's `stop`, at `054`, runs. The run made 3 system calls in all. The saves at the handler's start show the program's own words: R8 holds 88 and R9 holds 99.

generalisation: A system call looks like a function call. R1 names the job and R2 gives it its word, as a function's arguments go in R1 to R4, and the result comes back in R1.

It differs in where the job runs. A function call stays in the program's mode. A system call crosses into system mode at its trap's edge, and back at `resume`'s edge.

It differs in which registers it may change. A function may change R0 to R9. A system call may change only R1 and R2, the call's own registers. Every other register comes back as it was.

The handler saves the registers it writes at its start, before it reads C3. The same handler takes faults. A fault can come at any line of a program, where any register may hold the program's words. Until it has read C3, the handler cannot tell a call from a fault. So it keeps every register but the call's own.

The handler decides what each job may do. A user program reaches the shop's devices only through the jobs the handler offers.

A job the handler does not offer does nothing. The handler puts R8 and R9 back and resumes.
