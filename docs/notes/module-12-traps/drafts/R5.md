unseenAfter: The program shows 30 and ends. The handler's `stop` for job 4 ends the run at `054`, after 92 instructions. The panel shows "Door opened: yes".

"waiting" is the word at `7F0`. It has one bit for each event: bit 0 for the timer, bit 1 for the door. The door opened after 15 instructions. Its bit was set at the edge that ended the 16th, the first instruction to run with the door open. Nothing cleared it, so bit 1 is still set.

No line of the program or the handler read the door. In user mode the program cannot touch a device, and the handler runs only when the program traps.

motivation: The machine can go to the handler without the program asking. At the edge that would run the next instruction, if a bit of "waiting" is set and C0's bit 1 is 1, the machine traps instead.

A trap that an event outside the program makes, between two of its instructions, is called an **interrupt**. C0's bit 1 says whether interrupts are on.

The cause says which event. `81` means the timer reached 0, and `82` means the door opened. If both bits are set, the two causes come at one edge, and the lower number wins: `81` goes first.

The interrupt's edge makes the five transfers every trap makes: C2, C1, C0, C3 and the PC. C0 takes `01`, so interrupts are off in the handler.

The handler clears an event's bit by storing 1 to it. Storing 1 to `waiting` clears the timer's bit, and storing 2 clears the door's. For the door, the handler sets `R8 <= 2`, then stores it with `word[waiting] <= R8`.

The start turns interrupts on for the program by writing 2 to C1 instead of 0. C1 is then `10`: bit 1 on, bit 0 off, user mode. `resume` then does what lesson 1 said: the PC takes C2, and C0 takes C1.

Interrupts are taken in user mode and in system mode alike, whenever C0's bit 1 is 1.

c2Hints.0: The idea: clear bit 0 of "waiting" by storing 1 to it. Read `signals`, keep bit 0 with `&`, and compare the result with 1. To light ALARM beside the other lamps, read the lamps, set bit 0 with `|`, and store them back.

c2Hints.1: A common mistake: storing 1 to the lamps. That lights ALARM but puts NIGHT out. Another is comparing all of `signals` with 1: on a warm night WARM's bit is set too, and the comparison fails.

c2Hints.2: A smaller example: to put ALARM out and leave the other lamps as they are, a part would read `word[lamps]`, `&` it with 6, and store the result back.

c2Hints.3: Part of the answer: the part starts as the figures' timer part does: `R8 <= 1`, `word[waiting] <= R8`, `R8 <= word[signals]`, `R9 <= 1`, `R8 <= R8 & R9`, then `if R8 != R9 goto back`.

c2Hints.4: The whole answer:

```
tick:   R8 <= 1
        word[waiting] <= R8     // the timer's event is seen
        R8 <= word[signals]
        R9 <= 1
        R8 <= R8 & R9           // DOOR
        if R8 != R9 goto back   // closed in time
        R8 <= word[lamps]
        R8 <= R8 | R9           // ALARM, beside the lamps already lit
        word[lamps] <= R8
        goto back
```
