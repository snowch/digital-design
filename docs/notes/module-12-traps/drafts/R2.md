explanation: A handler saves each register it writes, before it writes it, and puts it back before `resume`.

It saves a register with an absolute store, at an address the instruction's constant gives: `word[0x408] <= R5`. It puts the register back with `R5 <= word[0x408]`.

An absolute store needs no register to hold its address. So the handler can save R5 before it has changed any register, as its first line.

It cannot push on the stack. The stack belongs to the program, and R14 may be what went wrong, as the last figure showed.

The handler's words live at addresses it alone uses. Here `400` holds the count, and `408` holds R5.

The control registers are the handler's own. The program never sees them change.

generalisation: The calling convention lets a function change R0 to R9. That is R0, R1 to R4 for the arguments, R1 for the result, and R5 to R9 as free registers. The caller made the function call, so it knows those registers may change.

A program never knows a trap happened. So a handler keeps every register, R0 to R15, as it was.

Each register a handler writes costs two more instructions: a save and a put back. So a handler writes as few registers as it can.
