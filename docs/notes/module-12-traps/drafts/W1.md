motivation: In earlier modules, a fault was a broken part that a fault lab put in a circuit. Here the word describes an instruction: an instruction the machine refuses faults.

The store to room B's sensor faults.

Instead of halting, the machine can go to a program of its own. A program the machine goes to when an instruction faults is a **handler**.

Going to the handler in place of halting is a **trap**. The store traps instead of halting the machine.

Control register C4 holds the handler's address. A program sets it before anything faults, with `C4 <= R1`.

At the edge that ends the instruction that faults, five registers take new words:

- C2 takes the return point, where to go back to;
- C1 takes C0, the status, as it was;
- C0 takes `01`;
- C3 takes the cause;
- the PC takes C4, so the next instruction is the handler's first.

The instruction that faulted changes nothing else: no register, no memory, no device.

The handler reads the cause with `R5 <= C3`. It goes back with `resume`, which sets the PC to C2.

C0 and C1 say more in lesson 3. In this lesson C0 is `01` throughout.

investigation: The figure is a timeline of the night program and its handler. It lists the run's edges one at a time. On this machine, each edge runs one instruction or takes one trap.

Each edge says what ran, or that it trapped. It lists the transfers the edge makes, each with the word it takes, such as `C2 ← 014`.

An R register's word, or a word of memory, is a decimal number. From 10 to `7FF`, the page shows its hexadecimal beside it. C0 to C4 and the PC are written as the pages write them: an address has three hexadecimal digits, C0 and C1 are two bits, and a cause has two hexadecimal digits.

At edge 7 the handler reads cause `34` into R5. R5 shows 52 `034`, because `34` in hexadecimal is 3 × 16 + 4 = 52 in decimal. The cause has not changed. Only the way it is written has.
