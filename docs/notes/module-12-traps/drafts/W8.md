motivation: The text you write has five parts. The first is the start, which runs from reset. The other four are parts of the handler, the lines at the address C4 holds.

- The start sets C4 to the handler's address. Then it runs the program whose number the word at `480` holds, counting from 0. It finds the program's address in the table `programs`, which the tests add after your text. The table's first word is how many programs there are. Each program's address comes after it. It runs the program in user mode with interrupts off, by writing C1 and C2, then running `resume`.
- The choice is the handler's first part. It reads C3 to tell a system call from a fault. It reads R1 to find the job.
- The jobs are these. Job 1 shows R2. Job 2 puts a room's reading in R1. Job 3 sets the lamps from R2's bits 2 to 0. Job 4 ends the program.
- The end of a program stores its record at `400` plus 8 times its number. Then it moves to the next number and goes back to the start.
- The stop comes after the last program. It stops the machine.

The number lives in the RAM, in the word at `480`, because a register is a program's to change. The RAM is not protected either. A user program could store over that word, as lesson 3's program stored over the handler's count. The word at `480` is safe only from the program's registers.

Job 2 checks R2, because lesson 6 taught that a handler must not trust what a program gives it. R2 is 0 for room A and 1 for room B. Any other value puts 0 in R1, so no program can make the handler read a word that is not a sensor.

A job may change R1 and R2 only, the call's own registers, as lesson 4 said. The handler keeps every other register for the program.

c1Task:
1. Write a handler that runs each program the table `programs` names, in order, in user mode with interrupts off. The tests add the table and the programs after it.
2. Offer jobs 1 to 4 by `call system`. Job 1 shows R2. Job 2 puts a room's reading in R1: R2 is 0 for room A and 1 for room B. Any other R2 puts 0 in R1. Job 3 sets the lamps from R2's bits 2 to 0. Job 4 ends the program.
3. A program that faults ends there. For program k, counting from 0, store its record in the word at `400` plus 8 times k. Write it as `word[R1 + 0x400]`, with 8 × k in R1. The record is 0 if the program ended with job 4. If it faulted, the record is its cause itself.
4. A job may change R1 and R2 only. After the last program, the handler runs `stop`.
5. There are 7 tests. In them, room A reads -184 and room B reads -250. Each test checks the words shown, the lamps, each program's record, and that the run ends at the handler's `stop`. It also checks C1 at the end: the last program's status at its last trap, `00`. `00` means user mode with interrupts off.
6. Run 6's second program puts a word of its own in R0 and in each of R3 to R15. Its test also checks those registers as the program left them at its last trap, which is the `call system` for job 4.
