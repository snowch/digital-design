# Brief 3A: lesson `user-mode` (Module 12, lesson 3), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap** and
**handler** (never bold them). This lesson introduces **user mode** and **system mode**: set each
in bold where it is first used, in `motivation`, plain meaning first. Neither may appear in
`question`, `systemLead` or `systemAfter`.

Keys to write: `question`, `systemLead`, `systemAfter`, `motivation`, `prediction`,
`p1Question`, `p1Explain`.

## The program the first figure runs

```
000  R1 <= 1
004  word[lamps] <= R1   // ALARM on
008  R1 <= display
00C  R1 <= R1 + 8        // a mistake: one word past the display, the lamps
010  R2 <= 0
014  word[R1] <= R2      // meant to clear the display
018  stop
```

`display` is `7C0`; plus 8 is `7C8`, the lamps. The store at `014` writes 0 to the lamps, so
ALARM goes off. Nothing faults: the program stops at `018` after 7 instructions.

## question (about 80 words, above a figure)

1. Lesson 2 ended on a question: how could the machine keep a faulty program away from the shop's
   devices, and away from the handler?
2. The figure's program lights ALARM, as the shop's own work would when a room is too warm. Then
   it means to clear the display, but its address is one word too far on: the lamps.
3. Every program so far could store to any device, and write C4 too.

## systemLead (one sentence)

Press "Run to the end" and watch the lamps.

## systemAfter (about 60 words, shown once the run has ended)

1. ALARM goes off at `014`, and the program stops at `018`. The machine refused nothing.
2. A store to the lamps is allowed, so nothing traps and no handler runs.
3. A shop that relies on ALARM cannot let any program switch it off.

## motivation (about 170 words; a short list allowed)

1. C0's bit 0 is the mode. When it is 1, the machine is in **system mode**: it runs every
   instruction, as every program so far has run.
2. When it is 0, the machine is in **user mode**, and it refuses (list):
   - `resume`, the two control-register jobs, and `stop`: cause `22`;
   - every load or store at a device's address, `7C0` and up: cause `32`.
3. Every other instruction runs as before, in the ROM and the RAM.
4. A trap's edge sets C0 to `01`, so the handler always runs in system mode, and C1 keeps the mode
   the program was in.
5. The handler starts a program in user mode with lesson 1's `resume`: it writes 0 to C1 and the
   program's address to C2, then runs `resume`. C0 takes C1, and the PC takes C2.
6. A user program cannot change C0 back: the line that would do it, `C0 <= R1`, is refused.

## prediction (about 50 words, above the figure)

1. The figure lists the handler's start and the same faulty program, now named `program`.
2. The handler lights ALARM, writes 0 to C1 and `program`'s address to C2, and runs `resume`.
3. Its handler keeps the cause at `400` and the return point at `408`, then stops.
4. Choose an answer and press "Check my prediction".

## p1Question (one sentence)

Just after the store to the lamps traps, what does C1 hold?

## p1Explain (about 60 words)

1. C1 holds `00`: C0 as it was when the store faulted, user mode with bit 1 at 0.
2. In lesson 1, C1 always took `01`, because every program ran in system mode.
3. C0 takes `01` at the trap's edge, so the handler runs in system mode.
