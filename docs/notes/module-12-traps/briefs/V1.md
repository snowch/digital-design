# Brief V1: Module 12's figure words (the debugger, the timeline, the memory map)

Read `00-module.md` (the shared fact sheet) first; it applies here, with one change: these words
appear on every Module 12 page, so you may use **trap**, **handler**, **user mode**, **system
mode** and **interrupt**, never bold. Each key is a short label or one sentence. A label has no
full stop; a sentence has one. Placeholders in braces, such as `{address}`, stay exactly as given:
the page puts a value there.

Some keys are fixed because the lessons' text already names them. Give these exactly as written:
`nextEdge`: Next edge. `backEdge`: Step back. `toEnd`: Run to the end. `eventsCaption`: The timer
and the door. `timerReached`: Timer reached 0. `doorOpened`: Door opened. `doorChoice`: When the
door opens. `doorNever`: never.

## The debugger's control registers panel

- `controlCaption`: the panel's title: the control registers.
- `controlNames.1` to `controlNames.5`: each register's job, shown after its name (C0 ... C4):
  status; status before the trap; return point; cause; handler's address.
- `systemMode`, `userMode`: the mode in words, as C0's or C1's bit 0 gives it: system mode; user
  mode.
- `interruptsOn`, `interruptsOff`: C0's or C1's bit 1 in words.
- `trapped`: one sentence, shown after a step or a run when an instruction trapped: the
  instruction at `{address}` trapped with cause `{cause}`, and the machine went to the handler at
  `{handler}`.
- `interrupted`: one sentence, the same for an interrupt: before the instruction at `{address}`
  ran, an interrupt with cause `{cause}` came, and the machine went to the handler at `{handler}`.
- `trapCount`: `{n}` traps went to the handler (said after "N instructions ran."). `trapCountOne`:
  the same for 1.
- `stops.cause22`, `stops.cause32`, `stops.cause81`, `stops.cause82`: one sentence each, when the
  machine halts with no handler set (C4 is 0). Module 11's form, which these must follow: "The
  machine halted with cause 34: the instruction at {address} stored to the ROM or to a sensor."
  Facts: `22`, the instruction at `{address}` is one user mode refuses (`resume`, a
  control-register job or `stop`); `32`, the instruction at `{address}` reached a device's address
  in user mode; `81`, the timer reached 0 before the instruction at `{address}`; `82`, the door
  opened before the instruction at `{address}`.
- `stops.unknown-control`: Module 11's form: "The debugger ended the run before the instruction at
  {address}: the address needs {reg}, which nothing has set." Fact: the instruction copies `{reg}`
  into a control register, and nothing has set `{reg}`.

## The debugger's panel "The timer and the door"

- `timer`: the timer's count, labelled: Timer.
- `yes`, `no`: the answers beside "Timer reached 0" and "Door opened".
- `open`, `closed`: DOOR's state.
- `doorBefore`: one option of "When the door opens": the door opens once `{n}` instructions have
  run. Write it as a short phrase: after `{n}` instructions.

## The trap timeline

- `timelineTitle`: the timeline's title: the run, edge by edge.
- `reset`: the button that clears the timeline back to before the first edge. (The datapath
  figures call theirs "Start again".)
- `noEdge`: shown before the first edge: no edge yet.
- `noLine`: the timeline's words for an address no line of the program names (a word of data or
  of 0s), used in place of the line's text: the word.
- `edge`: Edge `{n}`.
- `runs`: `{line}`, at `{address}`, runs.
- `traps`: `{line}`, at `{address}`, traps with cause `{cause}`.
- `interrupts`: `{line}`, at `{address}`, does not run: an interrupt with cause `{cause}` comes
  first.
- `resumes`: `resume`, at `{address}`, runs.
- `halts`: `{line}`, at `{address}`: the machine halts with cause `{cause}`.
- `stopsAt`: `stop`, at `{address}`: the program stops.
- `transfersLabel`: the label before an edge's transfers: at this edge.
- `nothingChanges`: an edge with no transfer: nothing changes.
- `modeAfter`: after an edge: then, `{mode}`. (`{mode}` is "user mode" or "system mode", with
  "interrupts on" or "interrupts off" after a comma on lessons 5 on.)

## The memory map

- `mapCaptionUser`: the memory map's caption when it shows what user mode does with each access.
