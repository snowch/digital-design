## The run the investigation shows (the whole handler, on the first run)

The debugger runs the whole handler with the first run's programs: `showA` shows 25 and ends;
`showB` reads room B with job 2, shows -250 and ends. Breakpoints are on `start:`, the handler's
start of each program, and `ended:`, where a program's record is written. It shows R1, R2, R8
and R9, the control registers with the mode in words, the records at `400` and `408`, and the
program's number at `480`. Facts: 128 instructions ran and 5 traps went to the handler, all
`call system`; the display showed 25, then -250; both records are 0; the word at `480` ends at 2;
the handler stops at `044`, its `done:` line.

## The handler the failure experiment runs

The whole handler, but its fault part skips the faulting instruction (adds 4 to C2 and resumes),
as lesson 1's handler did, instead of ending the program. Facts: runs 1, 4 and 6 match. Run 2:
the store to the display is skipped, `direct` ends with job 4, so its record is 0, not 50; 8 is
still shown. Run 3: the refused `stop` is skipped, and the run goes on past the program's end
onto words that are not instructions, each one skipped in turn: the debugger cuts the run off
after 5000 instructions. Run 5: the word that is not an instruction is skipped, with the same
result: cut off after 5000.

## failureExperiment (about 40 words)

   handler did, on the six runs.
