## c1Task (numbered list)

1. On this machine, how many edges does each take, counting the edge that traps:
   - a `call system`;

The answers (for your hints): 2, 3, 1, 4.

## c1Hints (five, in this order)

1. The idea: an edge that traps is the last edge of its instruction. Find the state where each
   cause appears.
2. A common mistake: counting a trap as an edge of its own. It ends the instruction's last state.
3. A smaller example: the store in the first figure took FETCH, READ, ALU and MEMORY, and trapped
   at MEMORY: 4 edges.
4. Part of the answer: the decoder's causes, `41` among them, appear in READ. An interrupt is taken
   at the edge that would fetch.
5. The whole answer: 2, 3, 1 and 4.

## The faults the failure experiment offers

- **TRAP stuck at 0.** At the store's MEMORY edge the trap logic still sets GO to 0, but nothing
  takes the trap: the controller stays in MEMORY, the PC stays at `014`, and the machine neither
  traps nor halts. Every edge after edge 24 writes nothing.
- **The control registers' write enable stuck at 0** (CWEN, at the control registers). `C4 <= R1`
  writes nothing, so C4 stays 0: there is no handler. At the store's MEMORY edge the trap logic
  sets HALT to 1: the machine halts with cause `34` at `014`, as Module 11's machine did.

## faultCwen (about 50 words, shown with the second fault)
