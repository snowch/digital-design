## motivation (about 90 words)

1. A handler runs in the middle of another program. That program did not call it and cannot tell
   that it ran.
2. So the handler must leave every register, R0 to R15, as it found it.
3. It saves each register it writes in the RAM, and puts each one back before `resume`.
4. C2 is the exception, and the handler writes it on purpose. Its new word in C2, the return point
   plus 4, is the skip. The program does not use C2.
5. Do not say how or where the handler saves a register: the prediction asks about that.

## prediction (about 40 words)

1. The figure lists the same program with a new handler, which saves R5 in the RAM and puts it
   back before `resume`.
2. Do not say which line saves R5, or when.
3. Last sentence: Choose an answer and press "Check my prediction".

## explanation (about 130 words)

1. A handler saves each register it writes, before it writes it, and puts it back before
   `resume`.
2. It saves a register with an absolute store, at an address the instruction's constant gives:
   `word[0x408] <= R5`. It puts the register back with `R5 <= word[0x408]`.
3. An absolute store needs no register to hold its address. So the handler can save R5 before it
   has changed any register, as its first line.
4. It cannot push on the stack. The stack belongs to the program, and R14 may be what went wrong,
   as the last figure showed.
5. The handler's words live at addresses it alone uses: here `400` for the count and `408` for
   R5.
6. The control registers are the handler's own: the program never sees them change.

## timelineLead (about 60 words; it may be numbered steps)

The figure: the trap timeline of the same run with the saving handler. Its first "Next edge"

2. Edge 13: `resume` makes two transfers: C0 ← `01` (C1's word) and PC ← `014`.
3. In between, each of the handler's edges makes one or two transfers: a register or a word, and

## generalisation (about 90 words)

1. The calling convention lets a function change R0 to R9: R0, R1 to R4 (its arguments and its
   result) and R5 to R9. The caller made the call, so it knows those registers may change.
2. A program never knows a trap happened. So a handler keeps every register, R0 to R15, as it
   was.
3. Each register a handler writes costs two more instructions: a save and a putting back. So a
   handler writes as few registers as it can.

## c2Task (a numbered list)

1. The starting text's handler counts each refused store in the word at `400` (`word[0x400]`) and
   skips it. It writes R5 and does not save it.
2. Change the handler so that every register, R0 to R15, holds after `resume` what it held before
   the trap. The count and the skip must still work.
3. There are 3 tests. Each adds a program after yours, named `program`. Each program puts its own
   words in R0 to R15 (11, 22 and so on up to 176), then makes one or two stores the machine
   refuses, then stops at its last line, `end: stop`.
4. One program first sets R14 to `0x400` and pushes, so its push faults in the ROM; its R14 then
   holds `3F8`.
5. Each test checks the count at `400`, every register from R0 to R15, the causes in order, and
   that the run stops at the program's `end`.
