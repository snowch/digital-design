# Brief W1: lesson `traps` (lesson 1), after the second reading

Read `00-module.md` first, including "Decisions after the reading review". You may use **trap**
and **handler** (the motivation bolds each once, as now). Each key replaces the page's text.
Write each from its facts alone.

Keys: `motivation`, `investigation`, `c1Task`, `c1Hints.4`, `c2Task`, `c2Hints.3`.

## motivation (about 180 words; one list)

1. In earlier modules a fault was a broken part a fault lab put in a circuit. Here the word is
   used of an instruction: an instruction the machine refuses **faults**. Say this once, plainly.
   (Not bold: "fault" is not this lesson's term. Write it as `faults` in plain text, no bold.)
2. The store to room B's sensor faults.
3. Instead of halting, the machine can go to a program of its own. A program the machine goes to
   when an instruction faults is a **handler** (bold).
4. Going to the handler in place of halting is a **trap** (bold). The store traps instead of
   halting the machine.
5. Control register C4 holds the handler's address. A program sets it before anything faults,
   with `C4 <= R1`.
6. At the edge that ends the instruction that faults, five registers take new words (a list):
   - C2 takes the return point, where to go back to;
   - C1 takes C0, the status, as it was;
   - C0 takes `01`;
   - C3 takes the cause;
   - the PC takes C4, so the next instruction is the handler's first.
7. The instruction that faulted changes nothing else: no register, no memory, no device.
8. The handler reads the cause with `R5 <= C3`. It goes back with `resume`, which sets the PC to
   C2.
9. C0 and C1 say more in lesson 3. In this lesson C0 is `01` throughout.

## investigation (about 100 words)

1. The figure is a timeline of the night program and its handler. It lists the run's edges one at
   a time. On this machine each edge runs one instruction, or takes one trap.
2. Each edge says what ran, or that it trapped, and lists the transfers it makes, each with the
   word it takes, such as `C2 ← 014`.
3. An R register's word, or a word of memory, is shown as a decimal number; from 10 to `7FF` its
   hexadecimal is shown beside it. (C0 to C4 and the PC are written as the pages write them: an
   address in three hexadecimal digits, C0 and C1 as two bits, a cause in two hexadecimal digits.)
4. At edge 7 the handler reads cause `34` into R5, and R5 shows 52 `034`: `34` in hexadecimal is
   3 × 16 + 4 = 52 in decimal. The cause has not changed; only the way it is written has.

## c2Task (a numbered list)

1. Write a handler that skips every store the machine refuses with cause `34`, and counts them in
   the word at `400`, which you write `word[0x400]`.
2. On any other cause, the handler runs `stop`, which ends the run.
3. The starting text sets C4, sets the count to 0 and goes to `program`. Its handler only resumes.
4. There are 5 tests. Each adds its own program after yours, named `program`, and runs all of it
   from reset.
5. In tests 1 and 2 the program carries on after its refused stores and ends at its own last line,
   named `end`, a `stop`. In each of them the line after the last refused store is named `after`,
   and the test checks that C2 holds that line's address when the run ends.
6. In tests 3, 4 and 5 the program meets another cause, and the run must end at your handler's
   `stop`.
7. Every test checks the count, the display, how many traps went to the handler, the causes in
   order, and where the run stops.
8. Do not give your own lines the names `program`, `end` or `after`: the tests' lines use them.
