# Brief 3B: lesson `user-mode` (Module 12, lesson 3), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap**,
**handler**, **user mode** and **system mode** (never bold them).

Keys to write: `investigation`, `timelineLead`, `timelineAfter`, `construction`, `answersLead`,
`c1Task`, `c1Hints.1` to `c1Hints.5`, `failureExperiment`, `ramLead`, `ramAfter`.

## The program the investigation runs

```
000  R1 <= handler
004  C4 <= R1
008  R1 <= 1
00C  word[lamps] <= R1      // ALARM on
010  R1 <= 0
014  C1 <= R1               // user mode, for the program resume starts
018  R1 <= program
01C  C2 <= R1
020  resume                 // C0 takes C1: user mode
024  handler: R5 <= C3
028  word[0x400] <= R5      // keep the cause
02C  R5 <= C2
030  word[0x408] <= R5      // and where
034  stop
038  program: R1 <= display
03C  R1 <= R1 + 8
040  R2 <= 0
044  word[R1] <= R2         // meant to clear the display
048  stop
```

The timeline's edges, from edge 5: edge 6 `C1 <= R1`: C1 ← `00`; edge 8 `C2 <= R1`: C2 ← `038`;
edge 9 `resume`: C0 ← `00`, PC ← `038`, and after it the machine is in user mode. Edges 10 to 12 run the program's first three lines. Edge 13: the store at `044` traps with
cause `32`: C2 ← `044`, C1 ← `00`, C0 ← `01`, C3 ← `32`, PC ← `024`; after it, system mode.
Edges 14 to 18: the handler keeps 50 (`32`) at `400` and 68 (`044`) at `408`, and stops at `034`.
ALARM stays on. (The timeline writes the mode after each edge: "Then: user mode." C0's bit 1 is 0 throughout
this lesson; do not mention it.)

## investigation (about 40 words)

1. The timeline runs the handler's start and the program, from the edge before C1 is written.
2. After each edge it says the mode the machine is in.

## timelineLead (numbered steps, about 50 words)

1. Step to `resume`'s edge and read the mode after it.
2. Step through the program's lines to the store to the lamps, and watch which five registers
   change when it traps.
3. Step on to the end.

## timelineAfter (about 70 words, shown once the learner has stepped to the last edge)

Give the facts above briefly: `resume` sets C0 to `00` and the PC to `038`, so the program runs in
user mode; the store at `044` traps with cause `32`, and C1 keeps `00`; the handler runs in system
mode, keeps the cause and the return point, and stops at `034`; ALARM is still on.

## construction (about 40 words)

You can tell what user mode does with an instruction from its address and its job alone, without
running it.

## answersLead (one sentence)

Work out each answer, then run the tests.

## c1Task (numbered list)

1. A program runs in user mode. For each line, give the cause it traps with, in hexadecimal, or 0
   if user mode runs it:
   - `R2 <= word[sensorA]`;
   - `word[0x400] <= R2`;
   - `stop`;
   - `R3 <= word[timer]`.
2. There are 4 tests, one for each line.

The answers (for your hints): `32`, 0, `22`, `32`.

## c1Hints (five, in this order)

1. The idea: user mode refuses any load or store at a device's address with cause `32`, and
   `resume`, the control-register jobs and `stop` with cause `22`.
2. A common mistake: thinking a load is allowed. User mode refuses a device's address for loads as
   well as stores.
3. A smaller example: the program's store to the lamps, at `7C8`, trapped with cause `32`.
4. Part of the answer: `400` is in the RAM, which user mode reaches as system mode does.
5. The whole answer: `32`, 0, `22` and `32`.

## The program the failure experiment runs

The handler's start, as before, but it also writes 0 to the word at `410`: no traps tonight. Its
handler counts the night's traps: it adds 1 to the word at `410` and shows it on the display, then
stops. The program, in user mode: `R3 <= 0x410`, `R4 <= 7`, `word[R3] <= R4` (its own total, at an
address the handler also uses), then `stop`. The store to `410` is in the RAM, so user mode runs
it. The `stop` traps with cause `22`. The handler adds 1 to the 7 it finds, so the display shows 8
instead of 1. ALARM stays on.

## failureExperiment (about 60 words)

1. The handler keeps a count of the night's traps in the word at `410`, and shows it after each
   trap.
2. The program keeps its own total in the RAM too, at `410` by chance.
3. The figure shows the word at `410`, and C0 and C1 in words.

## ramLead (one sentence)

Predict what the display shows, then press "Run to the end".

## ramAfter (about 70 words, shown once the run has ended)

1. The display shows 8, not 1.
2. The program's store to `410` ran in user mode: the RAM is not protected. It wrote 7 over the
   handler's count.
3. The program's `stop` trapped with cause `22`, and the handler added 1 to the 7.
4. The machine protects its devices and its control registers. It does not protect the RAM.
