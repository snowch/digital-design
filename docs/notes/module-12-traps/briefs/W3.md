# Brief W3: lesson `user-mode` (lesson 3), after the second reading

Read `00-module.md` first, including both "Decisions" sections. You may use **trap**, **handler**,
**user mode** and **system mode**, not bold outside the motivation. Each key replaces the page's
text. Write each from its facts alone.

Keys: `p1Explain`, `investigation`, `timelineAfter`, `c2Task`, `c2Hints.0`, `c2Hints.1`.

## p1Explain (about 90 words)

1. C1 holds `01` just after the store traps. That is C0 as it was when the store faulted.
2. `goto` changes only the PC, so C0 was still `01`, and the program ran in system mode. The `00`
   the start wrote to C1 was never used: the trap's edge wrote over it.
3. The cause is `34`, a store to a read-only device, not `32`. In system mode the store is
   refused because the sensor is read only, not because of the mode.
4. `resume` is the way these pages enter user mode: at one edge it copies C1 into C0 and C2 into
   the PC, so the mode changes at the same edge as the program's first line is reached. (Do not
   say it is the only way.)

## investigation (about 60 words)

1. The timeline runs a start that does use `resume`.
2. The start lights ALARM first, at edge 4, as the shop's own work would, then writes `00` to C1
   and the program's address to C2.
3. Its program is the first figure's program less its first two lines: it no longer lights ALARM
   itself, and it is named `program`.
4. The timeline begins at edge 5, the edge before the start writes C1. After each edge it says
   which mode the machine is in.

## timelineAfter (about 60 words)

1. `resume` sets C0 to `00` and the PC to `038`, so the program runs in user mode.
2. The store at `044` traps with cause `32`. At that edge C1 takes C0 again, which is `00`: the
   mode the program was in.
3. The handler runs in system mode. It stores the cause at `400` and the return point at `408`.
4. It ends with `stop` at `034`. ALARM is still on.

## c2Task (a numbered list)

1. The starting text's start sets C4, sets the count in the word at `400` to 0, and goes to
   `program` with `goto`. Its handler only runs `stop`.
2. Change the start so that `program` runs in user mode.
3. Write the handler. On cause `32`, which means a device's address was refused, it adds 1 to the
   count at `400` and skips the instruction. On any other cause, it stores the cause in the word
   at `408`, then runs `stop`.
4. The count is `word[0x400]`, and the stored cause is `word[0x408]`, as you type them.
5. The handler must leave every register, R0 to R15, as it found it, as in lesson 2.
6. There are 4 tests. Each adds a program after yours, named `program`. Each program puts a word
   of its own in every register, R0 to R15, a different set in each test, then reaches a device
   or does something else that user mode or the machine refuses.
7. Each test checks C1 at the end of the run, which holds the program's mode at its last trap. It
   checks the count at `400`, the stored cause at `408`, every register R0 to R15 as the program
   left it at its last trap, the causes in order, and that the run ends at the handler's `stop`.

## c2Hints.0 ("The idea:", two short sentences)

1. A start enters user mode with `resume`, after it writes `00` to C1 and the program's address to
   C2.
2. The handler saves the registers it writes, reads C3, and compares it with `0x32`.

## c2Hints.1 ("A common mistake:", two short sentences)

1. `goto program`. The program then runs in system mode, as the prediction above showed.
2. A store to the lamps is then allowed: the run gives no cause `32`, and the count stays 0.
