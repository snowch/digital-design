## The program the figures run (the night program with its handler)

```
000  R1 <= handler
004  C4 <= R1
008  R2 <= word[sensorA]
00C  word[display] <= R2
010  R0 <= 0
014  word[sensorB] <= R0     // the mistake
018  R3 <= 2
01C  word[lamps] <= R3       // NIGHT
020  stop
024  handler: R5 <= C3
028  word[0x400] <= R5       // keep the cause
02C  R5 <= C2
030  R5 <= R5 + 4            // the instruction after the one that faulted
034  C2 <= R5
038  resume
```

The run, edge by edge, as the timeline lists it (room A -184, room B -250):

- Edges 1 to 5 run `000` to `010`. Edge 2 is `C4 <= R1`: C4 ← `024`.
- Edge 6: the store at `014` traps with cause `34`. Its transfers: C2 ← `014`, C1 ← `01`,
  C0 ← `01`, C3 ← `34`, PC ← `024`.
- Edges 7 to 11 run the handler: R5 ← 52 (`34` read as a decimal number), the word at `400` ← 52,
  R5 ← 20 (`014`), R5 ← 24 (`018`), C2 ← `018`.
- Edge 12: `resume` at `038`. Its transfers: C0 ← `01` (it takes C1) and PC ← `018` (it takes C2).
- Edges 13 to 15: `R3 <= 2`, the store that lights NIGHT, and `stop` at `020`. The program stops.
- In all: 15 edges, 14 instructions run and 1 trap. The display shows -184 and NIGHT is on.

## c1Task (numbered list)

1. Just after the load traps, give in hexadecimal:
   - what C2 holds;
   - what C3 holds;
   - what C1 holds;
   - what the PC holds.
2. Write C2 and the PC as three hexadecimal digits, C3 and C1 as two. There are 4 tests, one for
   each answer.

The program (for your own working; do not reproduce it): `000 R1 <= handler`, `004 C4 <= R1`,
`008 R2 <= lamps`, `00C R2 <= R2 + 4`, `010 R3 <= word[R2]`, `014 word[display] <= R3`,
`018 stop`, `01C handler: R5 <= C3`, `020 word[display] <= R5`, `024 stop`. The answers are C2
`010`, C3 `33`, C1 `01`, PC `01C`.

## c1Hints (five, in this order)

1. The idea: at the trap's edge, C2 takes the return point, C1 takes C0, C3 takes the cause and the
   PC takes C4.
2. A common mistake: giving C2 the address of the next instruction. After a fault, the return
   point is the instruction that faulted.
3. A smaller example: in the night program, the store at `014` trapped with C2 ← `014`,
   C3 ← `34`, C1 ← `01` and PC ← `024`.
4. Part of the answer: the load is at `010`, and C1 takes C0, which is `01` throughout this
   lesson.
5. The whole answer: `010`, `33`, `01` and `01C`.

## noSkipAfter (about 80 words, shown once the run has ended)

1. The debugger cuts the run off after 5000 instructions. NIGHT never lights.
2. C2 still holds `014` when `resume` runs, so the PC goes back to the store to room B's sensor.
3. The store faults again, and traps again, and the handler resumes it again. The run goes round
   for ever.
4. After a fault, a handler must mend what went wrong, or add 4 to C2 to skip the instruction.
