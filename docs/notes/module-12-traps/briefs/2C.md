# Brief 2C: lesson `saving-state` (Module 12, lesson 2), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap** and
**handler** (never bold them). This lesson introduces no term.

Keys to write: `explanation`, `timelineLead`, `generalisation`, `saveLead`, `c2Task`,
`c2Hints.1` to `c2Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 120 words)

1. A handler saves each register it writes, before it writes it, and puts it back before `resume`.
2. It saves with absolute stores, at addresses the constant gives, such as `word[0x408] <= R5`. An
   absolute store needs no register, so the handler trusts nothing the program left in its
   registers.
3. It cannot push on the stack: the stack is the program's, and R14 may be what went wrong, as the
   last figure showed.
4. The handler's words live at addresses it alone uses. The C registers are the handler's own: the
   program never sees them change.

## timelineLead (about 40 words)

1. The figure shows the run with the saving handler, edge by edge, from the edge before the trap.
2. Watch the word at `408` take -184 at the handler's first edge, and R5 take it back at the edge
   before `resume`.

## generalisation (about 100 words)

1. The calling convention lets a function change R5 to R9: the caller knows it made a call.
2. A program never knows a trap happened, so a handler keeps every register, R0 to R15, as it was.
3. Each register a handler writes costs two more instructions, a save and a putting back. So a
   handler writes as few registers as it can.
4. Where it keeps saved words matters as much as saving them: in the RAM, at addresses chosen for
   the handler.

## saveLead (one sentence)

Write the handler, step through it on the tests' programs, then run the tests.

## c2Task (numbered list)

1. The starting text's handler counts each refused store in the word at `0x400` and skips it. It
   writes R5 and does not save it.
2. Change the handler so that every register the program used holds, after `resume`, what it held
   before the trap. The count and the skip must still work.
3. There are 3 tests. Each adds a program after yours, named `program`. Each program puts its own
   words in R1 to R9 (11, 22 and so on up to 99), then makes one or two stores the machine
   refuses, then stops. One program first sets R14 to `0x400`, so its push faults in the ROM.
4. Each test checks the count at `0x400`, the words in R1 to R9, and that the run ends at the
   program's `stop`.

## c2Hints (five, in this order)

1. The idea: save R5 with an absolute store before the handler's first write, and put it back
   just before `resume`.
2. A common mistake: saving R5 on the stack. One test's stack has reached the ROM, and the save
   would fault.
3. A smaller example: the investigation's handler saves R5 with `word[0x408] <= R5` first and
   puts it back with `R5 <= word[0x408]` last.
4. Part of the answer: the count lives at `0x400`, so the saved word needs an address of its own,
   such as `0x408`.
5. The whole answer:

```
        R1 <= handler
        C4 <= R1
        R1 <= 0
        word[0x400] <= R1       // the count of refused stores
        goto program
handler: word[0x408] <= R5      // save R5
        R5 <= word[0x400]
        R5 <= R5 + 1
        word[0x400] <= R5
        R5 <= C2
        R5 <= R5 + 4
        C2 <= R5
        R5 <= word[0x408]       // put R5 back
        resume
```

## reflection (about 70 words; end on the question)

1. The handler keeps the program's registers safe, and skips the program's mistakes.
2. But the program in this lesson ran with the machine's full reach: a stray store could change the
   lamps, the timer, or C4, the handler's address, before it faulted.
3. End on the question: how could the machine keep a faulty program away from the shop's devices,
   and away from the handler?

## modelVsReality (about 60 words)

1. Real handlers save registers as this one does, in memory set aside for them.
2. Many real machines give the handler a stack of its own, separate from the program's, which this
   machine does not have.
3. Saving and putting back a register costs a handler two memory accesses each time, so real
   handlers save only what they use.
