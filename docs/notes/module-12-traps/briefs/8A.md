# Brief 8A: lesson `system-call-mechanism` (Module 12, lesson 8, the module's capstone), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap**,
**handler**, **user mode**, **system mode**, **system call** and **interrupt** (never bold them).
This lesson introduces no term.

Keys to write: `question`, `asksLead`, `asksAfter`, `motivation`, `prediction`, `p1Question`,
`p1Explain`.

## Facts every part of this lesson may use

- **The task.** A handler that runs the shop's programs. The tests add, after the handler, a
  table named `programs`: its first word is how many programs, then each program's address, as
  `word` data: `programs: word 2, showA, showB`. Then the programs themselves.
- The handler sets C4, then runs each program in the table in turn, from the first, in user mode
  with interrupts off. It offers lesson 4's four jobs by `call system`: 1 shows R2; 2 puts a
  room's reading in R1 (R2 is 0 for room A, 1 for room B; any other R2 gives 0, so no program can
  make the handler read a word that is not a sensor); 3 sets the lamps from R2's bits 2 to 0; 4
  ends the program.
- A program that faults ends there. Its cause is its **record**: for program k (counting from 0),
  the word at `0x400 + 8k` holds 0 if it ended with job 4, or its cause, as a decimal number,
  if it faulted. Cause `32` is 50 as a decimal number; `22` is 34; `21` is 33.
- After the last program, the handler stops the machine.
- The handler keeps every register but R1 for the program across a job, as lessons 2 and 4
  taught. It keeps its own count, the number of the program running, in the word at `0x480`,
  because a register would be a program's to change.
- The tests: six runs. Room A reads -184 and room B -250. Each test checks the words shown, in
  order, the lamps, each program's record, and that the run ends at a `stop`.
  1. two programs that end with job 4: one shows 25, one shows room B's reading: 25, -250;
  2. a program that stores to the display itself, then one that shows 8: records 50 and 0;
  3. a program that lights NIGHT with job 3, then one that runs `stop`: lamps 2 (NIGHT), records
     0 and 34;
  4. a program that keeps 77 in R10 across a job: shows 5, then 77;
  5. a program that asks job 2 for room 5, which shows 0, then a table entry whose word is not an
     instruction: records 0 and 33;
  6. an empty table: the handler stops at once.

## The first figure

It runs a starting handler, the guided start, on the six runs. The guided start has the handler's
start (the loop that runs program number word `0x480`) and its choice of job, with job 1; its jobs
2 and 3 do nothing (job 2 leaves R1 at 0), and job 4 and a fault both run `stop`. Each run is a
card: what the test asks, and, once run, what the handler left, with a sentence saying whether
they match. What it left: run 1 shows 25, then stops (job 4 stops the machine instead of running
the next program); run 2 shows nothing (the fault stops the machine); run 3 leaves the lamps at
0; run 4 shows 5 and 77 but leaves no records; run 5 shows 0, then stops; run 6 matches.

## question (about 90 words, above a figure)

1. Lesson 7 ended on a question: can you write the handler that runs the shop's programs, one
   after another, each in user mode, giving them the jobs of lesson 4?
2. Say the task in two sentences from the facts above: a table of programs; each in user mode, in
   order; jobs 1 to 4; a record for each; stop after the last.
3. The figure runs a handler that does part of it on the six runs the tests use.

## asksLead (one sentence)

Read what each run asks, then press the button and compare what this handler left.

## asksAfter (about 70 words)

The facts of what the guided start left, above, briefly; only the empty table matches.

## motivation (about 200 words; a short list allowed)

The handler's parts, as a list, from the facts: the start (sets C4, runs program number `0x480`
by writing C1 and C2 and running `resume`); the choice (C3 tells a system call from a fault, R1
the job); the four jobs; the end of a program (record, next number, back to the start); the stop
after the last. Then: why the program's number lives in RAM; why job 2 checks R2 (lesson 6: a
handler must not trust what a program gives it); every register but R1 kept across a job.

## prediction (about 50 words)

1. The figure lists the whole handler, with the second run's two programs after it: `direct`
   stores 7 to the display itself; `after` shows 8 and ends.
2. Choose an answer and press "Check my prediction".

## p1Question (one sentence)

When the run ends, what does the word at `400`, the first program's record, hold, as a decimal
number?

## p1Explain (about 70 words)

1. 50: cause `32`, a device's address in user mode, written as a decimal number.
2. 32 is the cause's hexadecimal digits read as a decimal number. 0 would mean the program ended
   with job 4, which it never reached. 34 is cause `22`, a refused `stop`.
3. The second program still ran and showed 8.
