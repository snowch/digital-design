## The program the investigation runs

The same program as the lesson's first figure (room A's reading kept in R5; the store to room B's
sensor at `010` traps), with a handler at `01C` that saves R5 first:

```
01C  handler: word[0x408] <= R5     // save R5
020  R5 <= C3
024  word[0x400] <= R5
028  R5 <= C2
02C  R5 <= R5 + 4
030  C2 <= R5
034  R5 <= word[0x408]             // put R5 back
038  resume
```

Run with room A at -184: the word at `408` takes -184 at `01C`; R5 takes 52, 16 (`010`) and 20
(`014`); at `034` R5 takes -184 back; `resume` goes to `014`; the display shows -184; the
program stops at `018` after 14 instructions and 1 trap.

## c1Task

1. Each handler below skips the instruction that faulted. For each, choose whether the program,
   after `resume`, finds every register as it left it, or finds a register changed.
2. There are 4 tests, one for each handler.

Then give the four handlers, each under its letter (A, B, C, D) in a fenced code block, exactly as
here, with nothing changed:

A:
```
handler: word[0x408] <= R5
        R5 <= C2
        R5 <= R5 + 4
        C2 <= R5
        R5 <= word[0x408]
        resume
```

B:
```
handler: word[0x408] <= R5
        R5 <= C2
        R6 <= R5 + 4
        C2 <= R6
        R5 <= word[0x408]
        resume
```

C:
```
handler: word[0x408] <= R5
        R5 <= C2
        R5 <= R5 + 4
        C2 <= R5
        R5 <= word[0x410]
        resume
```

D:
```
handler: word[0x408] <= R5
        word[0x410] <= R6
        R5 <= C2
        R6 <= 4
        R5 <= R5 + R6
        C2 <= R5
        R6 <= word[0x410]
        R5 <= word[0x408]
        resume
```

The answers (for your hints): A leaves every register as it was; B changes R6, which it writes and
never saves; C saves R5 at `408` but puts back the word at `410`, so R5 changes; D saves R5 and R6
and puts both back, so it leaves every register as it was.

## c1Hints (five, in this order)

1. The idea: list every register the handler writes, then check that each is saved before it is
   written and put back from the same word before `resume`.
2. A common mistake: checking only R5. A handler that writes any other register must save that one
   too.
3. A smaller example: the investigation's handler writes only R5, saves it at `408` and puts it
   back from `408`.
4. Part of the answer: handler B writes R6 with `R6 <= R5 + 4` and never saves it.
5. The whole answer: A leaves every register as it was; B changes one; C changes one; D leaves
   every register as it was.

## The program the failure experiment runs

```
000  R1 <= handler
004  C4 <= R1
008  R14 <= 0x400        // the stack is full
00C  R10 <= 7
010  R14 <= R14 - 8
014  word[R14] <= R10    // a push into the ROM
018  stop
01C  handler: word[R14 - 8] <= R5    // save R5 below the stack's top
020  R5 <= C2
024  R5 <= R5 + 4
028  C2 <= R5
02C  R5 <= word[R14 - 8]
030  resume
```

R14 starts at `400`, the RAM's first address; the push takes it to `3F8`, in the ROM, and the
store traps with cause `34` (C2 ← `014`). The handler's first line stores at `3F0`, also in the
ROM: it faults with cause `34` at `01C`, the address C4 holds, so the machine halts there. 5
instructions ran and 1 trap went to the handler.

## failureExperiment (about 60 words)

1. A handler could save R5 on the stack, below the word R14 names, as a function does.
2. The figure runs a program whose stack has grown into the ROM: R14 holds `3F8` when its push
   faults.
3. The handler's first line stores R5 at R14 minus 8.

## stackLead (one sentence)

Predict how the run ends, then press "Run to the end".

## stackAfter (about 70 words, shown once the run has ended)

1. The machine halts with cause `34` at `01C`, the handler's first line.
2. The push at `014` trapped, and the machine went to the handler. The handler's own store, at
   `3F0`, is in the ROM too.
3. A trap at the address C4 holds halts the machine, so nothing more runs.
4. R14 may be the very register that went wrong. A handler does not trust it.
