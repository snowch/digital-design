# Brief 4L: lesson `system-calls` (Module 12, lesson 4), its labels

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap**,
**handler**, **user mode**, **system mode**, and **system call** except in the title and the
question's heading. No bold in labels.

Keys to write, each a short label (a title or heading is a few words, no full stop; an objective
starts with a verb; a caption is one sentence naming what the figure shows, with a full stop):

- `title`: the lesson's question: how does a user program show a reading, if it may not touch the
  display?
- `objectives.1` to `objectives.4`:
  1. make a system call with the job in R1 and its word in R2;
  2. say where a system call returns, and how that differs from a fault;
  3. tell a system call from a fault in a handler, by C3;
  4. add a job to a handler.
- Section headings (keys `question`, `motivation`, `prediction`, `investigation`, `construction`,
  `failureExperiment`, `explanation`, `generalisation`, `challenge`, `reflection`, under
  `titles.`): a store the display refuses; asking the handler; C2 after call system; three
  calls, edge by edge; a call's registers, worked out; a handler that skips a line; two return
  points; like a function call, across modes; reading a room's sensor; a door that does not ask.
- `challengeTitles.c1`: a call's registers. `challengeTitles.c2`: reading a room's sensor.
- Captions:
  - `captions.direct`: a user program that stores to the display, in the debugger.
  - `captions.predict`: a handler with two jobs and a program that uses them, listed, with a
    question about C2.
  - `captions.timeline`: the program's three calls, edge by edge, with the mode after each.
  - `captions.answers`: four questions about a call's registers.
  - `captions.skipping`: the same program with a handler that adds 4 to C2, in the debugger.
  - `captions.services`: the same program in the debugger, with a breakpoint on the handler.
  - `captions.sensor`: a handler that reads a room's sensor for a user program, and its tests.
- `fields.show`: R1 to show R2. `fields.end`: R1 to end the program. `fields.night`: R2 to light
  NIGHT with job 3. `fields.roomB`: R1 after job 2 for room B.
- `sensorLabels.1` to `sensorLabels.3`: room A, then room B; room B, kept in R5 across a call; the
  difference between the rooms.
