## Facts every part of this lesson may use

- This lesson's handler offers one more job, job 5: wait. R2 holds a number of rounds; the handler
  runs a loop of that many rounds, two instructions each, then resumes the program. Job 5 is this
  lesson's own; jobs 1 to 4 are as lesson 4 gave them.
- The handler is lesson 5's: its start writes 2 to C1, so the program runs in user mode with
  interrupts on; its door part clears the door's bit and sets the timer to 20; its timer part
  lights ALARM if the door is still open.
- The user program shows 5 (job 1), waits 60 rounds (job 5), shows 6 (job 1), and ends (job 4).
- In this lesson's runs the door opens once 60 instructions have run, while the handler waits.
- Writing to C0 is a control-register job, `C0 <= R1`, allowed in system mode. Writing 3 (`11`)
  turns interrupts on and keeps system mode; writing 1 (`01`) turns them off again.

## motivation (about 170 words; a short list allowed)

1. A handler can let interrupts in: it writes 3, `11`, to C0. Then a trap can come while the
   handler runs, an interrupt or a fault in the handler's own lines.
2. That trap is like any other. Its edge writes C2, C1, C0 and C3, and the PC takes C4: the
   handler starts again from its first line.
3. C2 held the program's return point, and C1 the program's status. The second trap writes over
   them both. Unless the handler kept them first, the way back to the program is lost.
4. So a handler that lets interrupts in first copies C1 and C2 to two words of the RAM. Before it
   resumes, it turns interrupts off again and writes C1 and C2 back.
5. A fault in the handler is lost the same way, and nothing keeps C1 and C2 first: a handler must
   not fault.
