## c1Hints (five, a ladder; each begins with its rung's words)

1. "The idea:" an edge that traps is the last edge of its instruction. Find the state where each
   cause appears: the decoder's in READ, the memory's in MEMORY, an interrupt's at an edge that
   would fetch.
2. "A common mistake:" counting a trap as an edge of its own. The trap ends the instruction at the
   state where its cause appears.
3. "A smaller example:" `nothing` takes FETCH, READ and ALU: 3 edges, with no trap.
4. "Part of the answer:" `stop` in user mode is refused by the decoder, which gives its cause in
   READ. `resume` goes from READ to WRITE, as a control-register job does.
5. "The whole answer:" 2, 3, 1 and 4, in the order of the list.

## faultTrap (about 90 words; shown after the learner has run this fault)

1. With TRAP stuck at 0, the trap logic still sets GO to 0 at the store's MEMORY edge, but nothing
   takes the trap.
2. At that edge and every edge after it, GO is 0 and TRAP is 0, so the controller's state register
   does not change: the state diagram marks MEMORY as the state the next edge leaves it in.
3. The PC stays at `014`. The machine neither traps nor halts, and every edge after edge 24 writes
   nothing.
4. TRAP is what moves the machine on. GO at 0 alone only stops the writing.

## explanation (about 220 words)

1. When two causes are ready at one edge, the trap logic takes the lower number, as Module 8's
   causes did.
2. On this machine only one pair can meet. The decoder's cause counts only while CHECKING, in READ;
   the memory's only in MEMORY; and an interrupt is taken only at an edge that would fetch, with
   FETCHING 1. So the only two causes that can be ready together are a fetch's (`11` or `12`) and
   an interrupt's (`81` or `82`), and the fetch's wins, as the lower number.
3. An interrupt is taken when FETCHING is 1, IE is 1, and a bit is set in "waiting" (`7F0`). The
   timer's `81` comes before the door's `82`, the lower number.
4. With no handler, a cause halts the machine, as Module 9's machine did. In system mode, `stop`
   sets HALT, and the run stops. In user mode, `stop` is cause `22`.
5. The controller's one new rule: at an edge that traps, its state register takes FETCH, whatever
   its table says, as at a reset. The arrow marked "CALL 1" is the function call's, `call`, not
   `call system`'s.
6. The edge that traps writes the control registers, the PC and the controller's state at once. GO
   is 0, so none of R0 to R15 changes and no word of memory changes. The machine still notes a
   door that opens at that edge: "waiting" takes its bit at every edge where PCEN is 1, and PCEN is
   1 at a trap's edge.
7. A trap's edge does not count down the timer, because no instruction finished. The timer counts
   instructions, as lesson 5 said.

## generalisation (about 90 words)

1. A trap adds no state to the controller. It ends the instruction at the edge where its cause
   appears, and sends the controller to FETCH. So its cost is the edges the instruction had already
   taken.
2. The handler's address is a register, C4, not a fixed number in the circuit. The program chooses
   it.
3. Everything a handler sees, C0 to C4, is a register the circuit writes at one edge. The handler is
   ordinary instructions.
4. The trap logic is combinational: a table from its inputs to GO, TRAP, CAUSE and HALT.

## c2Task (a numbered list)

1. The starting text is Module 9's stop logic: every cause halts the machine, and TRAP is always 0.
2. Change it into the trap logic:
   - An interrupt happens when FETCHING and IE are 1 and WAITING is not 0. Its cause is `81` if
     WAITING's bit 0 is 1, else `82`.
   - When two causes are ready at once, the lower number wins.
   - TRAP is 1 when anything traps and NOHANDLER is 0. HALT is 1 when anything traps and NOHANDLER
     is 1, or at a `stop` while CHECKING.
   - GO is 0 when anything traps or the machine halts.
3. There are 17 tests, one for each row of the table: each cause on its own, the events, which
   cause wins, and no handler.

## modelVsReality (about 70 words)

1. Real machines add trap hardware in the same places: registers for the return point, the status
   and the cause, a choice of the next PC, and logic that picks one cause.
2. Machines that overlap instructions must also undo the work of the instructions after the one
   that faulted. This machine runs one instruction at a time, so it has nothing to undo.
