## motivation (about 170 words, with one table)

1. The program asks the handler, which runs in system mode, to do the job for it, with the line
   `call system`. `call system` traps on purpose, with cause `41`. User mode allows it.
2. A trap that a program makes on purpose, to ask the handler for a job, is a **system call**.
3. The program says which job it wants in R1, and gives the job its word in R2. The handler leaves
   the result in R1. These are the calling convention's first registers, as for a function whose
   first argument names the job.
4. The jobs are numbered (a table, columns "R1" and "What the handler does"):
   - 1: shows R2 on the display;
   - 2: reads a room's sensor. R2 is 0 for room A and 1 for room B. The reading comes back in R1;
   - 3: sets the lamps from R2's bits: bit 0 ALARM, bit 1 NIGHT, bit 2 CLASH;
   - 4: ends the program.
5. The handler reads C3 to tell a system call from a fault, then reads R1 to choose the job. It
   runs the job, then `resume`.
6. This lesson's handler offers jobs 1 and 4.

## p1Explain (about 60 words; shown after the learner commits)

1. C2 holds `070`, the instruction after the call.
2. A system call's return point is the next instruction, not the call: the job is done, and the
   program goes on from the next line.
3. After a fault, the return point is the instruction that faulted: that would be `06C` here.
4. `01C` is the handler's address, which the PC takes.

## generalisation (about 160 words)

1. A system call looks like a function call: R1 names the job and R2 gives it its word, as a
   function's arguments go in R1 to R4, and the result comes back in R1.
2. It differs in where the job runs. A function call stays in the program's mode. A system call
   crosses into system mode at its trap's edge, and back at `resume`'s edge.
3. It differs in which registers it may change. A function may change R0 to R9. A system call may
   change only R1 and R2, the call's own registers. Every other register comes back as it was.
4. The reason: the handler saves the registers it writes at its start, before it reads C3. The
   same handler takes faults, and a fault can come at any line of a program, where any register
   may hold the program's words. Until it has read C3 the handler cannot tell a call from a
   fault, so it keeps every register but the call's own.
5. The handler decides what each job may do. A user program reaches the shop's devices only
   through the jobs the handler offers.
6. A job the handler does not offer does nothing: the handler puts R8 and R9 back and resumes.
