# Brief R9: four hints, after the second pass

Read `00-module.md` (the shared fact sheet) first, including its last section. Each key is one
hint, the third rung of a challenge's ladder, and begins with "A smaller example:". The review's
rule: a smaller example is smaller than the task and is no part of its answer. So none of these
may give a line the answer uses. Write each from its facts alone. Use **trap** and **handler**
freely; never bold.

## traps.c2Hints.3 (lesson 1; the task: count and skip refused stores, cause 34, stop on others)

A smaller example: a handler that runs `stop` on cause `21` alone, and resumes on every other
cause, reads C3 into a register, puts `0x21` in another, and branches when the two are equal.
Do not write the lines out.

## saving-state.c2Hints.3 (lesson 2; the task: save and put back every register the handler writes)

A smaller example: a handler that writes R7 alone would save R7 with `word[0x410] <= R7` as its
first line, and put it back with `R7 <= word[0x410]` just before `resume`.

## nesting.c2Hints.3 (lesson 6; the task: job 6 lets interrupts in, so it saves C1 and C2)

A smaller example: a handler that needs C3 after a trap could come inside it saves C3 the same way
a register is saved, through an R register: `R1 <= C3`, then `word[0x420] <= R1`; and it puts it
back with `R1 <= word[0x420]`, then `C3 <= R1`.

## trap-hardware.c2Hints.3 (lesson 7; the task: the trap logic's TRAP, HALT, GO and CAUSE)

A smaller example: a signal that is 1 when either of two causes is not 0 is
`assign either = (CAUSEF != 8'h00) | (CAUSEM != 8'h00);`. The trap logic's signals are built from
such pieces.
