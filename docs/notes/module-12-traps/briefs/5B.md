## The handler the rest of the lesson runs

```
handler: word[0x400] <= R8      // save R8 and R9
        word[0x408] <= R9
        R9 <= C3
        R8 <= 0x82
        if R9 == R8 goto door
        R8 <= 0x81
        if R9 == R8 goto tick
        R8 <= 0x41
        if R9 != R8 goto fault
        ... jobs 1 and 4, as in lesson 4 ...
door:   R8 <= 2
        word[waiting] <= R8     // the door's event is seen
        R8 <= 20
        word[timer] <= R8       // 20 instructions to close the door
        goto back
tick:   R8 <= 1
        word[waiting] <= R8     // the timer's event is seen
        R8 <= word[signals]
        R9 <= 1
        R8 <= R8 & R9           // DOOR
        if R8 != R9 goto back   // closed in time
        word[lamps] <= R9       // still open: ALARM
        goto back
back:   R8 <= word[0x400]       // put R8 and R9 back
        R9 <= word[0x408]
        resume
```

The door's part clears the door's bit and sets the timer to 20. The timer's part clears the
timer's bit and reads DOOR: if the door is still open, it lights ALARM.

## The run the timeline shows (the door opens once 15 instructions have run)

- Edge 16: `R2 <= R2 + 1` at `0AC` runs; the door's bit of "waiting" is set at this edge.
- Edge 17: the door's interrupt. The branch at `0B0` does not run. C2 ← `0B0`, C1 ← `10`,
  C0 ← `01`, C3 ← `82`, PC ← `01C`.
- Edges 18 to 29: the handler goes to `door:`, stores 2 to "waiting" (edge 24) and 20 to the timer
  (edge 26), and puts R8 and R9 back.
- Edge 30: `resume`. C0 ← `10`, PC ← `0B0`: user mode, interrupts on, back at the branch.
- The timer counts 20 instructions (edges 27 to 46), the handler's last four among them.
- Edge 47: the timer's interrupt, cause `81`, again before the branch at `0B0`.
- The handler goes to `tick:`, clears the timer's bit, reads DOOR as 1, and lights ALARM
  (`word[7C8] ← 1`, edge 61). Edge 65: `resume`, back to `0B0`.
- The program counts on to 30, shows 30 and ends with job 4: the handler stops at `09C`.
- In all: 136 edges, 132 instructions, 4 traps (`82`, `81`, `41`, `41`). The display shows 30;
  ALARM is on.

## c1Task (numbered list)

1. For each case, give the cause the next edge traps with, in hexadecimal, or 0 if the next
   instruction runs. The instruction itself would not fault.
   - C0 is `10` and "waiting" is `10`;
   - C0 is `00` and "waiting" is `10`;
   - C0 is `10` and "waiting" is `11`;
   - C0 is `01` and "waiting" is `01`.
2. There are 4 tests, one for each case.

The answers (for your hints): `82`, 0, `81`, 0.

## c1Hints (five, in this order)

1. The idea: the next edge traps only when C0's bit 1 is 1 and a bit of "waiting" is set.
2. A common mistake: reading C0's bit 0. Bit 0 is the mode; interrupts are bit 1, the left digit.
3. A smaller example: the door's interrupt in the timeline came with C0 at `10` and "waiting" at
   `10`, cause `82`.
4. Part of the answer: when both events wait, the timer's `81` goes first.
5. The whole answer: `82`, 0, `81` and 0.

## The program the failure experiment runs

The same handler and program, but the door's part does not clear the door's bit: its first two
lines are replaced by `nothing`. After `resume`, the door's bit is still set and interrupts are
on, so the next edge is the door's interrupt again, before the program's instruction runs. Every
`resume` leads to another interrupt. The debugger cuts the run off after 5000 instructions, all of
them after the door's interrupt the handler's: 416 traps went to the handler. R2 stays at 4 and the display at 0. ALARM never
lights: each visit sets the timer to 20 again, so it never reaches 0.

## failureExperiment (about 50 words)

1. The figure runs the same program with a handler whose door part does not clear the door's bit.
2. The door opens once 15 instructions have run.
