## Facts every part of this lesson may use

- The word "waiting", at `7F0`, has two bits. Bit 0 is set when the timer reaches 0. Bit 1 is set
  when the door opens. A bit stays set until a program writes a 1 to it: storing 2 to `waiting`
  clears bit 1, storing 1 clears bit 0. A 0 written leaves a bit as it is.
- The timer, at `7E8`, holds a count. A store sets the count. The count goes down by 1 each time
  an instruction finishes, while it is not 0. When it goes from 1 to 0, bit 0 of "waiting" is set.
  The timer counts every instruction, the handler's included.
- The debugger shows a panel titled "The timer and the door": the timer's count, the two bits of
  "waiting" ("Timer reached 0", "Door opened") as yes or no, and DOOR and WARM.
- In this lesson's runs the door opens once 15 instructions have run, and stays open.

## motivation (about 190 words; a short list allowed)

1. The machine can go to the handler without the program asking. At the edge that would run the
   next instruction, if a bit of "waiting" is set and C0's bit 1 is 1, the machine traps instead.
2. A trap that an event outside the program makes, between two of its instructions, is an
   **interrupt**. C0's bit 1 says whether interrupts are on.
3. The cause says which event: `81` the timer reached 0; `82` the door opened. If both wait, `81`
   goes first.
4. The interrupt's edge makes the five transfers every trap makes (C2, C1, C0, C3, the PC). C0
   takes `01`, so interrupts are off in the handler.
5. The instruction the PC names has not run. It is the return point: C2 takes its address, and
   `resume` runs it.
6. The handler clears the event's bit by storing a 1 to it: `R8 <= 2`, `word[waiting] <= R8` for
   the door.
7. The handler start turns interrupts on for the program by writing 2 to C1 instead of 0: bit 1
   on, bit 0 off, user mode. `resume` copies C1 to C0.
8. Interrupts are taken in user mode and in system mode alike, whenever C0's bit 1 is 1.

## p1Question (one sentence)

Just after the door's interrupt, what does C2 hold?

## p1Explain (about 70 words)

1. C2 holds `0B0`: the branch, the instruction that has not run yet.
2. `0AC` ran before the interrupt, so going back to it would add 1 to R2 twice.
3. `0B4` would skip the branch. `01C` is the handler's address, which the PC takes.
4. After `resume`, the branch runs as if nothing had happened: the program never knows.
