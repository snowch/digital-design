## c2Task (a numbered list)

1. The starting text holds the start and the whole handler except the timer's part, which only
   goes to `back`. The start lights the lamps that a word in each test's lines gives, named
   `startLamps`, before the program runs; some tests start with ALARM already lit.
2. Write the timer's part at `tick:`. It clears the timer's bit of "waiting", bit 0. Then, if the
   door is still open, it lights ALARM and leaves the other lamps as they are. If the door has
   closed, it leaves the lamps alone. Either way it ends by going to `back`.
3. The door is bit 0 of the word at `7D0`, which the assembler names `signals`; bit 1 is WARM. The
   lamps can be read as well as written, with `word[lamps]`.
4. Two words for bits: `R8 <= R8 & R9` keeps only the bits set in both; `R8 <= R8 | R9` sets every
   bit set in either. Write them in that form, with registers; the assembler does not take the
   words AND and OR.
5. An interrupt may change no register, because the program did not ask for it. The timer's part
   may write R8 and R9, but the handler saves them at its start and puts them back at `back`.
6. There are 5 tests. Each adds a program after yours, named `program`. It puts a word of its own
   in R0, R1 and R5 to R15, counts to 30 in R2 over 30 rounds, with R3 counting the rounds down to
   R4's 0, stores R1 in the word at `500`, then shows R2 with job 1 and ends with job 4.
7. Each test opens the door at its own time: left open; closed in time; never opened; opened late
   and left open; left open on a warm night, with WARM 1.
8. Each test checks the lamps; the display, which shows 30; the word at `500`, R1 as the
   interrupts left it; R0 and R2 to R15 as the program left them at its last trap, the call for
   job 4; the causes, in order; and that the run ends at the handler's `stop` for job 4.
