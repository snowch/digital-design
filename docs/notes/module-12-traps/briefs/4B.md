# Brief 4B: lesson `system-calls` (Module 12, lesson 4), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. You may use **trap**,
**handler**, **user mode**, **system mode** and **system call** (never bold them).

Keys to write: `investigation`, `timelineLead`, `timelineAfter`, `construction`, `answersLead`,
`c1Task`, `c1Hints.1` to `c1Hints.5`, `failureExperiment`, `skippingLead`, `skippingAfter`.

## The program the investigation runs

```
000  R1 <= handler
004  C4 <= R1
008  R1 <= 0
00C  C1 <= R1               // user mode
010  R1 <= program
014  C2 <= R1
018  resume
01C  handler: word[0x400] <= R8      // save R8 and R9
020  word[0x408] <= R9
024  R9 <= C3
028  R8 <= 0x41
02C  if R9 != R8 goto fault  // not call system: a fault
030  R8 <= 1
034  if R1 == R8 goto show
038  R8 <= 4
03C  if R1 == R8 goto end
040  goto back               // a job the handler does not offer
044  show: word[display] <= R2
048  back: R8 <= word[0x400]       // put R8 and R9 back
04C  R9 <= word[0x408]
050  resume
054  end: stop
058  fault: stop
05C  program: R2 <= 25
060  R1 <= 1
064  call system             // show R2
068  R2 <= R2 + 1
06C  R1 <= 1
070  call system             // show R2 again
074  R1 <= 4
078  call system             // end the program
```

The run: `resume` at `018` starts the program in user mode. The `call system` at `064` traps with
cause `41`: C2 ← `068`, C1 ← `00`, C0 ← `01`, C3 ← `41`, PC ← `01C`. The handler shows 25 and
resumes at `068`, in user mode. The second call, at `070`, shows 26 and resumes at `074`. The
third, at `078`, asks job 4: the handler stops at `054`. In all, 44 instructions ran and 3 traps
went to the handler; the display showed 25, then 26. The timeline starts from the edge after
`resume`.

## investigation (about 50 words)

1. The timeline runs the program from its first line, in user mode, with the mode after each edge.
2. Each `call system` takes the run into the handler, in system mode, and `resume` brings it back
   to the next line, in user mode.

## timelineLead (numbered steps, about 50 words)

1. Step to the first `call system` and read its transfers: C2 and C3 above all.
2. Step through the handler's lines to the store to the display and to `resume`.
3. Step on through the second call and the third, to the end.

## timelineAfter (about 70 words, shown once the learner has stepped to the last edge)

Give the run's facts briefly: each call's return point is the line after it; the handler shows 25,
then 26; each `resume` goes back to user mode; job 4 ends at `054`, where the handler stops; 3
system calls in all.

## construction (about 30 words)

You can write a system call's registers without running it, from the table of jobs.

## answersLead (one sentence)

Work out each answer from the table of jobs, then run the tests.

## c1Task (numbered list)

1. Give, as decimal numbers:
   - what R1 holds for the job that shows R2;
   - what R1 holds for the job that ends the program;
   - what R2 holds to light NIGHT alone with job 3;
   - what job 2 leaves in R1 for room B, with room B reading -250.
2. There are 4 tests, one for each answer.

The answers (for your hints): 1, 4, 2, -250.

## c1Hints (five, in this order)

1. The idea: R1 says which job; R2 gives the job's word; the result comes back in R1.
2. A common mistake: giving job 3 the lamp's number instead of its bit. NIGHT is bit 1, so R2 is
   the word with bit 1 set.
3. A smaller example: the investigation's program shows 25 with `R2 <= 25`, `R1 <= 1`,
   `call system`.
4. Part of the answer: job 2 reads the sensor R2 names and leaves its reading in R1.
5. The whole answer: 1, 4, 2 and -250.

## The program the failure experiment runs

The same program and handler, but the handler adds 4 to C2 before it puts R8 and R9 back, as lesson
1's handler did. Each `call system` then resumes two lines on: `R2 <= R2 + 1` never runs, and the
`R1 <= 4` before the third call never runs. The display shows 25 three times. After the third call
the PC goes past the program's last line, to a word of 0s at `08C`: it traps with cause `21`, and
the handler's `fault` line stops the machine at `064`. 58 instructions ran.

## failureExperiment (about 50 words)

1. The figure runs the same program with a handler that adds 4 to C2 before `resume`, as lesson 1's
   handler did for a fault.
2. Breakpoints are on: you can pause on any line.

## skippingLead (one sentence)

Predict what the display shows, then press "Run to the end".

## skippingAfter (about 80 words, shown once the run has ended)

1. The display showed 25 three times, and the handler stopped the machine at `064` with cause `21`.
2. Each `resume` went two lines past the call. `R2 <= R2 + 1` never ran, nor the `R1 <= 4` before
   the third call, which asked job 1 again.
3. After the third call the run went past the program's end, onto a word that is not an
   instruction.
4. A system call's return point is already the next line. Adding 4 skips a line of the program.
