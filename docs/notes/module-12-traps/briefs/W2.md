## timelineLead (a numbered list after one sentence; about 110 words)

The figure is the trap timeline of the same run, with the saving handler.

1. The first press of "Next edge" shows edge 4, `R0 <= 0`, the edge before the trap. Only the
   timeline shows each edge's transfers.
2. Edge 5: the store at `010` traps. That one edge makes five transfers: C2 ← `010`, C1 ← `01`,

3. Edges 6 to 12 run the handler's lines up to `resume`. Each makes two transfers: one register
   or one word, and the PC.
4. Edge 6 saves R5: word[408] ← -184. Edge 12 puts it back: R5 ← -184.
5. Edge 13: `resume` makes two transfers: C0 ← `01` (C1's word) and PC ← `014`.

## generalisation (about 80 words)

1. The calling convention lets a function change R0 to R9: R1 to R4 for the arguments, R1 for the
   result, R0 and R5 to R9 as free registers. The caller made the function call, so it knows
   those registers may change.
2. The motivation said why a handler cannot have that rule: no program calls it. Point back to
   that; do not say it again.
3. Each register a handler writes costs two more instructions: a save and a put back. So a handler
   writes as few registers as it can.

## c2Task (a numbered list)

1. The starting text's handler counts each refused store in the word at `400` (`word[0x400]`) and
   skips it. It writes R5 and R6, and saves neither.
2. Change the handler so that every register, R0 to R15, holds after `resume` what it held before
   the trap. The count and the skip must still work.
3. There are 3 tests. Each adds a program after yours, named `program`, and runs all of it from
   reset. Each program puts a word of its own in every register, R0 to R15, a different set in
   each test, and ends at its last line, `end: stop`.
4. Test 2 changes R5 and R6 between its two refused stores.
5. Test 3's stack started in the wrong place: it sets R14 to `0x400` and pushes, so its push
   faults in the ROM, and its R14 then holds `3F8`.
6. Each test checks the count at `400`, every register from R0 to R15, C3, the causes in order,
   and that the run stops at the program's `end`.

## c2Hints.0 ("The idea:", one sentence)

Save each register the handler writes with an absolute store, before the handler's first write
to it, and put each back from the same word just before `resume`.

## c2Hints.1 ("A common mistake:", two short sentences)

Saving on the stack, below R14. Test 3's stack started at `400`, so a save below R14 is in the ROM
and faults.

## c2Hints.3 ("Part of the answer:", two short sentences)

1. The starting handler writes two registers, R5 and R6, so it needs two words to save them in.
2. The count lives at `400`, so use other addresses, such as `408` and `410`.
