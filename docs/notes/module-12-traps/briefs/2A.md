## What lesson 1 left

Lesson 1's handler: `R5 <= C3`, `word[0x400] <= R5` (keep the cause), `R5 <= C2`,
`R5 <= R5 + 4`, `C2 <= R5`, `resume`. Lesson 1 ended: the night program did not use R5, and the
handler wrote R5 three times; what must a handler leave as it found it, and where can it keep
words while it works?

## The program the first figures run

```
000  R1 <= handler
004  C4 <= R1
008  R5 <= word[sensorA]     // room A's reading, kept in R5
00C  R0 <= 0
010  word[sensorB] <= R0     // the mistake
014  word[display] <= R5     // show room A's reading
018  stop
01C  handler: lesson 1's handler, six lines
```

Room A reads -184. The store at `010` traps with cause `34`; C2 takes `010`. The handler writes
R5 three times: 52 (the cause), then `010`, then `014` (20 as a decimal number). It resumes at
`014`, which stores R5 to the display. The display shows 20, not -184. The program stops at
`018` after 12 instructions and 1 trap.

## question (about 70 words, above a figure)

1. Lesson 1 asked what a handler must leave as it found it.
2. The figure's program keeps room A's reading in R5, makes the same mistake as the night program,
   then shows R5 on the display. It uses lesson 1's handler.
3. Room A reads -184, so the display should show -184.

## spoiledLead (one sentence)

Press "Run to the end" and read the display.

## spoiledAfter (about 70 words, shown once the run has ended)

1. The display shows 20, not -184. The program stops at `018`.
2. 20 is `014` as a decimal number: the return point after the handler added 4 to C2.
3. The handler left that word in R5, and the program, which knew nothing of the trap, showed it.

## motivation (about 140 words; a short list allowed)

1. A handler runs in the middle of another program. That program did not call it and cannot tell
   it ran.
2. So the handler must leave every register as it found it: it saves each register it writes, and
   puts each back before `resume`.
3. It saves a register with an absolute store, at an address the instruction's constant gives:
   `word[0x408] <= R5`. It puts it back with `R5 <= word[0x408]`.
4. An absolute store needs no register to hold its address, so the handler can make it before it
   has changed any register.
5. The handler keeps its saved words in the RAM, at addresses it chooses: here `400` for the cause
   and `408` for R5.

## p1Question (one sentence)

When the program stops, what does the word at `408` hold, as a decimal number?

## p1Explain (about 60 words)

1. The word at `408` holds -184: room A's reading, which R5 held when the handler saved it.
2. The handler saved R5 before its first write to R5, so 52 and 20 never reach `408`.
3. Putting R5 back reads the word and leaves it there.
