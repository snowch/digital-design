**handler**, **user mode**, **system mode**, **system call** and **interrupt** (never bold them).
This lesson introduces no term.

Keys to write: `question`, `edgesLead`, `edgesAfter`, `motivation`, `prediction`, `p1Question`,
`p1Explain`.

## Facts every part of this lesson may use

- The learner knows Module 9's machine of several edges: one memory port; the instruction
  register IR; the held words HA, HB, HR and HM; the controller, Module 5's state machine, with
  five states, FETCH, READ, ALU, MEMORY and WRITE, one edge each; the kind decides which states an
  instruction passes through. A register job takes FETCH, READ, ALU, WRITE; a store FETCH, READ,
  ALU, MEMORY. The PC keeps the instruction's address until the edge that ends it.
- Module 9's **stop logic** computed, before each edge, whether the coming edge stops the machine
  (HALT) and with which cause (CAUSE), from three causes: the fetch's (CAUSEF), the decoder's
  (CAUSED, counted only while CHECKING marks the READ state) and the memory's (CAUSEM). GO is 1
  unless the edge halts; an edge with GO at 0 writes nothing.
- Module 12's copy of that machine adds the trap hardware. Its drawing has the same three blocks:
  the control unit, the datapath and the memory port.
- **The control registers**, in the datapath: five registers, each with a selector in front of it
  that picks its next word. At a trap's edge C2 takes the return point, C1 takes C0, C0 takes
  `01` and C3 takes the cause. At `resume`'s edge C0 takes C1. At a control-register job's WRITE
  edge, the register the constant names takes register A's word. Out of the block: the word of
  the register the constant names, for register Y (`R5 <= C3`); C2 and C4 for the next PC; C0's
  two bits; and NOHANDLER, 1 when C4 is 0 or C4 equals the PC.
- **The next PC**: C4 at a trap's edge, C2 at `resume`'s edge, otherwise as in Module 9.
- **The trap logic**, in the control unit, where the stop logic was. In: the three causes, STOP,
  CHECKING, FETCHING, the waiting bits, IE (C0's bit 1) and NOHANDLER. Out: GO, TRAP, CAUSE and
  HALT. An edge traps when there is a cause, or when an event waits at an edge that would fetch
  with IE at 1. With a handler, TRAP is 1; with none, HALT is 1, as Module 9's machine did. GO is 0
  either way.
- **The controller**: one new rule. At an edge that traps, its state register takes FETCH, as at
  a reset, and the PC is written, so it takes C4. A control-register job and `resume` go READ to
  WRITE.
- The mode: C0's bit 0 goes to the decoder, which gives cause `22` in user mode for `resume`, the
  control-register jobs and `stop`; and to the memory port's checks, which give cause `32` in user
  mode for a device's address.

## The program the first figure runs

```
000  R1 <= handler
004  C4 <= R1
008  word[sensorB] <= R1     // refused: it traps at its MEMORY edge
00C  stop
010  handler: R5 <= C3
014  stop
```

The figure is a timing diagram of its first 12 edges, with lanes CLK, S (the controller's state),
PC, IR, TRAP and C2. Edges 1 to 4: `R1 <= handler` (FETCH, READ, ALU, WRITE). Edges 5 to 7:
`C4 <= R1` (FETCH, READ, WRITE). Edges 8 to 11: the store, FETCH, READ, ALU, MEMORY. Before edge 11,
in MEMORY, TRAP is 1. At edge 11: the PC takes `010`, C2 takes `008`, C3 takes `34`, and the state
goes to FETCH. Edge 12 fetches the handler's first line.

## question (about 90 words, above a figure)

1. Lesson 6 ended on a question: which parts of the machine copy C0 into C1, take the cause into
   C3, and send the PC to C4, all at one edge?
2. Lessons 1 to 6 ran on the machine of one edge per instruction. This lesson opens Module 9's
   machine of several edges, with the parts a trap needs added.
3. The figure is a timing diagram of a three-line program's first 12 edges: it sets C4, then
   stores to room B's sensor, which the machine refuses.

## edgesLead (one sentence)

Move along the diagram's edges and find the edge where TRAP is 1 just before it.

## edgesAfter (about 70 words)

Give the facts above: the store's edges 8 to 11; TRAP is 1 in MEMORY, before edge 11; at edge 11
the PC takes `010`, the handler's address, and C2 takes `008`, the store's; the state goes from
MEMORY to FETCH; edge 12 fetches `R5 <= C3`. The trap took no edge of its own: it is the store's
last edge.

## motivation (about 220 words; a short list allowed)

Say where each part sits and what it does, from the facts above (list the four parts):
the control registers and their selectors in the datapath; the next PC; the trap logic in the
control unit, where the stop logic was; the controller's one new rule. Then the mode's two
wires. End with: every part takes its word at the same edge, the last edge of the instruction that
traps.

## p1Question (one sentence)

What does the PC hold after the next edge?

## p1Explain (about 60 words)

1. The PC takes `010`, C4: the trap logic has set TRAP to 1, and at a trap's edge the next PC is
   C4.
2. `00C` would be the next instruction, if the store had not been refused. `008` is the store,
   which C2 takes.
3. Run the next edge and read the control registers.
