# Brief X2: Module 12's figures pass (lessons 1, 4, 5, 6 and 8)

Read `docs/notes/module-12-traps/briefs/00-module.md` first, both "Decisions" sections included,
then `docs/style.md`. Terms each lesson may use: lesson 1 `traps`: trap, handler; lesson 4
`system-calls`: those, user mode, system mode, system call; lessons 5 `interrupts`, 6 `nesting`
and 8 `system-call-mechanism`: those and interrupt. Write each key from its facts alone. A key
marked "(added)" is a new step or sentence that goes at the end of the existing text: write only
the new words. Keep lists as lists.

The drawing all these keys describe: the run drawn as lanes, above the timeline's list of edges.
One lane (a column) for each part of the program that runs; time runs down the page. A bar in a
lane is the run inside that part. An arrow across is the run moving between parts, labelled with
what it writes: a trap with C2 and C3, `resume` with the PC. From lesson 3 on, a band beside the
lanes shows the mode, one colour for system mode and another for user mode. The drawing grows
with each "Next edge". A button, "Next move", runs on to the next arrow.

## lesson `traps` (1)

- `lanes.program`, `lanes.handler`: two lanes' names, capitalised as headings are: the night
  program; the handler.
- `timelineLead` (added, as step 5): above the list, the run is drawn as two lanes, the night
  program and the handler. The trap is an arrow to the handler, labelled with C2 and C3, and
  `resume` an arrow back, labelled with the PC. Do not give the values.
- `captions.timeline`: a caption: the timeline of the night program's run with its handler, one
  edge at a time, drawn as lanes too.

## lesson `system-calls` (4)

- `lanes.start`, `lanes.handler`, `lanes.program`: three lanes' names, capitalised as headings:
  the start; the handler; the program.
- `timelineLead` (added, as step 4): the drawing above the list has three lanes: the start, the
  handler and the program, with the band for the mode beside them. Each `call system` is an arrow
  from the program to the handler, labelled with C2 and C3, and each `resume` an arrow back,
  labelled with the PC. "Next move" runs on to the next arrow.
- `captions.timeline`: a caption: the program's three calls, edge by edge, with the mode after
  each, and drawn as lanes.

## lesson `interrupts` (5)

- `lanes.start`, `lanes.handler`, `lanes.program`: as lesson 4: the start; the handler; the
  program.
- `timelineLead` (added, as step 5): the drawing above the list shows the start, the handler and
  the program as lanes, with the band for the mode. A circle in the program's lane marks where the
  door opens, between two instructions, and another where the timer reaches 0. Each interrupt is
  an arrow to the handler, labelled with C2 and C3. The program knows nothing of either: its lane
  just stops, and goes on after `resume`.
- `captions.timeline`: a caption: the run with the door open, edge by edge from edge 16, drawn as
  lanes too.

## lesson `nesting` (6)

- `lanes.start`, `lanes.handler`, `lanes.program`: as lesson 4. `lanes.again`: a fourth lane's
  name: the handler again, the handler run by a trap that came while the handler ran.
- `timelineLead` (added, as step 4): in the drawing above the list, the second trap, the
  handler's own load, is an arrow from the handler to a third lane, the handler again, labelled
  with the C2 and C3 it writes. Its `resume` is an arrow back to the handler, not to the program.
- `savedLead` (added, as step 4): under the debugger, the run is drawn as lanes. Circles in the
  handler's lane mark job 5's stores to `410` and `418`. The door's interrupt comes after them, as
  an arrow to the handler again, and so does the timer's; each `resume` comes back to the handler,
  and job 5's own `resume` goes back to the program.
- `captions.timeline`: a caption: the run from the program's call, edge by edge, with the mode
  after each, and drawn as lanes.
- `captions.saved`: a caption: job 5 saving C1 and C2 in the debugger, with the door's time to
  choose and the run drawn as lanes.

## lesson `system-call-mechanism` (8)

- `lanes.start`, `lanes.handler`: the start; the handler. `lanes.first`, `lanes.second`: run 2's
  first program; run 2's second program (capitalised as headings).
- `captions.lanes`: a caption: the shop's handler on run 2's programs, drawn as lanes, with no
  lines listed.
- `lanesLead` (numbered steps; about 60 words): the figure runs a handler that does the
  challenge's work on run 2's table. It lists no lines, so it does not give the handler away:
  only the lanes and the arrows between them. Steps: press "Next move" to run on to each arrow
  and read what it writes; press "Run to the end".
- `lanesAfter` (about 70 words; shown once the run has ended): run 2's first program stores to the
  display, which user mode refuses: it traps with cause `32`, and the handler goes back to the
  start, which runs the second program. The second program makes two system calls, job 1 and
  then job 4. After job 4, the handler goes back to the start, which finds no program left, and
  the run stops there.
