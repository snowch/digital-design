# Brief Y1: the review of the figures pass, the shared strings

Read `docs/style.md` first. These strings serve the drawings of Modules 11 and 12. Write each key
from its facts alone. No backticks anywhere. Keep every placeholder in braces exactly as given.
Answer in the form `key: text`, one key to a line.

## The move sentences (`lanes.move...`)

Each is one sentence, ending in a full stop, said under the drawing's buttons and read by a screen
reader. The page capitalises its first letter. Lane names arrive already in sentence form: "the
handler", "the start", "the program", "the night program", "the handler again", "the main
program", "run 2's first program", or a function's name such as "overBy". `{transfer}` is what the
move writes, such as "R15 ← 00C", "PC ← 018" or "C2 ← 014, C3 ← 34". Put the transfer after a
colon at the end.

- `lanes.moveCall` — Module 11: a call goes from `{from}` to `{to}`, a function. Use the words "a
  call goes to {to}" and name `{from}` too.
- `lanes.moveBack` — Module 11: the function `{from}` goes back to `{to}`. Use the words "goes back
  to".
- `lanes.moveTrap` — Module 12: an instruction in `{from}` traps, and the machine goes to `{to}`
  (the handler, or the handler again).
- `lanes.moveInterrupt` — Module 12: an interrupt comes while `{from}` runs, and the machine goes
  to `{to}`.
- `lanes.moveResume` — Module 12: `{from}` resumes `{to}`. Use the word "resumes". (`{from}` is the
  start, the handler or the handler again.)
- `lanes.moveJump` — Module 12, lesson 8 only: `{from}` (the handler) goes back to `{to}` (the
  start). Use the words "goes back to".

## The marks

Each is one sentence ending in a full stop, said in the same places. `{lane}` arrives in sentence
form, as above.

- `lanes.markDoor` — the freezer door opens while `{lane}` runs.
- `lanes.markTimer` — the timer reaches 0 while `{lane}` runs.
- `lanes.markStore` — `{lane}` stores a word that the lesson marks; `{label}` says which and what,
  such as "word[410] ← 2". Put `{label}` after a colon at the end.
- `lanes.markStop` — the run stops in `{lane}`. Name no line and no address.
- `lanes.markCut` — the drawing ends here, in `{lane}`, but the run goes on.

## Short labels inside the drawing (no full stop, lower case, as "system mode" and "freezer door opens" are)

- `lanes.stops` — beside the square that marks where the run stops: the run stops. Two or three
  words.
- `lanes.cut` — beside the square that marks where the drawing ends while the run goes on. A few
  words.
- `lanes.nowKey` — the key beside a dot in the drawing's key: the dot marks where the run has got
  to, the newest step. A few words.
- `lanes.interruptsBand` — the key beside a second band: the band is drawn where interrupts are
  on. Two or three words.

## The button

- `lanes.backMove` — a button beside "Next move": it goes back to the previous arrow or mark. Two
  or three words, capitalised as "Next move" is.

## The drawing's name (`lanes.title`)

Read by a screen reader as the drawing's name. Facts: the run drawn as lanes, side by side, time
running down. Each lane is a column for one stretch of lines that the run goes to: in Module 11 the
main program and a function; in Module 12 the start, the handler and the program. The moves
between lanes are arrows. Do not call the start or the handler part of "the program": in Module
12, "the program" means the user program only. One sentence, no full stop.

## The stack's boxes

- `boxes.stackLabel` — the drawing's name for a screen reader. Facts: the stack drawn as boxes,
  R14's word first, at the top, then the words below it on the stack, grouped by the call that
  pushed them; words a pop has passed are set apart above. Do not say "top of the RAM". One
  sentence, no full stop.
- `boxes.popped` — a heading over words a pop has passed: they are no longer on the stack, but
  still in the RAM, where a push stored them. A few words, no full stop.
