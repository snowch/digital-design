## Keys

### `motivation` (about 260 words)

Keep these facts, in this order:
1. The course's final machine: Module 12's machine of several edges, with its trap hardware, and
   the two instructions you added in your own copy: the call through a register (Module 9) and set
   if (Module 10).
2. What that took: the decoder Module 10's capstone built, which knows kind 9 and kind A; and a
   fifth source for the word register Y takes (after HR, HM, PC + 4 and CWORD): MET as a word, 0 or
   1, chosen by SET.
3. The machine is built from the course's own versions of the parts you designed, often wider
   (its register file has sixteen registers of 64 bits; Module 6's had four words of 4 bits). It
   does not run your own earlier answers: each lesson keeps its own work.
4. A part was tested alone. The machine also needs its parts joined. A bus or a wire between two
   blocks, where one block's output becomes another's input, is called a **join** (bold, plain
   meaning first).
5. Three joins as examples: the control unit sends the control bus, CONTROL, every control signal
   bundled into one bus, to the datapath and the memory port; the datapath sends the instruction in
   the IR to the control unit, which decodes it; the memory port sends FETCHED, the word at the
   address ADDR names, to the datapath. At a FETCH edge ADDR carries the PC, and the IR takes
   FETCHED.
6. A wire's name is on the right side of the block that drives it, where its outputs are, and on
   the left side of each block it enters. Two kinds of exception: HB, the word a store writes,
   enters the memory port under another name, D; and CLK, RST, DOOR, WARM, SENSORA and SENSORB are
   the machine's own inputs, drawn at its left edge, not driven by any block.
7. An instruction's words cross these joins edge by edge; the rest of the lesson follows them.

### `generalisation` (about 90 words)

1. Every machine is built this way: parts, each tested alone, then joined. A part's tests cannot
   test its joins.
2. The joins are tested by running whole programs, compared with the model after every
   instruction. The comparison names the first instruction that disagrees: start looking at the
   joins and the parts that instruction uses. (Do not say again that the course has done this
   since Module 8.)
3. The CPU and the memory are separate blocks joined by buses. Here there are eight: CONTROL, ADDR
   and HB go out to the memory port; FETCHED, MQ, CAUSEF, CAUSEM and WAITING come back. Machines
   far larger keep the same split.

### `c1Hints.1` to `c1Hints.5`

1. The idea: a bus leaves the block that drives it on its right side and enters the blocks that
   read it on their left. Find a bus by what it carries, as Modules 9 and 12 named it.
2. A common mistake: answering for the wrong end. "Reads" asks for the block a bus enters; "drives"
   for the block it leaves.
3. A smaller example, no part of the task: IR leaves the datapath on its right and enters the
   control unit on its left; the control unit reads it.
4. Part of the answer: each kind passes through its own states. A constant job takes FETCH, READ,
   ALU and WRITE. Writing a control register, `C4 <= R1`, takes FETCH, READ and WRITE. A load takes
   FETCH, READ, ALU, MEMORY and WRITE. `call system` takes FETCH and READ, and traps at its READ
   edge. `resume` takes FETCH, READ and WRITE. HB enters the memory port as D.
5. The whole answer: the memory port reads HB, the word a store writes. The memory port drives
   WAITING. The control unit reads STATUS, C0's two bits. The control unit reads CAUSEM. The IR
   takes `resume`'s word at edge 15, and the PC takes `010` at edge 17.
