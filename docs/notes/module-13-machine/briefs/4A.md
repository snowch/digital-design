# Brief 4A: lesson `final-machine` (Module 13, lesson 4), first part

Read `00-module.md` (the shared fact sheet) and `4-shared.md` (this lesson's facts) first; both
apply. You may use CPU, machine code, abstraction, join and trace. This lesson introduces no term.
Call the learner's text "your text" and the machine it describes "your machine". Call the parts
the course supplies "the course's parts".

Keys to write: `question`, `questionLead`, `motivation`, `prediction`, `p1Question`, `p1Explain`.

## The figure in these sections

The `lab-run` figure of `4-shared.md`. In the question, it offers only the course's own text and
all five programs. In the prediction, it offers only the text "The timer counts a trap's edge" and
two programs, the shop's program and "A system call, then the timer", and asks a question before
any run.

## question (about 120 words, above the figure)

1. Lessons 1 to 3 showed the whole machine: its three blocks, the joins between them, and a trace
   from a line of a program down to one gate.
2. Every part of it was built and tested in an earlier module. The joins between the parts were
   drawn for you.
3. This lesson's question: can you join the parts into the whole machine yourself, as text, so that
   it runs every program as the model does?
4. The figure runs the course's own text of the whole machine. It has the five programs the lab's
   tests run.

## questionLead (one or two sentences)

Choose a program and press "Run it". Each run compares the machine with the model after every
instruction and every trap; try all five.

## motivation (about 220 words; a short list allowed)

1. Modules 8 to 10 wrote the machine as text. The text placed parts by name and joined them with
   wires, as the drawing joins blocks.
2. In this lesson you write the top module of the whole machine: the course's nine parts, the joins
   between them, and the small parts between them (list them, as in `4-shared.md`).
3. The course's parts are not your own earlier answers: each lesson keeps its own work. Each of
   the course's parts passes the tests your part passed in its module. The joins are yours.
4. How it is tested: five programs, each reaching a different part of the machine. Name the five,
   one line each, as `4-shared.md` gives them. Each runs on your machine and on the model,
   compared after every instruction and every trap.
5. A test that fails names the first instruction after which the two disagree, and what differs.
   It does not name the join. Finding the join from that sentence is the skill this lesson teaches.

## prediction (about 80 words, above the figure)

1. The text in this figure changes one line: `assign TICK = PCEN;`.
2. TICK tells the timer to count down by one. PCEN, the PC's enable, is 1 at an edge where an
   instruction finishes. It is also 1 at an edge that traps, where the PC takes the handler's
   address.
3. Module 12's rule: a trap's edge finishes no instruction, so the timer does not count it.
4. No result shows until you commit. Choose an answer and press "Check my prediction".

## p1Question (one sentence)

Which of the two programs disagrees with the model on this text?

## p1Explain (about 90 words)

1. Only the timer program disagrees. Its run: "After `call system` at `018`, the timer is 1 on
   the machine and 2 by the model."
2. Why: the program sets the timer to 4. `R1 <= 3` and `C0 <= R1` finish, and the timer is 2.
   `call system` traps. The model does not count a trap's edge; this text does.
3. The shop's program sets no timer, so it never shows the timer's count wrong. A test finds a
   wrong join only where its program reaches it.
4. Run both programs in the figure to see each result.
