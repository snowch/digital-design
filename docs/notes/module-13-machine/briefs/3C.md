# Brief 3C: lesson `tracing` (Module 13, lesson 3), third part

Read `00-module.md` (the shared fact sheet) first and brief 3A's section on the figure; they apply
here. This lesson introduces **abstraction**: set it in bold where it is introduced, in the
explanation, with its plain meaning first. You may use CPU, machine code, join and trace (not
bold).

Keys to write: `explanation`, `generalisation`, `answersLead`, `c1Task`, `c1Hints.1` to
`c1Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 200 words)

1. Each level of the trace hides the level below it. The datapath's drawing shows the ALU as one
   block with words on its ports; it hides the 64 slices. The slice hides its full adder's gates.
   HR hides 64 flip-flops behind one word.
2. The level above may ignore what is hidden because the block's ports say all it needs: the ALU's
   Y is the result, whatever gates made it. Each block was tested on its ports in the module that
   built it, so the level above can trust the ports.
3. Introduce the term: hiding a level's inside behind what its ports do, so that the level above
   can use the block as a box, is **abstraction**. Plain meaning first, the term second, in bold.
4. Module 0 ended on this: each module builds one level from the one below, then uses it as a box.
   A trace goes the other way: it opens the boxes.
5. A trace is how you find a fault: the comparison names the instruction, the value's bits name the
   slice, and the drawing names the wire.

## generalisation (about 110 words)

1. Every machine is built in levels, each a box over the one below. Nobody works on all the levels
   at once: a program uses instructions, an instruction uses blocks, a block uses gates.
2. The boxes make the machine possible to build and to understand. They also hide a fault until
   someone opens them.
3. A trace can start anywhere: a wrong value on the display, a register, a lamp. It ends at a gate
   or a flip-flop, because the drawing of one bit opens no further; Module 4 opened the flip-flop
   itself into gates. (Corrected after the reading review: they are not the course's last level.)
4. The next lesson has you build a level yourself: the whole machine, from its parts, as text.

## c1Task (about 120 words; a numbered list)

1. Each answer is a single bit, 0 or 1, read at a named edge of the shop's program. Use the figure
   under the challenge: pause at the edge, then trace.
2. At the ALU edge of `R3 <= R1 - R2`, at `010`:
   - the output of the XOR gate `xorB` in the ALU's slice for bit 2 (it turns B's bit over for a
     subtraction);
   - SUM out of the full adder in the slice for bit 1.
3. At the WRITE edge of `call R6, R15`, at `02C`: D of the PC's bit 3, as Module 5's drawing shows
   it.
4. At the WRITE edge of `R5 <= R3 >= R4 signed`, at `018`: EN of R5's bit 0, and EN of R4's bit 0,
   as the register file's bit shows them.
5. There are 5 tests, one for each answer.

## c1Hints (five, in this order)

1. The idea: pause before the edge with "Pause before an edge", then open blocks until the wire is
   on the drawing; for a part that never opens, use its button and choose the bit.
2. A common mistake: pausing at the wrong edge of the line. Each line's edges are listed in order
   from its FETCH edge: the ALU edge of a register job is its third.
3. A smaller example: at the ALU edge of `R5 <= R3 >= R4 signed`, SUM in the slice for bit 1 gives
   1, as the investigation found.
4. Part of the answer: the register file writes one register at an edge: EN is 1 only for the
   register Y names. R2 is -250, so B's bit 2 is 1 before the XOR turns it over.
5. The whole answer: 0, 1, 0, 1, 0, in the order of the list.

## reflection (about 70 words)

1. You can now follow any value at any edge from a line of the program down to a gate or a
   flip-flop, and say what each level hides.
2. Every part you traced was the course's. The joins between them were the course's too.
3. End with the next lesson's question: can you join the parts into the whole machine yourself, and
   have it run the shop's programs as the model does?

## modelVsReality (about 70 words)

1. On this machine every instruction takes at most five edges, one per state.
2. A real CPU takes many edges for some instructions: a multiplication, a division, or a word that
   must come from far away in memory. Its controller waits, edge after edge, until the part is done.
3. Nothing of this is taught here. It is named so you know where this machine stops being like a
   real one.
