# Brief 1B: lesson `whole-machine` (Module 13, lesson 1), second part

Read `00-module.md` (the shared fact sheet) first; it applies here. Do not use CPU, machine code or
abstraction in these keys. You may use trap, handler, user mode, system mode, system call and
interrupt (never bold them), and **join**, which brief 1A defines: a bus or a wire between two
blocks (do not bold it again).

Keys to write: `investigation`, `timelineLead`, `timelineAfter`, `construction`, `loadLead`,
`failureExperiment`, `faultsLead`, `faultMq`, `faultNoHandler`, `faultCause`.

## investigation (about 70 words, above a figure)

1. The figure is a timing diagram of the shop's program from edge 57 to edge 68: the system call,
   the handler, `resume` and the return. Each edge keeps its number from the reset.
2. Its lanes are signals that cross joins: FETCHED, from the memory port to the datapath; IR, from
   the datapath to the control unit; TRAP, on the control bus to the datapath; CAUSE, from the
   control unit to the datapath; ADDR, from the datapath to the memory port. There are lanes too for
   S, the controller's state, and the PC.

## timelineLead (one sentence)

Move the cursor edge by edge and find where each word crosses a join.

## timelineAfter (about 130 words)

1. Edge 57 is the FETCH edge of `call system`, at `03C`. ADDR carries the PC, `03C`, to the memory
   port, and FETCHED brings back `80000000`; the IR takes it at edge 57.
2. Before edge 58, the READ edge, the control unit has decoded the IR: TRAP is 1 and CAUSE is `41`.
   At edge 58 the PC takes `044`, the handler's address, C3 takes `41` and C2 takes `040`.
3. Edges 59 to 62 run the handler's store, `word[display] <= R2`. At its MEMORY edge, 62, ADDR
   carries `7C0`, the display's address.
4. At every FETCH edge, ADDR carries the PC. At the other edges it carries HR, the ALU's held result.
5. Edges 63 to 68 run `resume` and `goto R15`. The challenge asks about them.

## construction (about 110 words, above a figure)

Follow one load across the joins: `R1 <= word[sensorA]`, at `008`, edges 8 to 12. The figure
starts after edge 7 and shows FETCHING, MLOAD, HOLDM and WREG, the line, its word, and R1. Facts,
in the order the edges make them:

1. Edge 8, FETCH: FETCHING is 1, so ADDR carries the PC, `008`; FETCHED brings `380017D8` from
   the memory port, and the IR takes it.
2. Edge 9, READ: HA and HB take the words of the registers the instruction names. The control
   unit has already decoded the IR's word as a load (kind 3), so the controller goes on to ALU.
3. Edge 10, ALU: the ALU adds 0 and the constant, `7D8`; HR takes `7D8`.
4. Edge 11, MEMORY: ADDR carries HR, `7D8`, room A's sensor; MQ brings -184 back from the memory
   port, MLOAD and HOLDM are 1, and HM takes it.
5. Edge 12, WRITE: WREG is 1, and R1 takes -184.
6. So the load's words cross five joins: FETCHED, IR, CONTROL, ADDR and MQ.

## loadLead (one sentence)

Press "Next edge" five times, and at each edge find which join carries the load's word.

## failureExperiment (about 90 words, above a figure)

1. Each part of this machine passes the tests it passed in its lesson. A join was never tested by
   those tests: it is tested only when the whole machine runs.
2. The figure runs the shop's program on the machine with one join held at a fixed value, which
   you choose. Under the drawing it compares the machine with the instruction-level model after
   every instruction and every trap, as every machine since Module 8 has been compared, and names
   the first place they disagree.
3. The three joins: MQ, from the memory port to the datapath; NOHANDLER, from the datapath to the
   control unit, 1 when C4 is 0 or holds the PC; CAUSE, from the control unit to the datapath.

## faultsLead (one sentence)

Choose a join, predict which instruction first goes wrong, then press "Run to the end".

## faultMq (about 50 words; shown once that fault has run)

With MQ held at 0, every load reads 0. After `R1 <= word[sensorA]` at `008`, R1 is 0 on the
machine and -184 by the model. The run still stops: the gap is 0, so the display shows 0 and CLASH
stays off. Nothing halts; only the comparison shows the fault.

## faultNoHandler (about 50 words)

With NOHANDLER held at 1, the trap logic sees no handler. At `call system` at `03C` the machine
halts with cause `41`; the model does not. C4 holds `044`, set by the program's second line, but
the control unit never learns it: the join between the two blocks carries the wrong bit.

## faultCause (about 70 words)

With CAUSE held at `00`, the trap still happens, but the datapath receives the wrong cause. C3
takes `00`. C2 takes `03C`, not `040`: the selector that picks the return point reads the cause, and
only cause `41` makes it pick the next instruction. So `resume` goes back to `call system`, which
traps again, over and over. The run is cut off after 300 edges. The comparison names C2 first.
