# Brief R2-5: lesson `capstone` (13.5), after the reading review

Read `00-module.md` and `5-shared.md` first. The facts below replace `5-shared.md` where they
differ. Write only the keys below. Say once, in `motivation`, that the answers depend on the
learner's program; do not say it again in other sections.

## What changed

- **The run strip.** Every figure that traces a run now has, above the drawing, the run's lines,
  each with its edges side by side by state (FETCH, READ, ALU, MEMORY, WRITE), the next edge
  marked. Pressing an edge pauses the run before it. Each edge is numbered from the reset. The
  old "Pause before an edge" lists are gone: do not name them.
- **Pinning.** A wire the learner presses stays marked as blocks open, and its name and value show
  under the drawing.
- **Values are written in hexadecimal** on the drawing, in the levels table and under the drawing
  when a wire is pressed. A question asked in signed decimal needs the learner to read the
  hexadecimal word as a signed number. Say so in the task.
- **RESULT, not Y.** The drawing labels the ALU's output wire RESULT. The wire named Y is the
  instruction's Y field, the register the line writes. Never call the ALU's output Y.
- **The prediction's explanation** shows after the learner presses "Next edge"; the verdict now
  says so. Do not end `p1Explain` by telling the learner to press anything.
- **The investigation's paragraph** (`invAfter`) shows only once the learner has opened the ALU
  inside the datapath.
- **The failure experiment's paragraph** (`failAfter`) shows only after the run with MET held at 0
  has reached its end.
- **The challenge's five questions changed.** Two old ones are gone (the address the memory reads
  at the first store, and D of the PC's bit 4). The five are now listed under `c1Task` below.
- **A fifth program test**, room A 50 and room B -250, that only a comparison read signed passes.
- **The five questions count among the tests**: 5 program tests and 5 questions, 10 in all. A
  question is graded only once the program passes its five program tests.

## The figures' program (checked by running)

```
R1 <= word[sensorA]
R2 <= word[sensorB]
R3 <= R2 < R1 signed     // set if: 1 when room B is colder than room A
R3 <= R3 + R3
R3 <= R3 + R3            // CLASH is bit 2
word[lamps] <= R3
word[display] <= R1
stop
```

Room A reads -184 and room B -250. It runs as the model does, in 31 edges, lights CLASH and shows
room A's reading, -184.

- The prediction's and the investigation's figures are paused before edge 13, the ALU edge of
  `R3 <= R2 < R1 signed` at `008`. The ALU works out A minus B, where A is R2 (-250) and B is R1
  (-184).
- At that edge: RESULT is -66 (`FFFFFFFFFFFFFFBE`), MINUS 1, OVER 0, COUT 0, MET 1. The condition
  block takes the flags and the job digit and gives MET. At the WRITE edge, R3 takes MET as a word.
- Module 3's lesson 4 (the ALU's flags) gave the rule: after A - B, read unsigned, A is less than B
  when COUT is 0. Read unsigned, -250's word (`FFFFFFFFFFFFFF06`) is less than -184's
  (`FFFFFFFFFFFFFF48`), so COUT is 0. Read signed, -250 is less than -184, so MET is 1.
- Here COUT and MET agree, but they answer different questions: COUT answers "is A less than B, read
  unsigned"; MET answers the job's own condition, here "less than, read signed". They disagree when
  one reading is at or above 0 and the other below: A -250 and B 50 give COUT 1 (read unsigned,
  -250's word is the larger) and MET 1. Do not use the word "borrow".
- The failure experiment holds MET at 0. The comparison's sentence, shown after the run: "After
  `R3 <= R2 < R1 signed` at `008`, R3 is 0 on the machine and 1 by the model." Trace back: R3 takes
  the word register Y takes at the WRITE edge; for a set if, that word is MET as a word; MET is 0
  where it leaves the condition block, though the flags say the condition holds.

## The task (checked on the model)

- The program shows on the display how many of the two rooms are colder than -20.0 degrees: 0, 1 or
  2. It lights ALARM, bit 0 of the lamps, when both are, and no lamp otherwise. Then it stops.
  "Colder than -20.0 degrees" is a reading less than -200; exactly -200 is not colder. It must use
  at least one set if.
- The display half is Module 10's lesson 5's count of cold rooms, which that lesson wrote with
  branches and then with set if.
- The lamps are three bits: CLASH, NIGHT, ALARM from left to right.
- Five program tests, each run on the model to its `stop`:
  1. Room A -184, room B -250: display 1, lamps `000`.
  2. Room A -250, room B -250: display 2, lamps `001`.
  3. Room A -150, room B -100: display 0, lamps `000`.
  4. Room A -200, room B -201: display 1, lamps `000`.
  5. Room A 50, room B -250: display 1, lamps `000`. A program whose set ifs read unsigned passes
     the first four and fails this one: read unsigned, 50 is less than -200's word.
- Then five questions about the learner's own program's run on the whole machine, with room A at
  -184 and room B at -250, all paused before the ALU edge of the learner's first set if:
  1. RESULT, the ALU's output, as a signed decimal number;
  2. COUT, the ALU's carry out: 0 or 1;
  3. MET, the branch condition, out of the condition block: 0 or 1;
  4. the output of the XOR gate `xorB` in the ALU's slice for bit 0, the gate that turns B's bit 0
     over for a subtraction: 0 or 1. It is inside the ALU: open `datapath`, `alu`, `g0`, `q0`,
     then `bit0`;
  5. HM, the held word, as a signed decimal number. HM takes the word a load fetched, at a load's
     MEMORY edge only, and holds it through every instruction after, until the next load.
- The answers are read off the recorded run of the learner's own program, so they depend on how it
  is written: which registers, which order of operands, which loads come first. No two programs
  need give the same answers.
- "Run my program on the whole machine" opens the trace figure on the learner's program.
- One program that passes (the course's own), with its answers: 16, 1, 0, 1 and -250. Its text is
  put into hint 5 by the course; write `{program}` and `{answers}` where they go.

## What the lesson adds (for `explanation` and `generalisation`; lesson 3 already said what abstraction is: do not define it again or restate it)

- The questions sit at different levels. COUT and MET are drawn at the datapath level, where they
  leave the ALU and the condition block. RESULT is too. The XOR gate's output shows only inside
  the ALU's slice for bit 0, four blocks below the datapath.
- HM is drawn at the datapath level, but its value at the set if's ALU edge comes from an earlier
  instruction, the last load. The set if's line does not name it. A held word carries an earlier
  instruction's value into a later one's edges.
- The program was the learner's own, and the trace worked on it as it did on the course's programs.
  Do not say which choice in the program changes which answer.
- In the generalisation: designers trace the same way when a test fails on their own design: a
  simulator records every wire at every edge, and they read one wire at one edge, as this lesson
  did. A real CPU has far more wires than this one, too many to draw at once, so their tools show
  the wires they choose as lines over time.

### `reflection` (about 70 words)

You started in Module 0 with the machine as a box that runs lines of a program. You built every
part: gates, adders, registers, memory, the ALU, the datapath, the control unit and the trap
hardware, and joined them. You can follow a line of your own program down to a single gate, at any
edge. Ask: which level was hardest to see through? Which level do you now use without thinking
about the ones below it?

## The course's words for a wrong answer (strings, one or two sentences each; never the value)

- `capLevels.result`: pause before the ALU edge of your first set if; read RESULT where it leaves
  the ALU in the datapath, in hexadecimal, and write it as a signed decimal number.
- `capLevels.carry`: at that same edge, read COUT where it leaves the ALU; it is the carry out of
  the ALU's top bit, not the condition.
- `capLevels.met`: at that same edge, read MET where it leaves the condition block in the datapath;
  it is worked out from the ALU's flags and the job digit.
- `capLevels.xorB`: at that same edge, open the ALU down to the slice `bit0` (`alu`, `g0`, `q0`,
  `bit0`), and read the output of the XOR gate `xorB`.
- `capLevels.held`: at that same edge, read HM in the datapath: it holds the word your last load
  fetched. Write it as a signed decimal number.
