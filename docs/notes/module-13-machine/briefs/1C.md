# Brief 1C: lesson `whole-machine` (Module 13, lesson 1), third part

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**CPU**: set it in bold where it is introduced, in the explanation, with its plain meaning first.
Do not use machine code or abstraction. You may use trap, handler, system call (never bold them),
and **join** (a bus or a wire between two blocks; not bold here).

Keys to write: `explanation`, `generalisation`, `answersLead`, `c1Task`, `c1Hints.1` to
`c1Hints.5`, `reflection`, `modelVsReality`.

## explanation (about 200 words)

1. The whole machine is its parts and the joins between them. Every join is a bus or a wire driven
   by one block and read by another.
2. The control unit decides what each edge does: it decodes the instruction in the IR, steps the
   controller through its states, and sends every control signal on the control bus. The datapath
   holds the registers, the PC, the IR and the control registers, and does the arithmetic. The
   memory port holds the ROM, the RAM and the devices behind one address.
3. The control unit and the datapath, together, are what works out and runs each instruction: the
   machine's **CPU**, its central processing unit. The memory port and what is behind it sit
   outside the CPU. (Introduce the term here: plain meaning first, then the term in bold.)
4. A trap is the whole machine at work: the control unit sees the cause and sends TRAP; at the same
   edge the datapath's control registers and its PC take their words, and the controller goes to
   FETCH.
5. The faults showed that a join can break the machine while every part still passes its own tests.

## generalisation (about 120 words)

1. Every machine is built this way: parts, each tested alone, then joined. A part's tests cannot
   test its joins.
2. The joins are tested by running whole programs and comparing the machine with a model of what
   each instruction should do, after every instruction. The course has done this for every machine
   since Module 8.
3. The comparison names the first instruction that disagrees. That is where to start looking: at
   the joins and the parts that instruction uses.
4. The CPU and the memory are separate blocks joined by a few buses: an address out, a word out,
   a word back. The same split holds in machines far larger than this one.

## answersLead (one sentence, above the challenge)

Read the drawing and the timing diagram, then run the tests.

## c1Task (about 110 words; a numbered list)

1. Open the question's figure, or the failure experiment's, at its top level. For each of four
   buses, choose the block that drives it, the block where the bus leaves on the right side:
   - HB, the word a store writes;
   - WAITING, the events that wait for an interrupt;
   - STATUS, C0's two bits;
   - CAUSEM, the memory step's cause.
2. Use the investigation's timing diagram for two edges, each a number counted from the reset:
   - the edge at which the IR takes `resume`'s word, `81000000`;
   - the edge at which the PC takes the return point, `040`.
3. There are 6 tests, one for each answer.

## c1Hints (five, in this order)

1. The idea: a bus is driven by the block whose right side it leaves, where that block's outputs
   are. It enters other blocks on their left side.
2. A common mistake: choosing the block a bus enters. A bus enters the block that reads it, not the
   one that drives it.
3. A smaller example: IR leaves the datapath on its right side and enters the control unit on its
   left. So the datapath drives IR.
4. Part of the answer: HB and STATUS leave the same block. `resume` takes three edges, FETCH, READ
   and WRITE, and the IR takes its word at the first.
5. The whole answer: HB, the datapath; WAITING, the memory port; STATUS, the datapath; CAUSEM, the
   memory port; the IR takes `resume`'s word at edge 63; the PC takes `040` at edge 65.

## reflection (about 70 words)

1. You have seen the whole machine as its parts and their joins, and an instruction's words crossing
   them edge by edge.
2. Each figure so far showed one view at a time: a drawing, a timing diagram, a table.
3. End with the next lesson's question: can you watch one line of the shop's program at every
   level at once, from the line to the gates, edge by edge?

## modelVsReality (about 70 words)

1. A real CPU has the same blocks, but it runs several instructions at once: while one instruction
   is at its MEMORY edge, the next is at its ALU edge and the one after is being fetched.
2. This machine runs one instruction at a time, so every edge belongs to one instruction.
3. Nothing of the overlapping is taught here. It is named so you know where this machine stops
   being like a real one.
