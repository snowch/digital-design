### `explanation` (about 200 words)

"Agree" means two different things; keep them apart.
1. Every level shows the circuit's real value. From the word down, every level reads the same wires
   of the same circuit at the same edge: the table's fields are the IR's bits in groups of four, the
   control signals are wires of the control unit, the drawing's values come from the circuit. So a
   level cannot show a different value from the one below it; it can only leave things out (the
   table shows a few signals; the top of the drawing shows three blocks, not their gates). The line
   is the only level outside the circuit: the assembler made the machine code before the run.
2. Every level describing the same instruction is another matter. In a healthy machine the
   signals do what the word asks. With BCONST held at 1, every level still showed real values, but
   they no longer described the same instruction: the word said B is R2, BCONST said the constant,
   and the ALU did what BCONST said.
3. The comparison with the model finds that second kind of disagreement, at the first instruction
   where it shows; the levels show where it comes from.

### `generalisation` (about 80 words)

1. Every program reaches a machine as machine code: whatever language it was written in, the
   machine runs words like `A7345000`.
2. The stages: fetch, decode, register read, ALU, memory, register write and PC update. Each but
   two is an edge of the controller's state; decode is the decoder's gates between two edges; PC
   update is the instruction's last edge, whichever state that is.
3. Being able to pause at any edge and open any wire, at any level, is what the next lesson uses to
   follow a value of your own choosing down to a gate.

### `c1Task`

1. Work out, without running anything: the machine code of `R9 <= R2 >= R7 unsigned`, as eight
   hexadecimal digits. It is not a line of the shop's program. Set if's job 5 is not less, read
   unsigned.
2. The line `R4 <= word[R2]` sits at `01C` in a program no figure runs. When it runs, R2 holds
   1024, and the word at address 1024 (`400`) holds 25. Work out, without running anything:
   - how many edges it takes, from its FETCH edge to its last;
   - the ALU's job at its ALU edge, by OP2 OP1 OP0: add, subtract, copy B or OR;
   - the word register Y takes at its WRITE edge, as a decimal number;
   - the PC after its last edge, as three hexadecimal digits.
3. There are 5 tests, one for each answer.

### `c1Hints.1` to `c1Hints.5`

1. The idea: a word's eight digits are its fields in order: K, J, A, B, Y, then three digits of
   constant. The other answers follow from the states a load takes and what each state does.
2. A common mistake: taking the ALU's result for the word a load writes.
3. A smaller example, no part of the task: `R4 <= 100` is `25004064`: kind 2, job 5, A 0, B 0, Y 4,
   constant `064`.
4. Part of the answer: set if is kind A. A load works out its address in the ALU, the register A
   names plus the constant, and takes the word at that address at its MEMORY edge.
5. The whole answer: `A5279000`. It takes 5 edges. The ALU's job is add. Y takes 25, and the PC
   after the last edge is `020`.
