# Brief 2A: lesson `full-path` (Module 13, lesson 2), first part

Read `00-module.md` (the shared fact sheet) first; it applies here. This lesson introduces
**machine code**: set it in bold where it is introduced, in the motivation, with its plain meaning
first. You may use CPU (lesson 1 introduced it: the control unit and the datapath, which work out
and run each instruction) and **join** (lesson 1: a bus or a wire between two blocks), not bold. Do
not use abstraction.

Keys to write: `question`, `wholeLead`, `wholeAfter`, `motivation`, `prediction`, `p1Question`,
`p1Explain`.

## The figure in every section of this lesson

The whole machine runs the shop's program, recorded edge by edge. Its buttons: "Next edge", "Step
back", "Run to the end", "Start again". Under them, a line says where the run is. Then a table, "The
instruction at every level", with these rows: Line (the line of the program the edge belongs to);
Address; Its word in the ROM (the word the assembler made for that line); The word in the IR, with
its fields (K, J, A, B, Y and the constant); The controller's state (the state the next edge is
made in); and the control signals OP2, OP1, OP0, WRITEY, SET and TRAP at the next edge. Then the
drawing, which opens down to the gates, every value on it the value at the same edge. Then tables
of R1 to R5 and of the devices.

## wholeAfter (about 50 words; shown once the run has reached its end)

The run stops at `030`, at `stop`, after 69 edges. The display shows 66, the gap between the rooms,

## motivation (about 260 words; a short list allowed)

1. Each level shows one instruction in its own form.
2. The line is text, such as `R5 <= R3 >= R4 signed`. The assembler, a program, turns each line into
   a word of 32 bits before the machine runs: here `A7345000`. Introduce the term: the words the
   assembler makes from the lines, the form the machine runs, are the program's **machine code**.
   The ROM holds the shop's program as machine code; the machine never sees the lines.
3. The IR holds the word being run, and its digits are its fields: K, J, A, B, Y and the
   constant. For `A7345000`: kind A, set if; job 7, not less, read signed; A is R3, B is R4, Y is
   R5; the constant `000`, unused.
4. The decoder turns the fields into control signals: for set if, OP2 OP1 OP0 are `011`, subtract;
   WRITEY is 1; SET is 1.
5. The controller's state says which step the next edge makes. Where each stage of the
   demonstration happens, as a list:
   - fetch: the FETCH edge, where the IR takes the word;
   - decode: the gates of the decoder, from the moment the IR holds the word; it takes no edge of
     its own;
   - register read: the READ edge, where HA and HB take registers A and B;
   - ALU: the ALU edge, where HR takes the result;
   - memory: the MEMORY edge, for a load or a store;
   - register write: the WRITE edge, where register Y takes its word;
   - PC update: the instruction's last edge, where the PC takes its next value; then the next
     instruction's FETCH.
6. Not every instruction passes every state: `R5 <= R3 >= R4 signed` takes FETCH, READ, ALU and
   WRITE, four edges, and no MEMORY.

## p1Question (one sentence)

What word will the IR hold after the next edge?

## p1Explain (about 80 words)

1. The IR takes `A7345000`: kind A (set if), job 7 (not less, signed), A is R3, B is R4, Y is R5,
   constant `000`.
2. `A7435000` swaps the two registers read, which would test R4 against R3.
3. `57345000` is kind 5, a branch, which compares but writes no register.
4. `25004064` is the word the IR holds now, `R4 <= 100`: the IR keeps it until the FETCH edge.
5. Press "Next edge" and read the row "The word in the IR".
