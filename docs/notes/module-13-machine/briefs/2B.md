# Brief 2B: lesson `full-path` (Module 13, lesson 2), second part

Read `00-module.md` (the shared fact sheet) first; it applies here, with brief 2A's description of
the figure. You may use CPU, **join** and **machine code** (the words the assembler makes from the
lines, the form the machine runs; not bold here). Do not use abstraction.

Keys to write: `investigation`, `callLead`, `callAfter`, `construction`, `storeLead`,
`failureExperiment`, `faultsLead`, `faultBconst`, `faultSet`.

## investigation (about 50 words, above the figure)

The figure starts after edge 56: the next edge fetches `call system`, at `03C`. It shows the
control registers too. Follow the system call at every level, then the handler's first edge.

## callLead (a numbered list of three steps)

1. Press "Next edge" once and read the row "The word in the IR" and its fields.
2. Read the state, TRAP and the line under the buttons.
3. Press "Next edge" again and read the PC and the control registers.

## callAfter (about 110 words)

1. At edge 57, FETCH, the IR takes `80000000`, the machine code of `call system`: K 8, a system
   job; J 0, `call system`; every other field 0.
2. The next state is READ, and TRAP is 1: the decoder has given cause `41`, and the trap logic
   has set TRAP. The line under the buttons says the next edge traps, with cause `41`.
3. At edge 58 the PC takes `044`, the handler's address from C4; C3 takes `41`; C2 takes `040`, the
   line after the call. The state goes to FETCH.
4. Every level agreed at every edge: the line said `call system`, the word said kind 8 job 0, the
   signals trapped, and the registers took the trap's words.

## construction (about 140 words, a numbered list after one sentence)

Work out one store at every level before you run it: `word[lamps] <= R5`, at `024`, edges 38 to
41. Facts:

1. Its machine code is `480507C8`: K 4, a store; J 8, an address given by the constant alone; A 0,
   unused; B 5, the register stored; Y 0, unused; the constant `7C8`, the lamps' address.
2. Edge 38, FETCH: the IR takes `480507C8`.
3. Edge 39, READ: HB takes R5, which holds 0.
4. Edge 40, ALU: OP2 OP1 OP0 are `010`, add; the ALU adds 0 and the constant, and HR takes `7C8`.
5. Edge 41, MEMORY: ADDR carries `7C8`, MSTORE is 1, and the lamps take `000`. PCEN is 1 too: a
   store ends at its MEMORY edge, and the PC takes `028`.

## storeLead (one sentence)

Press "Next edge" four times and check each step of the list against the table and the drawing.

## failureExperiment (about 90 words, above the figure)

1. Every level agrees in a healthy machine, because they are one circuit seen at different sizes.
2. The figure lets you break one control signal inside the decoder. The line and its machine code
   stay right; the machine does something else.
3. Under the drawing it compares the machine with the instruction-level model after every
   instruction and every trap, and names the first place they disagree.
4. The two faults: BCONST held at 1, so the ALU's B input always takes the constant; SET held at 0
   in the control unit, where SET is kind A's line in the decoder.

## faultsLead (one sentence)

Choose a fault, predict which line first goes wrong, then press "Run to the end" and read the
comparison.

## faultBconst (about 60 words)

1. With BCONST held at 1, the loads still work: a load takes the constant as B anyway.
2. The first disagreement is `R3 <= R1 - R2`, at `010`: R3 is -184 on the machine and 66 by the
   model. The ALU took the constant, 0, in place of R2.
3. The run still stops, showing 0 on the display.

## faultSet (about 80 words)

1. With SET held at 0 in the control unit, the decoder has no line for kind A. It refuses
   `R5 <= R3 >= R4 signed` as an illegal instruction, cause `21`, and the machine goes to the
   handler.
2. The comparison says: after that line, at `018`, the PC is `044` on the machine and `01C` by the
   model.
3. The handler shows R2, -250, and resumes at the refused line, which traps again, over and over.
   The run is cut off after 300 edges.
