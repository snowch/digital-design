## The figures' program (new; checked by running)

```
R1 <= word[sensorA]
R2 <= word[sensorB]
R3 <= R1 - R2            // the gap, room A minus room B
R4 <= word[limit]        // 10.0 degrees
R5 <= R3 < R4 signed     // set if: 1 when the gap is less than the limit
word[display] <= R5
stop
limit:  word 100
```

Room A reads -184 and room B -250. It shows 1 on the display (the gap, 66, is less than 100). It
runs as the model does, in 28 edges.

- The prediction's and the investigation's figures are paused before edge 22, the ALU edge of
  `R5 <= R3 < R4 signed` at `010`. The ALU works out A minus B: A is R3, the gap, 66; B is R4, the
  limit, 100.
- At that edge: RESULT -34; ZERO 0, MINUS 1, COUT 0, OVER 0; MET 1. HM holds 100, the word the last
  load fetched (the limit). The set if writes MET into R5 at its WRITE edge.
- In Module 3's terms: after A - B, read unsigned, A is less than B when COUT is 0. 66 is less than
  100 read unsigned, so COUT is 0; read signed it is less too, so MET (the job "less than, read
  signed") is 1. Same verdict, different bits. They disagree when one value is at or above 0 and
  the other below: A -250 and B 50 give COUT 1 and MET 1.
- MET held at 0: the comparison's sentence is "After `R5 <= R3 < R4 signed` at `010`, R5 is 0 on the
  machine and 1 by the model." R5 takes MET as a word at the WRITE edge; MET is 0 where it leaves
  the condition block, though the flags say the condition holds.
