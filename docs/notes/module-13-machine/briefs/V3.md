# Brief V3: the lab's own words: buttons, run sentences, and the comments in the texts

Read `00-module.md` and `4-shared.md` first. These are short strings on controls and in program
text. Buttons and list names: a few words, capital first letter, no full stop. A sentence ends with
a full stop. Keep every `{slot}` exactly as given, once. A comment in a program text is one line of
at most about 90 characters, starting with a capital letter; a heading comment ends with no full
stop; a comment that is a sentence ends with a full stop. Write "start" for a way in.

## Buttons and lists (one line each)

- `labOutline`: button: start from the outline. `labParts`: button: start from the parts.
  `labEmpty`: button: start from nothing.
- `labReplace`: button that confirms replacing the learner's text with that start.
  `labKeep`: button that keeps the learner's text.
- `labTextLegend`: the list choosing which text runs. `labProgramLegend`: the list choosing which
  program runs. `labRun`: button that runs it. `labRunning`: the same button while a run goes.
- `labChange`: heading over the one line a text changes. `labRunsCaption`: heading over the list
  of runs so far.

## Sentences (keep each slot)

- `labRunLine`: one run: "{text}, {program}: {result}" (keep as it is).
- `labRunAgrees`: a run where the machine and the model agree after every one of its {n}
  instructions and traps.
- `labRunStops`: at `{line}` at `{address}`, the machine stops; the model does not.
- `labRunGoesOn`: at `{line}` at `{address}`, the model stops or halts; the machine goes on.
- `labDiffers`: after `{line}` at `{address}`, {what} is {machine} on your machine and {model} by
  the model.
- `labHalts`: at `{line}` at `{address}`, your machine halts with cause `{cause}`; the model does
  not.
- `labStopsOnly`: at `{line}` at `{address}`, your machine stops; the model does not.
- `labRunsOn`: at `{line}` at `{address}`, the model stops or halts; your machine goes on.

## Comments in the course's text of the machine (one line each, a heading: no full stop)

- `textPc`: the PC, and the address the memory's one port reads.
- `textMemory`: the memory: the ROM, the RAM and the devices.
- `textIr`: the IR.
- `textControl`: the control unit: the decoder, the system jobs, the mode, the controller and the
  trap logic.
- `textRegisters`: the registers, and the words held between edges.
- `textAlu`: the ALU and its inputs.
- `textCregs`: the control registers.
- `textY`: the word that register Y takes.
- `textNext`: the next PC.

## The six JOIN comments (each begins exactly `JOIN: `, then a few words, no full stop)

Each names what the join carries and where it comes from, never the wire's name.

- `joinUser`: user mode, from C0.
- `joinWaiting`: the events waiting, from the memory.
- `joinNoHandler`: whether a handler is set, from the control registers.
- `joinCause`: the cause of a trap, from the trap logic.
- `joinSet`: set if's condition, as the word Y takes.
- `joinTrap`: where a trap's edge sends the PC.

## The comment lines that open the two other starts

- `parts.1` to `parts.4` (a sentence each): every part the course supplies is placed below, with
  all its ports and none joined; join each port, inside its brackets, to a wire; the wires are
  declared above, named as the drawing names them; write the small parts between the parts: the
  PC, the address the memory reads, the IR, the held words, USER and IE, TICK, WIDE, the ALU's
  two inputs, the word Y takes, the target and the next PC.
- `empty.1` to `empty.3` (a sentence each): only the machine's ports are given; the parts the
  course supplies are memory, decoder, system, controller, traplogic, cregs, registers, alu and
  condition; the parts start lists their ports. Write these names in backticks.
