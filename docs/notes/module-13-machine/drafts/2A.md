motivation: Each level of the drawing shows the same instruction in its own form. The first form is the line of text, such as `R5 <= R3 >= R4 signed`. An assembler, which is a program, turns each line into a 32-bit instruction before the machine runs. Here the line becomes `A7345000`. The words the assembler makes from the lines are the form the machine runs. They are the program's **machine code**. The ROM holds the shop's program as machine code, and the machine never sees the lines.

The IR holds the instruction being run. Its eight hexadecimal digits are its fields: K, J, A, B, Y and the constant. In `A7345000`, K is A, which is set if. J is 7, which is not less, read signed. A is R3, B is R4 and Y is R5. The constant `000` is unused.

The decoder turns the fields into control signals. For set if, OP2, OP1 and OP0 are `011`, which subtracts. WRITEY is 1, and SET is 1.

The controller's state says which step the next edge makes. Each stage of the demonstration happens at one of these points:

- fetch: the FETCH edge, where the IR takes the word;
- decode: the gates of the decoder, from the moment the IR holds the word; it takes no edge of its own;
- register read: the READ edge, where HA and HB take registers A and B;
- ALU: the ALU edge, where HR takes the result;
- memory: the MEMORY edge, for a load or a store;
- register write: the WRITE edge, where the register Y names takes its word;
- PC update: the instruction's last edge, where the PC takes its next value; then the next instruction's FETCH.

Not every instruction passes every state. `R5 <= R3 >= R4 signed` takes FETCH, READ, ALU and WRITE: four edges, and no MEMORY.
