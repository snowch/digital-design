motivation: Modules 8 to 10 wrote the machine as text. You placed its parts by name and joined them with wires.

Here you write the top module of the whole machine, `machine`, in the subset Modules 8 to 10 used. It needs no new construct. The course supplies nine parts: `memory`, `decoder`, `system`, `controller`, `traplogic`, `cregs`, `registers`, `alu` and `condition`. You write the joins between them, and the small parts between them. These are:

- the PC;
- the address the memory reads;
- the IR;
- the held words HA, HB, HR and HM;
- USER and IE, from C0;
- TICK, which tells the timer to count;
- the constant made a word, WIDE;
- the ALU's two inputs;
- the word register Y takes;
- the target of a branch;
- the next PC.

The parts are the course's own versions of the parts you designed. The machine does not run your earlier answers. The joins are yours.

Seven programs test your machine, and each reaches a different part of it. Each count is the instructions and traps that run has.

- The shop's program: a set if, a call through a register, a system call and `resume`. 19 instructions and traps.
- A fault in user mode: user mode refuses a device's address, with cause `32`. 11 instructions and traps.
- A system call, then the timer: the program sets the timer to 4 at `00C` and makes a system call at `018`. The timer later interrupts it, with cause `81`. 17 instructions and traps.
- The door: the door opens while the program runs, and the program is interrupted, with cause `82`. 10 instructions and traps.
- Signs, bytes and WARM: a constant whose sign matters (-5), a set if whose condition holds, a comparison read unsigned, a subtraction that overflows, a byte stored and loaded, and the word of DOOR and WARM read with WARM at 1, and a call to a label above the call. 15 instructions and traps.
- A system job in user mode: the program drops to user mode and runs `stop`, which user mode refuses, with cause `22`. The handler shows the cause. 11 instructions and traps.
- A store to the ROM: with no handler, the store traps with cause `34`, and the machine halts. 2 instructions and traps.

Each program runs on your machine and on the model. The comparison is made after every instruction and every trap. A test fails at the first instruction or trap after which the two disagree. Its sentence names that line, its address, what differs, and the value on your machine and by the model. It does not name the join. Finding the join from that sentence is the skill this lesson teaches.

explanation: The comparison finds a wrong join at the first instruction or trap its effect reaches, not at the end of the program.

A wrong line shows only where a program reaches it. The timer's count shows only at an edge that traps while the timer runs. A branch's condition shows only where a branch is not taken. The door shows only where it opens.

The sentence names a value, and that value points at a part. Look up the part in this list:

- the PC: the next PC's choice, or a trap or `resume` that set it;
- a register: the word register Y takes, or the register file's write;
- C0 to C4: the control registers. C0 holds the mode and whether interrupts are on; at a trap it takes `01`, and at `resume` it takes C1. C1 takes C0 at a trap. C2 takes the return point and C3 takes the cause at a trap. C4 holds the handler's address, which the program writes;
- the timer or "waiting": the memory's events, and what the memory takes in;
- a byte of the RAM (a sentence such as "byte 401 is 255 on your machine and unknown by the model"): the memory, and the store that wrote it;
- a halt or a stop where the model goes on, or the reverse: the trap logic, which decides both a halt and a stop (it holds Module 9's stop logic), and what it takes in.

generalisation: Lesson 1's "Testing the joins" says that a join is tested only by running whole programs. Teams that design a CPU test them as this lesson did: the same programs run on the design and on a model, with the comparison as this lesson made it. They run many more programs than seven, many of them made at random. They also measure which parts the programs reached.

Programs that agree do not prove a design right. They show only that no program reached a wrong part. The text with one join wrong agreed with the model on six of the seven programs.

The fix is a program that reaches the part, as the door program reaches the door.
