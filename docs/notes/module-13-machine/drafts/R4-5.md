question: Module 0 began with the machine as a box that runs lines of a program. Lesson 3 traced one value of your choosing down to a single gate, and lesson 4 joined the parts into the whole machine. Can you write a program of your own, run it on the whole machine, and answer questions about your own run that a trace answers directly?

The figure runs a short program written for this lesson, not for the challenge. It shows 1 on the display when room B is less than 10.0 degrees warmer than room A. It is paused before edge 22, the ALU edge of its set if.

motivation: The display half is the count of cold rooms from Module 10's lesson 5, which that lesson wrote with branches and then with set if.

Then the challenge asks questions about your own run on the whole machine, each paused before the ALU edge of your first set if: the ALU's result, a row of its flags and MET, a row of carries inside the ALU, and a held word.

The answers are read off the run of your own program, so they depend on how you wrote it. No two programs need give the same answers.

When an answer is wrong, the course tells you which level to look at and what to read there. It never gives you the value.

The figures practise reading the datapath on the figure's own program.

prediction: The figure is paused before edge 22, the ALU edge of `R5 <= R3 < R4 signed` at `010`. The ALU works out R3 minus R4: the gap, -66, minus the limit, 100. Module 3's rule says that after A minus B, read unsigned, A is less than B when COUT is 0. Here A is R3 and B is R4. The question asks about COUT. No value shows until you commit. Choose an answer and press "Check my prediction".

p1Question: After the next edge, what does COUT hold?

p1Explain: COUT is 1. Read unsigned, the word for -66 is the larger, so A is not less than B. RESULT is -166, with MINUS 1. COUT leaves the ALU in the datapath.

investigation: Stay at edge 22. Find MET where it leaves the condition block, beside the ALU, and compare it with COUT. Predict first: is MET 1 or 0?

invLead: Open the datapath. RESULT and the flags leave the ALU there, and MET leaves the condition block beside it.

invAfter: MET is 1, COUT is 1, and RESULT is -166. MET answers the job's condition: less than, read signed. -66 is less than 100, so MET is 1. COUT answers Module 3's question, read unsigned: 1 says A is not less than B. The same subtraction gives opposite verdicts, because its operands have opposite signs.

A question about one wire is answered by reading that wire at that edge.

construction: 1. Write the program in the editor. It assembles as you type, and a line it cannot read is named.
2. Press "Run tests". The program tests run on the model. Once the program passes them, the questions are graded.
3. Press "Run my program on the whole machine". The trace figure opens on your program, with room A at -184 and room B at -250. Every question is about this run.
4. In the run, find your first set if, and press its ALU edge.
5. Open the blocks to the wire a question names, and read its value. Press a wire to pin it; its value shows under the drawing. Values in the drawing and the table of levels are hexadecimal: turn a word into a signed decimal number where a question asks for one. Where the trace shows X, write X.
6. If you change the program, run it again. The answers belong to the run of the program you graded.

failureExperiment: The figure's machine holds MET at 0, as if the condition block's output were joined to 0. The comparison with the instruction-level model runs beside it. Run it, read the first difference, and trace it back to the wire.

failLead: Choose the fault, run to the end, and read the comparison.

failAfter: The comparison's sentence: "After `R5 <= R3 < R4 signed` at `010`, R5 is 0 on the machine and 1 by the model."

Trace back from R5. R5 takes the word the datapath writes at the WRITE edge. For a set if, that word is MET as a word. MET is 0 where it leaves the condition block, though the flags say the condition holds. The comparison named a register and a line. The trace found the wire.

explanation: RESULT, the flags and MET are drawn at the datapath level, where they leave the ALU and the condition block. The carries for bits 7 to 4 are drawn inside the ALU's group `q1`, three levels below the datapath (`alu`, `g0`, `q1`).

HM is drawn at the datapath level. Its value at the ALU edge of your first set if was written at an earlier edge, by an earlier instruction. The set if's line does not name it. A held word such as HR or HM keeps its value across later instructions' edges until its own enable writes it again.

c1Task: 1. Write a program for the shop that shows on the display how many of the two rooms are colder than -20.0 degrees: 0, 1 or 2. It lights ALARM, bit 0 of the lamps, when both rooms are, and no lamp otherwise. Then it stops. "Colder than -20.0 degrees" means a reading less than -200. A reading of exactly -200 is not colder. A set if writes 1 into the register it names when its condition holds, and 0 when it does not. The program must use at least one set if.
2. The lamps are three bits: CLASH, NIGHT, ALARM from left to right.
3. The seven program tests, each run on the model to its `stop`:
   1. Room A -184, room B -250: display 1, lamps `000`.
   2. Room A -250, room B -250: display 2, lamps `001`.
   3. Room A -150, room B -100: display 0, lamps `000`.
   4. Room A -200, room B -201: display 1, lamps `000`.
   5. Room A 50, room B -250: display 1, lamps `000`.
   6. Room A -250, room B 50: display 1, lamps `000`.
   7. Room A -201, room B -200: display 1, lamps `000`.
4. Then four questions about your program's run on the whole machine, with room A at -184 and room B at -250. All four are paused before the ALU edge of your first set if:
   1. RESULT, the ALU's output, as a signed decimal number.
   2. The ALU's four flags ZERO, MINUS, COUT and OVER, then MET, in that order: a row of five bits, 0 or 1.
   3. The carry out of each of the ALU's slices for bits 7 to 4, bit 7 first: the slices `bit3` to `bit0` of the group `q1` (inside `datapath`, `alu`, `g0`). A row of four bits, 0 or 1.
   4. HM, a held word, as a signed decimal number.
5. Where the trace shows X, a wire whose value is not known yet, the answer is X.
6. The drawing and the table of levels write values in hexadecimal. RESULT and HM are asked as signed decimal numbers. (The registers and the devices tables write decimal.)
7. There are 11 tests: the seven program tests, then the four questions. A question is graded only once your program passes its seven program tests.
8. Press "Run my program on the whole machine" to trace it.

c1Hints.1: The idea: two set ifs, one for each room, each comparing the room with -200, read signed. Then press the ALU edge of the first set if in the run, and open the blocks to each wire.

c1Hints.2: A common mistake is a set if read unsigned. It fails the test where that room reads 50. Another is answering in hexadecimal where a signed decimal number is asked.

c1Hints.3: A smaller example, from the figure: at the ALU edge of `R5 <= R3 < R4 signed`, COUT is 1 and MET is 1. Read COUT where it leaves the ALU, and MET where it leaves the condition block.

c1Hints.4: Part of the answer: the count is the sum of the two set ifs' words, and ALARM is their AND, written to the lamps. The carries for bits 7 to 4 are in the slices `bit3` to `bit0` of the group `q1`, inside `datapath`, `alu` and `g0`. The carry out of `bit3` is C8, and the others are C3, C2 and C1. HM holds the word the last load fetched.

modelVsReality: Real designs are checked with a testbench: a text in the same language that drives the machine's inputs, waits, and prints what it sees. Below is a short one for the course's machine, to read.

```systemverilog
module machine_test;
  logic CLK = 0, RST = 1, DOOR = 0, WARM = 0;
  logic [63:0] SENSORA = -184, SENSORB = -250;
  logic [63:0] PC, DISPLAY;
  logic [2:0] S, LAMPS;
  logic HALT;
  logic [7:0] CAUSE;

  machine m (.*);

  always #5 CLK = ~CLK;

  initial begin
    #12 RST = 0;
    wait (HALT);
    $display("display %0d, lamps %b", $signed(DISPLAY), LAMPS);
    $finish;
  end
endmodule
```

`.*` joins each of the machine's ports to the wire of the same name. `always #5` turns the clock over every 5 units of simulated time. `initial` runs its lines once, from the start. `#12` waits 12 units, so the reset holds over the first rising edge. `wait (HALT)` waits until HALT is 1, which happens when the machine stops and when it halts. `$display` prints the display and the lamps.

The course's engine does not run this text. It describes a test, not hardware. Tools that simulate SystemVerilog run it. They would also need the text of each of the course's parts, which the course's engine builds itself, and the program in the ROM.
