Its lanes are signals that cross joins. FETCHED runs from the memory port to the datapath. IR runs from the datapath to the control unit. TRAP runs on the control bus to the datapath. CAUSE runs from the control unit to the datapath. ADDR runs from the datapath to the memory port. There are lanes too for S, the controller's state, and for the PC.

construction: Follow one load across the joins: `R1 <= word[sensorA]`, at `008`, on edges 8 to 12. The figure starts after edge 7. It shows FETCHING, MLOAD, HOLDM and WREG, the line, its word and R1.

1. Edge 8, FETCH: FETCHING is 1. ADDR carries the PC, `008`. FETCHED brings `380017D8` from the memory port, and the IR takes it.
2. Edge 9, READ: HA and HB take the values of the registers the instruction names. The control unit has already decoded the IR's word as a load (kind 3), so the controller goes on to ALU.
3. Edge 10, ALU: the ALU adds 0 and the constant, `7D8`. HR takes `7D8`.
4. Edge 11, MEMORY: ADDR carries HR, `7D8`, room A's sensor. MQ brings -184 back from the memory port. MLOAD and HOLDM are 1, and HM takes -184.
5. Edge 12, WRITE: WREG is 1, and R1 takes -184.
6. So the load's values cross five joins: FETCHED, IR, CONTROL, ADDR and MQ.

failureExperiment: 1. Each part of this machine passes the tests it passed in its lesson. Those tests never covered a join. A join is tested only when the whole machine runs.
2. The figure runs the shop's program with one join held at a fixed value that you choose. Under the drawing, it compares the machine with the instruction-level model after every instruction and every trap, as every machine since Module 8 has been compared. It names the first place they disagree.
3. The three joins are: MQ, from the memory port to the datapath; NOHANDLER, from the datapath to the control unit, 1 when C4 is 0 or holds the PC; and CAUSE, from the control unit to the datapath.

faultsLead: Choose a join, predict which instruction first goes wrong, then press "Run to the end".

faultMq: With MQ held at 0, every load reads 0. After `R1 <= word[sensorA]` at `008`, R1 is 0 on the machine and -184 by the model. The run still stops: the gap is 0, so the display shows 0 and CLASH stays off. Nothing halts. Only the comparison shows the fault.

faultNoHandler: With NOHANDLER held at 1, the trap logic sees no handler. At `call system`, at `03C`, the machine halts with cause `41`. The model does not. C4 holds `044`, set by the program's second line, but the control unit never learns it: the join between the datapath and the control unit carries the wrong bit.

faultCause: With CAUSE held at `00`, the trap still happens, but the datapath receives the wrong cause. C3 takes `00`. C2 takes `03C`, not `040`. The selector that picks the return point reads the cause, and only cause `41` makes it pick the next instruction. So `resume` goes back to `call system`, which traps again, over and over. The figure cuts the run off after 300 edges. The comparison names C2 first.
