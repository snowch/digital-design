question: Module 0 began with the machine as a box that runs lines of a program. Lesson 3 traced one value of your choosing down to a single gate, and lesson 4 joined the parts into the whole machine. Can you write a program of your own, run it on the whole machine, and answer questions about your own run that a trace answers directly?

The figure runs a short program written for this lesson, not for the challenge. It shows 1 on the display when room A is less than 10.0 degrees warmer than room B.

motivation: The challenge asks for a program that shows on the display how many of the two rooms are colder than -20.0 degrees (0, 1 or 2), lights ALARM when both are, and stops. The program must use at least one set if.

The display half is the count of cold rooms from Module 10's lesson 5, which that lesson wrote with branches and then with set if.

Then the challenge asks four questions about your own run on the whole machine, each paused before the ALU edge of your first set if: the ALU's result, a row of the ALU's flags and MET, a row of gates' outputs inside the ALU, and a held word.

The answers are read off the run of your own program, so they depend on how you wrote it. No two programs need give the same answers.

When an answer is wrong, the course tells you which level to look at and what to read there. It never gives you the value.

The figures practise reading the datapath on the figure's own program.

prediction: The figure is paused before edge 22, the ALU edge of `R5 <= R3 < R4 signed` at `010`. The ALU works out R3 minus R4: the gap, 66, minus the limit, 100. The set if writes MET into R5 at its WRITE edge: 1 if the condition holds, else 0. No value shows until you commit. Choose an answer and press "Check my prediction".

p1Explain: MET holds 1: 66 is less than 100, read signed. RESULT is -34, with MINUS 1 and OVER 0. The condition block takes the flags and the job digit and gives MET; find MET where it leaves the condition block in the datapath. At the WRITE edge, R5 takes it as a word.

investigation: Stay at this edge, edge 22. Find COUT, the ALU's carry out, and compare it with MET. Recall Module 3's rule, in its terms: after A minus B, read unsigned, A is less than B when COUT is 0. Here A is R3, the gap, and B is R4, the limit. Predict first: is COUT 1 or 0?

invLead: Open the datapath. RESULT and the flags leave the ALU there, and MET leaves the condition block beside it.

invAfter: COUT is 0, RESULT is -34, MET is 1. Module 3's rule reads COUT with the two words read unsigned. After A minus B, A is less than B when COUT is 0. Here A is R3, the gap, and B is R4, the limit. 66 is less than 100 read unsigned, so COUT is 0.

COUT and MET reach the same verdict here, with different bits. COUT answers whether A is less than B, read unsigned. MET answers the job's own condition: less than, read signed. The two can disagree. Take A -250 and B 50. COUT is 1, because -250's word is the larger when read unsigned. MET is also 1, because -250 is less than 50 when read signed. The bits match, but the verdicts are opposite.

A question about one wire is answered by reading that wire at that edge.

Trace back from R5. R5 takes the word the datapath writes at the WRITE edge. For a set if, that word is MET as a word. MET is 0 where it leaves the condition block, though the flags say the condition holds. The comparison named a register and a line. The trace found the wire.

explanation: RESULT, the flags and MET are drawn at the datapath level, where they leave the ALU and the condition block. The XOR outputs show only inside the ALU's slices, four blocks below the datapath.

HM is also drawn at the datapath level. Its value at the ALU edge of this set if was written at an earlier edge, by an earlier instruction. The set if's line does not name it. A held word such as HR or HM keeps its value across later instructions' edges until its own enable writes it again.

generalisation: When a test fails on their own design, designers read one wire at one edge, the way this lesson did. A simulator records every wire at every edge. A real CPU has far more wires than this machine, too many to draw at once. So their tools show the wires they choose, as lines over time.

c1Task: 1. Write a program for the shop that shows on the display how many of the two rooms are colder than -20.0 degrees: 0, 1 or 2. It lights ALARM, bit 0 of the lamps, when both rooms are, and no lamp otherwise. Then it stops. "Colder than -20.0 degrees" means a reading less than -200. A reading of exactly -200 is not colder. A set if writes 1 into the register it names when its condition holds, and 0 when it does not. The program must use at least one set if.
2. The lamps are three bits: CLASH, NIGHT, ALARM from left to right.
3. The six program tests, each run on the model to its `stop`:
   1. Room A -184, room B -250: display 1, lamps `000`.
   2. Room A -250, room B -250: display 2, lamps `001`.
   3. Room A -150, room B -100: display 0, lamps `000`.
   4. Room A -200, room B -201: display 1, lamps `000`.
   5. Room A 50, room B -250: display 1, lamps `000`.
   6. Room A -250, room B 50: display 1, lamps `000`.
4. Then four questions about your program's run on the whole machine, with room A at -184 and room B at -250. All four are paused before the ALU edge of your first set if:
   1. RESULT, the ALU's output, as a signed decimal number.
   2. The ALU's four flags ZERO, MINUS, COUT and OVER, then MET, in that order: a row of five bits, 0 or 1.
   3. The outputs of the XOR gates `xorB` in the ALU's slices for bits 7 to 4 (the group `q1`, inside `datapath`, `alu`, `g0`), highest first: a row of four bits, 0 or 1. For a subtraction each turns B's bit over, so the row depends on the operand your set if puts in B.
   4. HM, the held word, as a signed decimal number.
5. Where the trace shows X, a wire whose value is not known yet, the answer is X.
6. The drawing and the table of levels write values in hexadecimal. RESULT and HM are asked as signed decimal numbers. (The registers and the devices tables write decimal.)
7. There are 10 tests: the six program tests, then the four questions. A question is graded only once your program passes its six program tests.
8. Press "Run my program on the whole machine" to trace it.
