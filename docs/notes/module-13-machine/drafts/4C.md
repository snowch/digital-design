explanation: A wrong join is found at the first instruction or trap whose effect reaches it. The comparison runs after every instruction and every trap, against the instruction-level model. It does not wait for the end of the program.

A wrong join shows only where a program reaches it. The timer's count shows its fault only on an edge that traps while the timer runs. A branch's condition shows its fault only where a branch is not taken. The door shows its fault only where the door opens.

So each of the five programs reaches a different part:

- **The shop's program** reaches the two instructions you added, and a system call.
- **A fault in user mode** reaches user mode's refusal of a device's address.
- **A system call, then the timer** reaches the timer, and a system call.
- **The door** reaches the door opening.
- **A store to the ROM** reaches a store with no handler.

What the failure sentence names points at a part:

- the PC: the next PC's choice, or a trap or `resume` that set it;
- a register: the word register Y takes, or the register file's write;
- the timer or "waiting": the memory's events, and what the memory takes in;
- a halt where the model goes on, or the reverse: the trap logic, and what it takes in.

generalisation: Teams that design a CPU check their designs the same way. They run the same programs on the design and on a model that works out each instruction in numbers. They compare the two after every instruction.

They run many more programs than five, many of them made at random. They also measure which parts of the design the programs reached.

Programs that agree do not prove a design right. They show only that no program reached a wrong part. The change "DOOR held at 0" passes four of the five programs. None of those four opens the door. The fifth does, and it shows the fault.

The fix is a program that reaches the part, as the door program reaches the door.

c1Task: Write the top module, `machine`, of the whole machine. Its ports are given, and they stay as they are:

- inputs `CLK`, `RST`, `DOOR`, `WARM`, `SENSORA` and `SENSORB`;
- outputs `PC`, `S` (the controller's state), `HALT`, `CAUSE`, `DISPLAY` and `LAMPS`.

The course supplies nine parts as modules. Place them by name: `memory`, `decoder`, `system`, `controller`, `traplogic`, `cregs`, `registers`, `alu` and `condition`. Each of the course's parts passes the tests your own part passed in its module. The machine does not run your answers from earlier lessons. Each lesson keeps its own work.

Your text joins these parts and writes the small parts between them.

Three ways in, each a button above the text:

- **Start from the outline**: the course's text with six joins left out, each marked `JOIN:`. This is where the lab starts.
- **Start from the parts**: every part placed, all its ports listed, none joined.
- **Start from nothing**: the machine's ports alone.

The tests run five programs on your machine and on the model, from the reset. After every instruction and every trap, the two are compared: the PC, the sixteen registers, the control registers, the display, the lamps, the timer, "waiting", and whether each has stopped or halted. A test fails at the first instruction or trap after which they disagree. Its sentence names that line, its address, what differs, and the value on your machine and by the model. It never names the join.

c1Hints.1: Start from the outline. Run the tests first: each failure is a program that reaches one of the six `JOIN:` lines.

c1Hints.2: Read a failure for the value it names, then ask which part makes that value. A PC that differs after a trap points at the next PC's choice. A wrong timer or "waiting" points at the memory.

c1Hints.3: The trap logic decides, at every edge, whether to trap. It needs to know the events waiting in the memory and whether a handler is set. The control registers know whether a handler is set.

c1Hints.4: User mode is C0's bit 0 turned over, since bit 0 is 1 in system mode. The control registers give C0 as `STATUS`. C3 takes a trap's cause from the trap logic.

c1Hints.5: Set if writes MET, the branch condition, as a whole word, 0 or 1, when SET is 1. A trap's edge gives the PC the handler's address, which the control registers give as C4.

modelVsReality: The course's comparison runs the model and your machine side by side, in the same browser.

Real teams that design a CPU do the same, at far greater scale. The model is a program that works out each instruction in numbers. The design runs in a simulator of its gates or of its text. The two are compared after every instruction.

Their tests run millions of instructions, many from programs made at random.

Some checks are proofs about the design for every input rather than tests of chosen programs. The course does not teach them.
